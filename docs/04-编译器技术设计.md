## 1. 总体架构

### 1.1 数据流

卅 v1 是一条**经典的单向流水线**，没有任何回溯到上一阶段的机制：

```
                      ┌────────────────────────────────────────────┐
    源文件 .saho        │  UTF-8 文本（可中英混写、可任意缩进）        │
                      └───────────────────┬────────────────────────┘
                                          ▼
                            ┌──────────────────────────┐
                            │  ① 词法分析 Lexer         │
                            │  []byte -> []Token         │  internal/lexer/keywords.go
                            └────────────┬─────────────┘  中英关键字归一化
                                         ▼
                            ┌──────────────────────────┐
                            │  ② 语法分析 Parser        │
                            │  []Token -> ast.Node       │  递归下降 + 出错同步恢复
                            └────────────┬─────────────┘
                                         ▼
                            ┌──────────────────────────┐
                            │  ③ 树遍历求值 Interpreter │
                            │  ast.Node -> Value / 副作用│  Environment 作用域链 + 内置函数注册表
                            └────────────┬─────────────┘
                                         ▼
                            ┌──────────────────────────┐
                            │  ④ 输出与错误报告          │
                            │  stdout（程序输出）        │
                            │  stderr（双语人类可读诊断） │
                            └──────────────────────────┘
```

四个阶段的**契约**极其明确，这也是整份设计最重要的约束：

| 阶段 | 输入 | 输出 | 不许做的事 |
|---|---|---|---|
| ① 词法分析 | 源码 `[]byte` + 文件名 | `[]lexer.Token`（末尾必为 `TokEOF`） | 不判断语法是否成立、不解析表达式优先级 |
| ② 语法分析 | `[]lexer.Token` + 文件名 | `*ast.Program`（AST 根） | 不做类型检查、不执行任何用户代码 |
| ③ 求值 | `ast.Node` + `*interp.Environment` | `interp.Value` / 输出副作用 | 不回头修改 AST、不依赖源码文本 |
| ④ 报告 | `[]diag.Diagnostic` | stderr 文本 | 不做任何语义判断 |

**为什么坚持单向**：单向流水线意味着每一层都能被**单独测试**。词法分析器可以只喂一个字符串、断言 token 序列；语法分析器可以喂 token 切片；求值器可以手工构造 AST。在 Go 里这件事还有一个额外好处：`internal/` 下的包可以只导出**窄接口**，编译期就能阻止"求值器偷偷去扫描源码"。这种可测试性对一门教学语言尤其重要——报错文案的正确性必须能被测试固定下来（见第 8 节快照测试与 conformance 语料）。

**Go 版的分层铁律**（对应旧版的 `import-linter` 静态检查）：

1. `internal/interp` **不许** import `internal/lexer` 与 `internal/parser`（唯一例外见下）；
2. `internal/lexer` **不许** import `internal/parser` 与 `internal/interp`；
3. `internal/parser` 可以 import `internal/lexer`（它要消费 `Token`），但**不许** import `internal/interp`；
4. 唯一的例外：插值表达式要求"解析器在解析期把 `{...}` 片段编译成 AST 子树"，因此用*解析器回调*（`lexer.ExprScanner` 接口）而不是反向 import——`internal/lexer` 只声明接口，由 `internal/parser` 注入实现，依赖方向永远是 **parser → lexer**。

这条铁律用 `go vet` + 一个 30 行的 `TestImportDirection` 单元测试守住（8.1）：测试读取各包的 import 清单，断言不存在反向引用。

### 1.2 一个完整例子在各阶段的形态

以 `设 计数 = 0` 为例：

```
① Token 流：
   Token{Kind: TokLet,    Text: "设",  Line: 1, Col: 1, Offset: 0}
   Token{Kind: TokIdent,  Text: "计数", Line: 1, Col: 3, Offset: 4}
   Token{Kind: TokAssign, Text: "=",   Line: 1, Col: 6, Offset: 11}
   Token{Kind: TokNumber, Text: "0",   Line: 1, Col: 8, Offset: 13}
   Token{Kind: TokNewline,Text: "\n",  Line: 1, Col: 9, Offset: 14}
   Token{Kind: TokEOF,    Text: "",    Line: 2, Col: 1, Offset: 15}

② AST：
   &ast.Assign{
       Pos:   ast.Pos{Line: 1, Col: 1, Offset: 0},
       Target:&ast.Var{Pos: ..., Name: "计数"},
       Value: &ast.NumLit{Pos: ..., Val: big.NewRat(0, 1)},
       ExplicitLet: true,
   }

③ 求值：
   env.Define("计数", interp.NewNumberInt(0))     // 无输出

④ 报告：无诊断信息，退出码 0
```

注意第 ③ 步：`0` 在内部就是有理数 `0/1`，不是 `float64(0)`，也不是 Go 的 `int`。这一个决定贯穿全文（见 5.2）。

## 2. 技术选型

### 2.1 v1 结论：用 Go 实现独立解释器，产出单个静态可执行文件 `sahou.exe`

| 候选 | 优势 | 对 卅 v1 的问题 |
|---|---|---|
| **Go（选定）** | `gofmt` 级可读、单文件静态编译零依赖部署、UTF-8 与 `rune` 原生、`goroutine` 为 v1.1 网络后端铺路、GC 免手动内存管理、标准库自带 `math/big` 与大整数 | 表达动态值的样板代码比 Python 多一些（用 `interface{}` + 类型 switch 化解）；启动时二进制比脚本大（教学场景无感） |
| Python（旧版选型） | 生态成熟、代码最像伪代码、教学二次开发门槛最低 | 运行速度慢；发布单个可执行文件要靠 PyInstaller 打包，**产出物不是"一个文件"而是一个目录**；目标机器需装解释器或承担打包体积；GIL 让 v1.1 网络后端必须换宿主 |
| Rust | 性能与工程质量上限高、单文件可执行 | 开发速度慢；借用检查与生命周期注解会让"教学代码骨架"难以阅读；本语言 v1 的目标读者是初学者，源码本身就是教材，可读性优先 |
| C | 最快、最小 | 内存管理与字符串处理会让实现复杂度爆炸，与"简单正确"目标冲突 |
| JavaScript | 浏览器里能跑（教学分发优势） | 数值语义（全是 float）与"小数精确"直接冲突；发布命令行可执行文件需要 Node 运行时 |

**选定 Go 的五条理由**（与简报 R1"先保证简单正确"一致，并按重要性排序）：

1. **单文件静态编译、零依赖部署**。`CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" ./cmd/卅` 直接产出 **一个 `sahou.exe`**，把它拷到任何 Windows 机器上双击就能跑：不需要装 Python、不需要装运行时、不需要安装目录、不需要配 `PATH`。这对"中小学机房"是决定性的——机房环境高度异质，还可能没有管理员权限；老师把 `sahou.exe` 和示例 `.saho` 文件放在一个 U 盘目录里，课就能上。跨平台也只是一条命令：`GOOS=darwin GOARCH=arm64 go build`、`GOOS=linux GOARCH=amd64 go build`，同一份源码不需要改一行。
2. **`gofmt` 级可读**。Go 只有一种官方格式，全世界的 Go 代码长得一样：没有"这个人的花括号风格"，也没有"这个人的命名风格"。`gofmt -l` 在 CI 里零配置运行，教学项目最容易失控的"风格漂移"问题在语言层面就被消掉了。同时，`struct` + `interface` + 类型 `switch` 恰好是解释器最自然的表达方式：AST 就是一组 `struct`，`Value` 就是一个 `interface`，求值器就是一个 `switch node := n.(type)`——比 Python 的 `match/case` 更"看得见结构"，也更适合当教材。
3. **UTF-8 与 `rune` 原生**。Go 的字符串是 UTF-8 字节序列，`for range` 与 `[]rune(s)` 直接按码点遍历，`unicode.IsLetter`、`unicode.IsDigit` 覆盖中日韩与全角字符。卅 是一门**中文优先**的语言：标识符可以是汉字、列号要按码点算（一个汉字算一列）、报错要在源码行下面画 `^~~~~`、全角标点要专门报错。这些在 Go 里都是标准库一行调用；在 C 里要自己写 UTF-8 解码器，在 Python 里反而要小心 `str`/`bytes` 与索引语义的差别。
4. **`goroutine` 为 v1.1 网络后端铺路**。《[05-前端后端扩展设计](./05-前端后端扩展设计.md)》规划了 v1.1 的 `网络` 模块（服务端 + HTTP 客户端）。用 Python 做宿主时，`http.server` 与 GIL 会限制并发，且 `async/await` 与树遍历求值器混在一起会显著提高实现复杂度。Go 的 `net/http` 标准库自带生产级 HTTP 服务器，每个请求一个 goroutine 是一行代码的事；而语言层面 v1 仍然规定**单线程顺序语义**（用户看不到并发），实现上却已经站在能扩展的地基上。这是"实现语言选 Go"最值钱的一条未来收益。
5. **GC 免手动内存管理，同时 `math/big` 提供任意精度整数与有理数**。教学语言的实现者不应该把时间花在 `free`/`malloc` 上；Go 的 GC 让"环境、闭包、字典、字符串"这些高频分配的对象随手创建即可。更重要的是标准库直接提供 `math/big.Int`、`math/big.Rat`、`math/big.Float`：**"任意精度整数天然成立"和"小数精确"这两条规范要求（《02》5.2），在 Go 里不需要任何第三方库就能实现**（详见 5.2）。

**主动承受的代价**：

- **动态值的样板代码**：`Value` 必须自己定义 `interface{}` 实现，比较与显示要写类型 `switch`。缓解办法是把这些分支**全部集中到 `internal/interp/value.go` 与 `number.go`**，全解释器不许在别处写"这是不是数"的判断（对应规范 6.1 的"唯一语义出口"）。
- **二进制体积**：静态链接后约 3–6 MB。对教学分发而言这是优点而非缺点（比"先装 200 MB 的运行时"划算得多）。
- **编译期反馈带来的"改一处要重编"**：Go 编译很快（本项目全量编译在 1 秒量级），且"编译通过"本身就是一层有价值的纪律。

**工程纪律（用工具链替代 Python 版的 mypy/black/ruff）**：

| 关注点 | Go 方案 |
|---|---|
| 格式 | `gofmt` / `go fmt ./...`（CI 里跑 `test -z "$(gofmt -l .)"`） |
| 静态检查 | `go vet ./...`；可选 `staticcheck ./...` |
| 类型安全 | 编译期强类型；`any` 只允许出现在 `Value`、`Dict`、参数表三个明确位置 |
| 错误处理 | 一律多返回值 `(T, error)`；**禁止 `panic` 跨包传播**，`panic` 只用于"不可能发生"的内部断言，且 `main` 最外层有 `defer recover` 兜底（8.5） |
| 依赖治理 | v1 设计时 `go.mod` 零 `require`；v1.8 为 Windows 原生窗口引入唯一第三方依赖 `github.com/jchv/go-webview2`（纯 Go、无 CGO，运行时用系统预装的 WebView2）。其余全部只用标准库 |
| 竞态 | `go test -race ./...`（v1 虽单线程，但提前把 CI 配好） |

### 2.2 迁移路径：Go 树遍历 → Go 字节码 VM → 必要时 Rust 重写

迁移不是"某天推倒重来"，而是**分四个阶段、每阶段都可独立交付**：

| 阶段 | 形态 | 触发条件 | 关键动作 |
|---|---|---|---|
| **A. Go 树遍历（v1，本文档）** | 直接对 AST 递归求值，产出单个 `sahou.exe` | 立项 | 把诊断、内置函数、conformance 语料先做扎实；数值统一走 `big.Rat` |
| **B. Go + 编译期优化（仍树遍历）** | AST 上做常量折叠、作用域槽位化（把 `map[string]Value` 查名改成 `[]Value` 下标）、闭包环境扁平化、`switch` 分派顺序调优 | 某教学示例明显卡顿，或用户开始写循环一百万次以上的程序 | 优化只发生在 `internal/interp`，语言行为零变化，靠 conformance 语料兜底 |
| **C. Go 字节码 VM（v2）** | `Parser -> AST -> Compiler -> Chunk -> 栈式 VM`，仍由同一个 `sahou.exe` 承载（子命令 `sahou run --vm`） | 语言形态稳定（《02》冻结 ≥1 个版本）、有真实用户 | 新增 `internal/compiler` 与 `internal/vm`；解释器与 VM **并存**，用同一套一致性测试双向验证；`尝试/接住`、`返回`、函数调用在 VM 里用显式栈帧 |
| **D. 必要时 Rust 重写** | 同一门语言，新宿主 | 需要极高吞吐、无 GC 的嵌入式环境、或分发到无法运行 Go 运行时的平台 | 直接把 `tests/cases/*.saho` + `*.out` 当作**唯一验收标准**；先移植 lexer/parser（纯函数、易移植），再移植 VM（难移植） |

**为什么迁移路径里"Rust 重写"排在最后且标注"必要时"**：Go 版已经解决了 v1 的全部诉求（静态单文件、跨平台、原生 UTF-8、GC、并发地基）。只有当出现**Go 无法满足**的硬约束（例如要求无 GC 的实时性、或目标平台不支持 Go 工具链）时，才值得付出一次完整重写的成本。届时最大的资产不是代码，而是下面这套语料库。

**迁移期最值钱的资产是"一致性测试语料库"**（见 8.4）。语言的行为规范不该写在文档里被反复解读，而应写成**可执行的断言**：给定 `.saho` 源码 + 标准输入，必须得到固定的 stdout 与固定的诊断文案。只要这套语料库通过，换任何实现（Go VM、Rust VM、甚至未来用 卅 自举）都是"同一个语言"。

**不可迁移的兼容性红线**（A→D 任何阶段都不许变）：

1. 单一"数"类型语义：`10 == 10.0` 为真；`10 / 3` 得 `3.3333...`；**小数精确**，`0.1 + 0.2 == 0.3` 恒真（5.2）；
2. 双语关键字完全等价，且**报错里回显用户实际写的那个词**（用户写 `完毕`，报错就说 `完毕`，不说 `end`）；
3. `end`/`完毕` 收尾、缩进不参与语法；
4. 报错必带行号，且尽量带"你是不是想写"；
5. 内置函数**不超过 30 个**（v1 实为 29 个），中英双名指向同一实现。

## 3. 词法分析器设计

### 3.1 职责

把 UTF-8 源码扫描成 `[]Token`。**只做无歧义的局部判断**：这是什么记号、它从哪来。需要往前看很远才能决定的（例如"这个表达式是不是完整的"）一律交给语法分析器。

Go 版在职责上有一条硬约束：`lexer.Scan` **永不 panic、永不返回 error**，它把问题全部写成 `diag.Diagnostic` 并继续扫描。这直接对应 8.5 的健壮性底线"输入任意字节序列都不许崩溃，只能产出诊断"。

### 3.2 Token 类型定义

```go
// internal/lexer/token.go
package lexer

// TokenKind 是词法记号的种类。关键字已经归一化：
// 用户写 "如果" 或 "if"，得到的都是 TokIf。
type TokenKind int

const (
	TokEOF TokenKind = iota
	TokNewline

	// ── 字面量 ────────────────────────────────────────────
	TokNumber   // 10、3.5、10.0
	TokString   // "你好"（纯文本，不含插值）
	TokTemplate // "你好, {名字}!" —— 见 3.5 插值撕裂

	// ── 名字 ──────────────────────────────────────────────
	TokIdent // 计数、name、从a到b（允许中英混写）

	// ── 关键字（中英已归一化，见 3.3；共 18 个，与《02》2.6 表逐行对应） ──
	TokIf     // 如果 / if
	TokElif   // 又如 / elif
	TokElse   // 否则 / else
	TokWhile  // 当   / while
	TokFor    // 遍历 / for
	TokIn     // 于   / in
	TokEnd    // 完毕 / end
	TokFn     // 函数 / fn
	TokReturn // 返回 / return
	TokLet    // 设   / let
	TokTrue   // 真   / true
	TokFalse  // 假   / false
	TokNull   // 空值 / null
	TokAnd    // 并且 / and
	TokOr     // 或者 / or
	TokNot    // 非   / not
	TokTry    // 尝试 / try
	TokCatch  // 接住 / catch

	// ── 运算符与标点 ──────────────────────────────────────
	TokAssign   // =
	TokArrow    // =>
	TokPlus     // +
	TokMinus    // -
	TokStar     // *
	TokSlash    // /
	TokPercent  // %
	TokEq       // ==
	TokNeq      // !=
	TokLT       // <
	TokLE       // <=
	TokGT       // >
	TokGE       // >=
	TokLParen   // (
	TokRParen   // )
	TokLBracket // [
	TokRBracket // ]
	TokLBrace   // {
	TokRBrace   // }
	TokComma    // ,
	TokColon    // :
	TokDot      // .
)

// Token 是词法分析器的输出。Text 永远保留源码原文，用于报错回显：
// 用户写 "完毕"，报错就说 "完毕"，绝不擅自改写成 "end"。
type Token struct {
	Kind   TokenKind
	Text   string // 源码原文（模板 token 是整个字面量原文）
	Line   int    // 1 起，按 LF/CRLF 计行
	Col    int    // 1 起，按 Unicode 码点计（一个汉字算 1 列）
	Offset int    // 在源串中的字节偏移，用于把源码行切开、在错误字符下方画 ^

	// Parts 仅 TokTemplate 使用：文本片段与插值表达式源码片段交替。
	// 只有一段且为 text 时不生成 TokTemplate 而是 TokString（省一次求值）。
	Parts []TemplatePart
}

// TemplatePart 是插值撕裂的产物。
type TemplatePart struct {
	IsExpr bool   // true = 插值表达式；false = 字面文本
	Text   string // 字面文本，或插值表达式的源码（不含外层花括号）
	Line   int    // 该片段起始行（插值表达式报错时用）
	Col    int    // 该片段起始列
}

// String 让报错与调试输出可读（"TokIdent(计数)@1:3"）。
func (t Token) String() string {
	return tokenKindName(t.Kind) + "(" + t.Text + ")@" + itoa(t.Line) + ":" + itoa(t.Col)
}
```

**设计要点**

- `Text` 保留源码原文，`Kind` 是归一化结果——这是"双语关键字是同一套语法两种拼写"在数据结构上的落地。
- `Line`/`Col`/`Offset` 三者都存：`Line`/`Col` 用于人类阅读（**Col 按码点计**，因为中文用户看到的"第 5 列"是字符列，不是字节列），`Offset`（字节）用于高效切源码行、在错误字符下方画 `^`。
- 缩进与空格**不产生 token**（除行内空白跳过）；缩进只影响列号，绝不影响语法。这正是简报 D1"缩进不参与语法"的实现方式。
- `TokNewline` 存在但很"软"：解析器在语句之间跳过它；在括号 `(` `[` `{` 内部，词法分析器会**抑制**换行（用 `bracketDepth` 计数器），从而允许用户把长调用折行写（规范 2.10）。
- `TokPercent` 存在，因为《02》3.1 把 `%` 取余纳入 v1（旧版本文档曾按简报猜测"未纳入"，现已按规范修正）。
- **没有** `TokSemicolon`：规范 2.10 明确 v1 不允许一行内写多条语句，所以 `;` 是错误字符（会走全角/未知字符报错通道）。

### 3.3 双语关键字归一化策略（核心）

**策略：在词法阶段完成归一化，语法分析器永远只看到 18 个规范 `TokenKind`。** 中英关键字不进入后续任何一层，因此"两套关键字"的实现成本被压到一张 `map` 里。

```go
// internal/lexer/keywords.go
package lexer

// keywords 是双语关键字的唯一事实来源（与《02》2.6 表逐行对应，共 18 条）。
// 键是"用户可能写出的拼写"，值是归一化后的规范 Kind。
var keywords = map[string]TokenKind{
	// ── 英文（规范拼写） ──
	"if": TokIf, "elif": TokElif, "else": TokElse,
	"while": TokWhile, "for": TokFor, "in": TokIn,
	"end": TokEnd, "fn": TokFn, "return": TokReturn,
	"let": TokLet,
	"true": TokTrue, "false": TokFalse, "null": TokNull,
	"and": TokAnd, "or": TokOr, "not": TokNot,
	"try": TokTry, "catch": TokCatch,

	// ── 中文（等价拼写） ──
	"如果": TokIf, "又如": TokElif, "否则": TokElse,
	"当": TokWhile, "遍历": TokFor, "于": TokIn,
	"完毕": TokEnd, "函数": TokFn, "返回": TokReturn,
	"设": TokLet,
	"真": TokTrue, "假": TokFalse, "空值": TokNull,
	"并且": TokAnd, "或者": TokOr, "非": TokNot,
	"尝试": TokTry, "接住": TokCatch,
}

// canonicalNames 反向表：给报错文案用（"你是不是想写……"要知道规范拼写，
// 也要在错误里同时给出中英两种写法）。每项的两种拼写与 keywords 完全对称。
var canonicalNames = map[TokenKind]string{
	TokIf: "如果/if", TokElif: "又如/elif", TokElse: "否则/else",
	TokWhile: "当/while", TokFor: "遍历/for", TokIn: "于/in",
	TokEnd: "完毕/end", TokFn: "函数/fn", TokReturn: "返回/return",
	TokLet: "设/let", TokTrue: "真/true", TokFalse: "假/false",
	TokNull: "空值/null", TokAnd: "并且/and", TokOr: "或者/or",
	TokNot: "非/not", TokTry: "尝试/try", TokCatch: "接住/catch",
}

// keywordSpellings 给出每个规范 Kind 的全部合法拼写（拼写建议的候选集合）。
var keywordSpellings = func() map[TokenKind][]string {
	m := make(map[TokenKind][]string, len(canonicalNames))
	for spelling, kind := range keywords {
		m[kind] = append(m[kind], spelling)
	}
	return m
}()

// lookupKeyword 是归一化的唯一入口。
func lookupKeyword(text string) (TokenKind, bool) {
	k, ok := keywords[text]
	return k, ok
}

// isKeyword 供"用关键字当变量名"的专门报错使用（《02》7.2 示例 17）。
func isKeyword(text string) bool {
	_, ok := keywords[text]
	return ok
}
```

**为什么放在词法阶段而不是语法阶段**

1. **语法分析器只需认识 21 个关键字**，而不是 42 个中英拼写；文法和实现都不会翻倍。`parse_if` 里写的是 `p.match(TokIf)`，与用户写中文还是英文无关。
2. **报错文案需要原文**：`Token.Text` 保留了 `"完毕"`，因此"缺少 `完毕`"这条错误能直接回显用户实际使用的语言风格（规范 7.1 第 1 条"中文优先"落实在词法层）。
3. **混用天然被支持**：`for i 于 从a到b(1,10) … 完毕` 里 `for`、`于`、`完毕` 各自独立归一化，不需要任何"语言模式"或"语言切换"概念。8.3 的"跨语言等价用例"（全中/全英/混写三者输出必须逐字一致）正是这条设计的可执行断言。
4. **测试极简**：8.1 的关键字归一化测试只需对 18 对拼写断言"归一化后 Kind 相等、Text 保留原文"。

**歧义处理**：如果某个中文关键字同时又是合法的内置函数名或用户变量名（例如用户把变量命名为 `于`），采取"**关键字优先**"——因为关键字是语言保留的，这与所有主流语言一致；实现上 `lookupKeyword` 在标识符扫描之后无条件生效，用户若撞名会得到规范 7.2 示例 17 那种明确报错（`"如果" 是关键字，不能当变量名`），而不是一条莫名其妙的语法错误。内置函数名（29 个）**不是关键字**，它们是普通标识符，只在名字解析时命中全局环境里的内置函数值（规范 6.1 最后一条）。

### 3.4 词法分析器骨架

```go
// internal/lexer/lexer.go
package lexer

import (
	"strings"
	"unicode"
	"unicode/utf8"

	"sahou/internal/diag"
)

// Lexer 把 UTF-8 源码扫描成 Token 序列。
// 约定：Scan 永不 panic、永不返回 error——所有问题都变成 Diagnostic 并继续扫描。
type Lexer struct {
	src      []byte
	file     string
	pos      int // 当前字节偏移
	line     int // 1 起
	col      int // 1 起，按码点计
	toks     []Token
	diags    []diag.Diagnostic
	depth    int // 括号深度 >0 时抑制 TokNewline（规范 2.10）
	template *TemplateScanner
}

// New 创建扫描器。第 3、4 个参数用于"从插值片段里再起一次词法分析"：
// 片段是完整源码的子串，必须带着真实行列继续，报错才会指到正确位置。
func New(src []byte, filename string, startLine, startCol int) *Lexer {
	if startLine <= 0 {
		startLine = 1
	}
	if startCol <= 0 {
		startCol = 1
	}
	return &Lexer{src: src, file: filename, line: startLine, col: startCol}
}

// Scan 是唯一入口：扫描到 EOF 为止。
func (l *Lexer) Scan() ([]Token, []diag.Diagnostic) {
	for !l.atEnd() {
		switch ch := l.peek(); {
		case ch == ' ' || ch == '\t' || ch == '\r':
			l.advance() // 空白：跳过（缩进无意义，简报 D1）
		case ch == '#':
			for !l.atEnd() && l.peek() != '\n' {
				l.advance() // 注释到行尾
			}
		case ch == '\n':
			l.scanNewline()
		case ch >= '0' && ch <= '9':
			l.scanNumber()
		case ch == '"' || ch == '\'':
			l.scanString()
		case isIdentStart(ch):
			l.scanIdentifierOrKeyword()
		default:
			l.scanOperator()
		}
	}
	// 文件末尾若不在行首，补一个 NEWLINE，让"最后一行没有换行"与"有换行"等价。
	if n := len(l.toks); n > 0 && l.toks[n-1].Kind != TokNewline {
		l.toks = append(l.toks, Token{Kind: TokNewline, Text: "\n", Line: l.line, Col: l.col, Offset: l.pos})
	}
	l.toks = append(l.toks, Token{Kind: TokEOF, Line: l.line, Col: l.col, Offset: l.pos})
	return l.toks, l.diags
}

// ── 标识符 / 关键字：先按标识符扫完，再查表归一化 ────────────
func (l *Lexer) scanIdentifierOrKeyword() {
	start, line, col := l.pos, l.line, l.col
	for !l.atEnd() {
		r, _ := utf8.DecodeRune(l.src[l.pos:])
		if !isIdentContinue(r) {
			break
		}
		l.advance()
	}
	text := string(l.src[start:l.pos])
	kind, ok := lookupKeyword(text)
	if !ok {
		kind = TokIdent // ★ 归一化就这一处：不是关键字就是标识符
	}
	l.toks = append(l.toks, Token{Kind: kind, Text: text, Line: line, Col: col, Offset: start})
}

func (l *Lexer) scanNumber() {
	start, line, col := l.pos, l.line, l.col
	for !l.atEnd() && l.peek() >= '0' && l.peek() <= '9' {
		l.advance()
	}
	// 小数点前后都必须有数字（规范 2.7）：".5" / "5." 都要报专门错误。
	if l.peek() == '.' && l.peekAt(1) >= '0' && l.peekAt(1) <= '9' {
		l.advance()
		for !l.atEnd() && l.peek() >= '0' && l.peek() <= '9' {
			l.advance()
		}
	}
	text := string(l.src[start:l.pos])
	l.toks = append(l.toks, Token{Kind: TokNumber, Text: text, Line: line, Col: col, Offset: start})

	// "5." 这种情况：数字扫完了但还是个小点，抓成一条专门诊断，别让它变成 "." 记号的怪错。
	if l.peek() == '.' && !isDigitOrIdent(l.peekAt(1)) {
		l.diags = append(l.diags, diag.New(diag.CodeBadDecimal, diag.SevError,
			diag.Pos{Line: l.line, Col: l.col, Offset: l.pos},
			diag.Args{"原文": text, "建议": text + "0"}))
	}
}

// ── 标识符字符判定：直接在 rune 上做，天然支持中文 ────────────
func isIdentStart(ch byte) bool {
	if ch < utf8.RuneSelf { // ASCII 快路径
		return ch == '_' || (ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z')
	}
	r, _ := utf8.DecodeRune([]byte{ch}) // 仅用于 ASCII 判断之外的粗略预判
	return unicode.IsLetter(r) || ch >= 0x80
}

func isIdentContinue(r rune) bool {
	return r == '_' || unicode.IsLetter(r) || unicode.IsDigit(r)
}

// ── 运算符：最长匹配优先（规范 2.4） ─────────────────────────
var operators2 = map[string]TokenKind{
	"==": TokEq, "!=": TokNeq, "<=": TokLE, ">=": TokGE, "=>": TokArrow,
}

var operators1 = map[byte]TokenKind{
	'=': TokAssign, '+': TokPlus, '-': TokMinus, '*': TokStar, '/': TokSlash,
	'%': TokPercent, '<': TokLT, '>': TokGT,
	'(': TokLParen, ')': TokRParen, '[': TokLBracket, ']': TokRBracket,
	'{': TokLBrace, '}': TokRBrace, ',': TokComma, ':': TokColon, '.': TokDot,
}

func (l *Lexer) scanOperator() {
	line, col, start := l.line, l.col, l.pos
	if l.pos+1 < len(l.src) {
		if kind, ok := operators2[string(l.src[l.pos:l.pos+2])]; ok {
			l.advanceRunes(2)
			l.toks = append(l.toks, Token{Kind: kind, Text: string(l.src[start:l.pos]), Line: line, Col: col, Offset: start})
			return
		}
	}
	if kind, ok := operators1[l.peek()]; ok {
		l.bumpBracket(kind)
		l.advance()
		l.toks = append(l.toks, Token{Kind: kind, Text: string(l.src[start:l.pos]), Line: line, Col: col, Offset: start})
		return
	}
	// 走到了这里 = 出现不该出现的字符。分两种：
	// (1) 全角标点：给出"你打的是全角，应该打半角"的专门错误（规范 2.9 硬要求）
	// (2) 其它未知字符：笼统报"我不认识这个字符"
	r, size := utf8.DecodeRune(l.src[l.pos:])
	pos := diag.Pos{Line: line, Col: col, Offset: start}
	if half, ok := fullwidthToHalf(r); ok {
		l.diags = append(l.diags, diag.New(diag.CodeFullwidthPunct, diag.SevError, pos,
			diag.Args{"全角": string(r), "半角": half}))
	} else {
		l.diags = append(l.diags, diag.New(diag.CodeUnknownChar, diag.SevError, pos,
			diag.Args{"字符": string(r)}))
	}
	_ = size
	l.advance() // 弹性恢复：吞掉坏字符继续，尽量一次多报几条
}

// scanNewline：括号内部不产生 NEWLINE（规范 2.10 的"长调用可折行"）。
func (l *Lexer) scanNewline() {
	line, col, start := l.line, l.col, l.pos
	l.advance()
	if l.depth == 0 {
		l.toks = append(l.toks, Token{Kind: TokNewline, Text: "\n", Line: line, Col: col, Offset: start})
	}
}

// bumpBracket：维护括号深度；右括号多出来时深度不为负（错误留给解析器报）。
func (l *Lexer) bumpBracket(k TokenKind) {
	switch k {
	case TokLParen, TokLBracket, TokLBrace:
		l.depth++
	case TokRParen, TokRBracket, TokRBrace:
		if l.depth > 0 {
			l.depth--
		}
	}
}

// ── 游标原语（省略 getter 的逐行注释） ───────────────────────
func (l *Lexer) atEnd() bool { return l.pos >= len(l.src) }

func (l *Lexer) peek() byte {
	if l.atEnd() {
		return 0
	}
	return l.src[l.pos]
}

func (l *Lexer) peekAt(k int) byte {
	if l.pos+k >= len(l.src) {
		return 0
	}
	return l.src[l.pos+k]
}

// advance 前进一个码点，并维护 line/col（按码点计列）。
func (l *Lexer) advance() {
	if l.atEnd() {
		return
	}
	r, size := utf8.DecodeRune(l.src[l.pos:])
	l.pos += size
	if r == '\n' {
		l.line++
		l.col = 1
	} else {
		l.col++
	}
}

func (l *Lexer) advanceRunes(n int) {
	for i := 0; i < n && !l.atEnd(); i++ {
		l.advance()
	}
}

func isDigitOrIdent(ch byte) bool {
	return ch == '_' || ch >= 0x80 || (ch >= '0' && ch <= '9') ||
		(ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z')
}
```

**注意 `advance()` 里的两件事**：它按**码点**前进（不是按字节），并在遇到 `\n` 时重置列号。这两条保证"一个汉字算一列"和"报错行号准"。

### 3.5 字符串插值在词法阶段的处理

简报 D6 与规范 5.5 要求 `"你好, {名字}!"` 的花括号里可以是**任意表达式**，而且简报示例里出现了**嵌套引号**：

```
返回 "{动物["名字"]} 吃饱啦，饥饿度 {动物["饥饿"]}"
```

因此字符串扫描器必须做到两件事：**跟踪 `{}` 嵌套深度**、**在插值内部允许引号重新开始一段字符串**。做法是把字符串字面量"撕裂"成结构化的片段序列，放进 `Token.Parts`。

```go
// internal/lexer/string.go
package lexer

// scanString 扫描 "..." / '...'；遇到 { 进入表达式模式，按嵌套深度配对到 }。
// 产物二选一：纯文本 -> TokString；含插值 -> TokTemplate（Parts 交替）。
func (l *Lexer) scanString() {
	quote := l.peek()
	line, col, start := l.line, l.col, l.pos
	l.advance() // 吃掉开引号

	var parts []TemplatePart
	var buf []rune
	flushText := func() {
		if len(buf) > 0 {
			parts = append(parts, TemplatePart{Text: string(buf), Line: line, Col: col})
			buf = buf[:0]
		}
	}

	for !l.atEnd() && l.peek() != quote {
		switch {
		case l.peek() == '\n':
			// 文本字面量不能跨行（规范 2.8）。
			l.diags = append(l.diags, diag.New(diag.CodeUnterminatedString, diag.SevError,
				diag.Pos{Line: line, Col: col, Offset: start},
				diag.Args{"引号": string(quote)}))
			return
		case l.peek() == '\\':
			l.advance()
			buf = append(buf, l.scanEscape(line, col)...)
		case l.peek() == '{':
			flushText()
			parts = append(parts, l.scanInterpolation(line, col))
		case l.peek() == '}':
			// 孤立的 } 只有 \} 才合法（规范 2.8）。
			l.diags = append(l.diags, diag.New(diag.CodeUnescapedBrace, diag.SevError,
				diag.Pos{Line: l.line, Col: l.col, Offset: l.pos}, nil))
			l.advance()
		default:
			r, _ := utf8.DecodeRune(l.src[l.pos:])
			buf = append(buf, r)
			l.advance()
		}
	}
	if !l.atEnd() {
		l.advance() // 吃掉闭引号
	}
	flushText()

	tok := Token{Text: string(l.src[start:l.pos]), Line: line, Col: col, Offset: start}
	if len(parts) == 1 && !parts[0].IsExpr {
		tok.Kind = TokString // 纯文本 -> 省掉一次求值
	} else {
		tok.Kind = TokTemplate
		tok.Parts = parts
	}
	l.toks = append(l.toks, tok)
}

// scanEscape 处理 \n \t \\ \" \' \{ \}；未知转义报错并列出全部合法转义（规范 2.8）。
func (l *Lexer) scanEscape(line, col int) []rune {
	pos := diag.Pos{Line: l.line, Col: l.col, Offset: l.pos}
	r, _ := utf8.DecodeRune(l.src[l.pos:])
	l.advance()
	switch r {
	case 'n':
		return []rune{'\n'}
	case 't':
		return []rune{'\t'}
	case '\\':
		return []rune{'\\'}
	case '"':
		return []rune{'"'}
	case '\'':
		return []rune{'\''}
	case '{':
		return []rune{'{'}
	case '}':
		return []rune{'}'}
	default:
		l.diags = append(l.diags, diag.New(diag.CodeBadEscape, diag.SevError, pos,
			diag.Args{"转义": "\\" + string(r)}))
		return []rune{r} // 弹性恢复：按字面字符收下，避免连锁报错
	}
}

// scanInterpolation 从 { 扫到配对 }，内部允许嵌套 {} 与嵌套字符串。
// 返回的 TemplatePart.Text 是插值表达式的**源码片段**（不含花括号）。
func (l *Lexer) scanInterpolation(line, col int) TemplatePart {
	startLine, startCol, start := l.line, l.col, l.pos
	l.advance() // 吃掉 '{'
	depth := 1
	exprStart := l.pos

	for !l.atEnd() {
		ch := l.peek()
		switch {
		case ch == '\n':
			l.diags = append(l.diags, diag.New(diag.CodeUnclosedInterp, diag.SevError,
				diag.Pos{Line: startLine, Col: startCol, Offset: start}, nil))
			return TemplatePart{IsExpr: true, Text: string(l.src[exprStart:l.pos]), Line: startLine, Col: startCol}
		case ch == '"' || ch == '\'':
			l.skipNestedString() // ★ 嵌套引号：整段跳过（含它自己的插值），不干扰外层深度
		case ch == '{':
			depth++
			l.advance()
		case ch == '}':
			depth--
			if depth == 0 {
				text := string(l.src[exprStart:l.pos])
				l.advance() // 吃掉 '}'
				return TemplatePart{IsExpr: true, Text: text, Line: startLine, Col: startCol}
			}
			l.advance()
		default:
			l.advance()
		}
	}
	l.diags = append(l.diags, diag.New(diag.CodeUnclosedInterp, diag.SevError,
		diag.Pos{Line: startLine, Col: startCol, Offset: start}, nil))
	return TemplatePart{IsExpr: true, Text: string(l.src[exprStart:l.pos]), Line: startLine, Col: startCol}
}

// skipNestedString 跳过插值里的一个完整字符串字面量（支持 \ 转义与其中的 { }）。
func (l *Lexer) skipNestedString() {
	quote := l.peek()
	l.advance()
	for !l.atEnd() && l.peek() != quote {
		if l.peek() == '\n' {
			return
		}
		if l.peek() == '\\' {
			l.advance()
			if !l.atEnd() {
				l.advance()
			}
			continue
		}
		l.advance()
	}
	if !l.atEnd() {
		l.advance()
	}
}
```

`TemplatePart.Text` 存的是**源码片段**而非 token 列表，因此解析器需要重新词法分析一次这段片段。为此 `internal/lexer` 暴露一个窄接口，由 `internal/parser` 注入实现（保证依赖方向 parser → lexer）：

```go
// internal/lexer/lexer.go（同一个包）
// ExprScanner 由解析器注入：把插值片段编译成一段表达式 AST。
// lexer 不认识 AST，只负责"喊一声"；这样依赖方向永远是 parser -> lexer。
type ExprScanner interface {
	// ScanInterp 的入参是片段源码与它的真实起始位置；
	// 返回编译结果（由 parser 包定义的具体类型，这里用 any 承载）。
	ScanInterp(src string, line, col int) (any, []diag.Diagnostic)
}

func (l *Lexer) SetExprScanner(s ExprScanner) { l.template = s }
```

**取舍说明**：把插值表达式以"源码片段"而非"token 列表"存进 `TemplatePart`，是为了让 AST 可以**被打印、被快照、被调试**（见 8.2）。代价是求值前必须再解析一次；v1 只解析一次（Parse 阶段就把 `TemplatePart` 编译成 `ast.Expr` 子树存进 `ast.StringTemplate` 节点），之后求值不再做字符串解析。这是"AST 自包含、可快照"与"多一次解析"之间的取舍，而 v1 的性能目标（简报已把高性能列为非目标）允许这样选。

### 3.6 全角标点专门报错（规范 2.9 的落实点）

中文输入法很容易打出全角标点，这是中文学习者最高频的"环境错误"。规范要求**必须报出专门的错误**，而不是笼统的"语法错误"。因此词法器带一张"全角 → 半角"映射表：

```go
// internal/lexer/fullwidth.go
package lexer

// fullwidthPairs 只收录"在语法位置出现时几乎一定是输入法问题"的字符。
// 注意：中文文本**内容**里的全角标点在引号内，根本不经过这里（它们被 scanString 吃掉）。
var fullwidthPairs = map[rune]string{
	'（': "(", '）': ")", '【': "[", '】': "]",
	'｛': "{", '｝': "}", '，': ",", '：': ":",
	'。': ".", '；': ";", '“': "\"", '”': "\"",
	'‘': "'", '’': "'", '＜': "<", '＞': ">",
	'＝': "=", '＋': "+", '－': "-", '＊': "*",
	'／': "/", '！': "!",
}

func fullwidthToHalf(r rune) (string, bool) {
	half, ok := fullwidthPairs[r]
	return half, ok
}
```

对应的消息模板（`internal/diag/messages.go`）产出的文案与规范 7.2 示例 6 逐字一致：

```
第 1 行：这里应该是半角逗号 ","，你打成了中文逗号 "，"。请把输入法切换到英文标点。
line 1: expected "," but found "，". Switch your IME to half-width punctuation.
  提示：这个位置也可能根本不需要逗号。
```

`；`（全角分号）单独走一条更明确的文案：v1 **没有** `;`，一行只能写一条语句（规范 2.10），所以提示是"把这条语句换到下一行"。

## 4. 语法分析器设计（递归下降）

### 4.1 文法与函数对应关系

**递归下降的核心优势**：每个非终结符 = 一个方法，文法结构在代码里逐行可见，最适合教学场景。下表是《02》4.2 完整文法与 Go 实现的对照（文法以规范为准，本文只做映射）。

| 非终结符 | 产生式（简写，与规范 4.2 对应） | 实现方法（`internal/parser`） |
|---|---|---|
| `程序` | `{ 语句 } EOF` | `ParseProgram()` |
| `语句` | `赋值语句 \| 表达式语句 \| 如果语句 \| 当语句 \| 遍历语句 \| 函数定义语句 \| 返回语句 \| 尝试语句` | `parseStatement()` |
| 块 | `换行 { 语句 } 收尾词` | `parseBlock(terminators ...TokenKind)` |
| 函数定义语句 | `("fn"\|"函数") IDENT "(" [参数表] ")" NL 块 end` | `parseFuncDef()` |
| 匿名函数 | `("fn"\|"函数") "(" [参数表] ")" "=>" 表达式` | `parseLambda()` |
| 如果语句 | `("if"\|"如果") 表达式 NL 块 { (elif) 表达式 NL 块 } [ (else) NL 块 ] end` | `parseIf()` |
| 当语句 | `("while"\|"当") 表达式 NL 块 end` | `parseWhile()` |
| 遍历语句 | `("for"\|"遍历") IDENT ("in"\|"于") 表达式 NL 块 end` | `parseFor()` |
| 尝试语句 | `("try"\|"尝试") NL 块 ("catch"\|"接住") IDENT NL 块 end` | `parseTry()` |
| 返回语句 | `("return"\|"返回") [表达式]` | `parseReturn()` |
| 赋值语句 | `["let"\|"设"] 左值 "=" 表达式` | `parseAssignOrExpr()` |
| 左值 | `标识符 \| 左值 "[" 表达式 "]" \| 左值 "." 标识符` | `parsePostfix()` 后校验（`isLValue`） |
| 别名 | `标识符` 与关键字同形时按关键字处理（3.3） | `splitImei`（"如果_" 之类逃生名）|
| 表达式 | `匿名函数 \| 或者表达式` | `ParseExpression()` → `parseLambda()` |
| 或者表达式 | `并且表达式 { (OR) 并且表达式 }` | `parseOr()` |
| 并且表达式 | `非表达式 { (AND) 非表达式 }` | `parseAnd()` |
| 非表达式 | `(NOT) 非表达式 \| 比较表达式` | `parseNot()` |
| 比较表达式 | `加减表达式 [ 比较运算符 加减表达式 ]`（**不可连写**） | `parseComparison()` |
| 加减表达式 | `乘除表达式 { ("+"\|"-") 乘除表达式 }` | `parseTerm()` |
| 乘除表达式 | `一元表达式 { ("*"\|"/"\|"%") 一元表达式 }` | `parseFactor()` |
| 一元表达式 | `"-" 一元表达式 \| 后缀表达式` | `parseUnary()` |
| 后缀表达式 | `基本表达式 { 后缀 }` | `parsePostfix()` |
| 后缀 | `"(" [实参表] ")" \| "[" 表达式 "]" \| "." 标识符` | `parseCall/parseIndex/parseAttr` |
| 实参表 | `实参 { "," 实参 }`；`实参 = 表达式 \| 标识符 ":" 表达式` | `parseArgs()` |
| 基本表达式 | `数字 \| 文本 \| 真/假/空值 \| 标识符 \| "(" 表达式 ")" \| 列表 \| 字典` | `parsePrimary()` |
| 列表字面量 | `"[" [表达式 {"," 表达式}] "]"`（允许尾随逗号） | `parseListLit()` |
| 字典字面量 | `"{" [字典项 {"," 字典项}] "}"`（允许尾随逗号） | `parseDictLit()` |

**优先级表**（规范 3.2，低 → 高）：`或者/or` < `并且/and` < `非/not` < 比较 < `+ -` < `* / %` < 一元 `-` < 调用/索引/成员。**该表在实现上只体现为这一串 `parseXxx` 的嵌套顺序**——顺序即优先级，改顺序即改优先级，不需要额外的优先级爬升表（Pratt parser）。匿名函数 `函数(x) => 表达式` 的优先级最低（规范 3.2 第 9 级），因此 `ParseExpression` 的第一跳是 `parseLambda`，匿名函数体会一直吃到最右端。

**比较不可连写**（规范 3.2、S5）：`a < b < c` 是**错误**。实现上 `parseComparison` 只允许**至多一个**比较运算符；若随后又出现比较运算符，报 `CodeChainedCompare` 并给出改写建议（`如果 0 < 分数 并且 分数 < 100`），而不是默默按左结合解析成 `(a < b) < c`。这是"语法/语义与 02 严格一致"的一条硬性检查。

// ── 打印：诊断文案与 AST 快照共用的稳定文本形式 ────────────
//
// 用途一：报错时说"0 < 分数 < 100 不能连写"要把原表达式回显出来；
// 用途二：8.2 的 AST 快照（ast.Dump 基于 Print 做缩进展开）。
//
// ★ 注意输出必须**稳定**：字段顺序固定、数字用 FormatNumber 的口径、
//   绝不含 map 迭代顺序或指针地址。Go 的 map 顺序是故意随机的，
//   任何"直接 range map 拼字符串"的写法都会让快照测试随机失败。
func Print(n Node) string {
	switch x := n.(type) {
	case *NumLit:
		return formatRat(x.Val)
	case *TextLit:
		return strconv.Quote(x.Val)
	case *BoolLit:
		if x.Val {
			return "真"
		}
		return "假"
	case *NullLit:
		return "空值"
	case *Var:
		return x.Name
	case *StringTemplate:
		var sb strings.Builder
		sb.WriteString("\"")
		for _, p := range x.Parts {
			if p.Expr == nil {
				sb.WriteString(p.Text)
			} else {
				sb.WriteString("{" + Print(p.Expr) + "}")
			}
		}
		sb.WriteString("\"")
		return sb.String()
	case *ListLit:
		items := make([]string, 0, len(x.Items))
		for _, it := range x.Items {
			items = append(items, Print(it))
		}
		return "[" + strings.Join(items, ", ") + "]"
	case *DictLit:
		pairs := make([]string, 0, len(x.Pairs))
		for _, p := range x.Pairs {
			pairs = append(pairs, Print(p.Key)+": "+Print(p.Value))
		}
		return "{" + strings.Join(pairs, ", ") + "}"
	case *Unary:
		if x.Op == UOpNeg {
			return "-" + Print(x.Operand)
		}
		return "非 " + Print(x.Operand)
	case *Binary:
		return Print(x.Left) + " " + binaryOpText(x.Op) + " " + Print(x.Right)
	case *Index:
		return Print(x.Target) + "[" + Print(x.Index) + "]"
	case *Attr:
		return Print(x.Target) + "." + x.Name
	case *Call:
		parts := make([]string, 0, len(x.Args)+len(x.Kwargs))
		for _, a := range x.Args {
			parts = append(parts, Print(a))
		}
		for _, kw := range x.Kwargs {
			parts = append(parts, kw.Name+": "+Print(kw.Value))
		}
		return Print(x.Callee) + "(" + strings.Join(parts, ", ") + ")"
	case *Lambda:
		return "函数(" + strings.Join(x.Params, ", ") + ") => " + Print(x.Body)
	}
	return "<未知节点>"
}

func binaryOpText(op BinaryOp) string {
	switch op {
	case OpAdd:
		return "+"
	case OpSub:
		return "-"
	case OpMul:
		return "*"
	case OpDiv:
		return "/"
	case OpMod:
		return "%"
	case OpEq:
		return "=="
	case OpNeq:
		return "!="
	case OpLT:
		return "<"
	case OpLE:
		return "<="
	case OpGT:
		return ">"
	case OpGE:
		return ">="
	case OpAnd:
		return "并且"
	case OpOr:
		return "或者"
	}
	return "?"
}

// formatRat 按"整数就写整数、否则写分数"的规则打印字面量。
// 注意这里**故意**不用 interp.FormatNumber：ast 包不许 import interp（1.1 分层铁律），
// 而且 AST 快照要的是"值的原样"（3/2 就写 3/2），不是"15 位有效数字的显示形式"。
func formatRat(r *big.Rat) string {
	if r.IsInt() {
		return r.Num().String()
	}
	return r.RatString() // "3/2"
}
```

**为什么把 AST 放在 `internal/parser/ast` 而不是 `internal/parser`**：`internal/interp` 需要消费 AST，但**不许** import `internal/parser`（1.1 的分层铁律）。把 AST 抽到子包 `ast` 后，依赖变成 `parser -> ast` 与 `interp -> ast`，两条边都合法，`interp` 也拿不到解析器的任何内部状态。

**为什么字面量不用 `any`**：AST 快照测试（8.2）要把 AST 打印成稳定的文本。若 `NumLit.Val` 是 `any`，打印代码就得对每个值做类型断言，还要处理"同一个数打印成 `0` 还是 `0/1`"。用 `*big.Rat` 之后，AST 打印器（4.2 末尾的 `ast.Print`）用一条固定规则输出——整数写整数、分数写 `3/2`——既不必做类型断言，也**不依赖显示层的舍入规则**，快照因此长期稳定。反过来，`ast` 包**不许** import `interp` 去复用 `FormatNumber`：那会违反 1.1 的分层铁律，也会让"AST 快照"随显示口径变化而抖动。

### 4.3 解析器骨架（含错误恢复）

```go
// internal/parser/parser.go
package parser

import (
	"math/big"

	"sahou/internal/diag"
	"sahou/internal/lexer"
	"sahou/internal/parser/ast"
)

type Parser struct {
	toks  []lexer.Token
	file  string
	p     int
	diags []diag.Diagnostic
}

func New(toks []lexer.Token, filename string) *Parser {
	return &Parser{toks: toks, file: filename}
}

// ParseProgram 是唯一对外入口：返回 AST 与全部诊断（有诊断时 AST 仍可用，
// 便于快照测试与"一次报多个错"）。
func (p *Parser) ParseProgram() (*ast.Program, []diag.Diagnostic) {
	start := p.peek()
	body := make([]ast.Stmt, 0, 32)
	p.skipNewlines()
	for !p.check(lexer.TokEOF) {
		stmt := p.parseStatement()
		if stmt != nil {
			body = append(body, stmt)
		}
		p.skipNewlines()
	}
	return &ast.Program{Pos: pos(start), Body: body}, p.diags
}

// ── 工具 ─────────────────────────────────────────────────

func (p *Parser) peek() lexer.Token { return p.toks[min(p.p, len(p.toks)-1)] }

func (p *Parser) peekAt(k int) lexer.Token { return p.toks[min(p.p+k, len(p.toks)-1)] }

func (p *Parser) check(kinds ...lexer.TokenKind) bool {
	got := p.peek().Kind
	for _, k := range kinds {
		if got == k {
			return true
		}
	}
	return false
}

func (p *Parser) match(kinds ...lexer.TokenKind) (lexer.Token, bool) {
	if p.check(kinds...) {
		tok := p.peek()
		p.p++
		return tok, true
	}
	return lexer.Token{}, false
}

func (p *Parser) skipNewlines() {
	for p.check(lexer.TokNewline) {
		p.p++
	}
}

// expect 在缺失时记一条诊断，并**返回一个零值 token 继续**，避免连锁报错。
// whatCN 是"期望什么"的中文说法，fixHint 是可选的教学化建议。
func (p *Parser) expect(kind lexer.TokenKind, whatCN, fixHint string) lexer.Token {
	if tok, ok := p.match(kind); ok {
		return tok
	}
	got := p.peek()
	actual := got.Text
	if actual == "" {
		actual = "换行/文件结束"
	}
	p.diags = append(p.diags, diag.New(diag.CodeUnexpectedToken, diag.SevError,
		pos(got), diag.Args{"期望": whatCN, "实际": actual},
		diag.WithSuggestion(fixHint))) // 例："这个 如果 少了一个 完毕 收尾"
	return got
}

func pos(t lexer.Token) ast.Pos {
	return ast.Pos{Line: t.Line, Col: t.Col, Offset: t.Offset}
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

// ── 语句层：语句边界先吃掉软换行 ─────────────────────────

func (p *Parser) parseStatement() ast.Stmt {
	tok := p.peek()
	switch {
	case tok.Kind == lexer.TokFn && p.peekAt(1).Kind == lexer.TokIdent:
		return p.parseFuncDef()
	case tok.Kind == lexer.TokIf:
		return p.parseIf()
	case tok.Kind == lexer.TokWhile:
		return p.parseWhile()
	case tok.Kind == lexer.TokFor:
		return p.parseFor()
	case tok.Kind == lexer.TokTry:
		return p.parseTry()
	case tok.Kind == lexer.TokReturn:
		return p.parseReturn()
	case tok.Kind == lexer.TokEnd:
		// 多余收尾词：专门错误码 + 专门文案（规范 7.2 示例 4）。
		p.diags = append(p.diags, diag.New(diag.CodeStrayEnd, diag.SevError, pos(tok),
			diag.Args{"词": tok.Text}))
		p.p++
		return nil
	default:
		return p.parseAssignOrExpr()
	}
}

// parseBlock：直到遇到某个收尾关键字为止。块体为空要单独报错（规范 4.3 第 2 条）。
func (p *Parser) parseBlock(openTok lexer.Token, terminators ...lexer.TokenKind) []ast.Stmt {
	p.skipNewlines()
	body := make([]ast.Stmt, 0, 8)
	for !p.check(append(terminators, lexer.TokEOF)...) {
		stmt := p.parseStatement()
		if stmt != nil {
			body = append(body, stmt)
		}
		p.skipNewlines()
	}
	if len(body) == 0 {
		p.diags = append(p.diags, diag.New(diag.CodeEmptyBlock, diag.SevError, pos(openTok),
			diag.Args{"开头": openTok.Text}))
	}
	return body
}

func (p *Parser) parseIf() ast.Stmt {
	start := p.expect(lexer.TokIf, "如果/if", "")
	cond := p.ParseExpression()
	branches := []ast.Branch{{Cond: cond, Body: p.parseBlock(start, lexer.TokElif, lexer.TokElse, lexer.TokEnd)}}
	for {
		elif, ok := p.match(lexer.TokElif)
		if !ok {
			break
		}
		c := p.ParseExpression()
		branches = append(branches, ast.Branch{Cond: c, Body: p.parseBlock(elif, lexer.TokElif, lexer.TokElse, lexer.TokEnd)})
	}
	var orelse []ast.Stmt
	if elseTok, ok := p.match(lexer.TokElse); ok {
		orelse = p.parseBlock(elseTok, lexer.TokEnd)
		// 又如 写在 否则 之后：规范 5.9 明确报错。
		if p.check(lexer.TokElif) {
			p.diags = append(p.diags, diag.New(diag.CodeElifAfterElse, diag.SevError, pos(p.peek()), nil))
		}
	}
	// ★ 缺 完毕 时，不在缺它的位置报错，而是在块开头报错并给建议（规范 4.3 第 4 条）。
	p.expect(lexer.TokEnd, "完毕/end",
		"每个 如果/if 都要用 完毕/end 收尾；这个块从第 "+itoa(start.Line)+" 行开始")
	return &ast.If{Pos: pos(start), Branches: branches, Orelse: orelse}
}

// ── 表达式：方法嵌套顺序 == 优先级顺序（规范 3.2） ──────────

func (p *Parser) ParseExpression() ast.Expr { return p.parseLambda() }

// parseLambda：最低优先级，只认 函数/函数 (参数) => 表达式（规范 4.2）。
func (p *Parser) parseLambda() ast.Expr {
	if p.check(lexer.TokFn) && p.peekAt(1).Kind == lexer.TokLParen {
		start := p.peek()
		p.p += 2 // 吃掉 函数 (
		params := p.parseParams()
		p.expect(lexer.TokRParen, ")", "")
		p.expect(lexer.TokArrow, "=>", "匿名函数要写成 函数(x) => x + 1")
		body := p.ParseExpression() // 函数体延伸到最右
		return &ast.Lambda{Pos: pos(start), Params: params, Body: body}
	}
	return p.parseOr()
}

func (p *Parser) parseOr() ast.Expr {
	left := p.parseAnd()
	for {
		tok, ok := p.match(lexer.TokOr)
		if !ok {
			return left
		}
		left = &ast.Binary{Pos: pos(tok), Op: ast.OpOr, Left: left, Right: p.parseAnd()}
	}
}

func (p *Parser) parseAnd() ast.Expr {
	left := p.parseNot()
	for {
		tok, ok := p.match(lexer.TokAnd)
		if !ok {
			return left
		}
		left = &ast.Binary{Pos: pos(tok), Op: ast.OpAnd, Left: left, Right: p.parseNot()}
	}
}

func (p *Parser) parseNot() ast.Expr {
	if tok, ok := p.match(lexer.TokNot); ok {
		return &ast.Unary{Pos: pos(tok), Op: ast.UOpNot, Operand: p.parseNot()}
	}
	return p.parseComparison()
}

// parseComparison：至多一个比较运算符（规范 3.2、S5 不可连写）。
func (p *Parser) parseComparison() ast.Expr {
	left := p.parseTerm()
	tok, ok := p.match(lexer.TokEq, lexer.TokNeq, lexer.TokLT, lexer.TokLE, lexer.TokGT, lexer.TokGE)
	if !ok {
		return left
	}
	right := p.parseTerm()
	node := &ast.Binary{Pos: pos(tok), Op: compareOp(tok.Kind), Left: left, Right: right}
	if _, chained := p.match(lexer.TokEq, lexer.TokNeq, lexer.TokLT, lexer.TokLE, lexer.TokGT, lexer.TokGE); chained {
		p.diags = append(p.diags, diag.New(diag.CodeChainedCompare, diag.SevError, pos(tok),
			diag.Args{"原文": ast.Print(left) + " " + tok.Text + " ..."}))
		// 吞掉剩下的比较，避免同一条链报三次。
		for p.check(lexer.TokEq, lexer.TokNeq, lexer.TokLT, lexer.TokLE, lexer.TokGT, lexer.TokGE) {
			p.p++
			p.parseTerm()
		}
	}
	return node
}

func (p *Parser) parseTerm() ast.Expr {
	left := p.parseFactor()
	for {
		tok, ok := p.match(lexer.TokPlus, lexer.TokMinus)
		if !ok {
			return left
		}
		op := ast.OpAdd
		if tok.Kind == lexer.TokMinus {
			op = ast.OpSub
		}
		left = &ast.Binary{Pos: pos(tok), Op: op, Left: left, Right: p.parseFactor()}
	}
}

func (p *Parser) parseFactor() ast.Expr {
	left := p.parseUnary()
	for {
		tok, ok := p.match(lexer.TokStar, lexer.TokSlash, lexer.TokPercent)
		if !ok {
			return left
		}
		left = &ast.Binary{Pos: pos(tok), Op: mulOp(tok.Kind), Left: left, Right: p.parseUnary()}
	}
}

func (p *Parser) parseUnary() ast.Expr {
	if tok, ok := p.match(lexer.TokMinus); ok {
		return &ast.Unary{Pos: pos(tok), Op: ast.UOpNeg, Operand: p.parseUnary()}
	}
	return p.parsePostfix()
}

// parsePostfix：调用/索引/成员，左结合、可叠加（a.b[0](x)）。
func (p *Parser) parsePostfix() ast.Expr {
	expr := p.parsePrimary()
	for {
		switch {
		case p.check(lexer.TokLParen):
			tok := p.peek()
			p.p++
			args, kwargs := p.parseArgs()
			p.expect(lexer.TokRParen, ")", "")
			expr = &ast.Call{Pos: pos(tok), Callee: expr, Args: args, Kwargs: kwargs}
		case p.check(lexer.TokLBracket):
			tok := p.peek()
			p.p++
			idx := p.ParseExpression()
			p.expect(lexer.TokRBracket, "]", "索引要写成 名单[0]")
			expr = &ast.Index{Pos: pos(tok), Target: expr, Index: idx}
		case p.check(lexer.TokDot):
			tok := p.peek()
			p.p++
			name := p.expect(lexer.TokIdent, "字段名", "点号后面要写名字，比如 动物.名字")
			expr = &ast.Attr{Pos: pos(tok), Target: expr, Name: name.Text}
		default:
			return expr
		}
	}
}

// parseArgs：位置实参在前，命名实参（标识符 ":" 表达式）在后（规范 4.3 第 6 条）。
func (p *Parser) parseArgs() ([]ast.Expr, []ast.Kwarg) {
	var args []ast.Expr
	var kwargs []ast.Kwarg
	seenNamed := false
	for !p.check(lexer.TokRParen, lexer.TokEOF) {
		if p.check(lexer.TokIdent) && p.peekAt(1).Kind == lexer.TokColon {
			seenNamed = true
			name := p.peek().Text
			p.p += 2
			kwargs = append(kwargs, ast.Kwarg{Name: name, Value: p.ParseExpression()})
		} else {
			if seenNamed {
				p.diags = append(p.diags, diag.New(diag.CodePositionalAfterNamed, diag.SevError, pos(p.peek()), nil))
			}
			args = append(args, p.ParseExpression())
		}
		if _, ok := p.match(lexer.TokComma); !ok {
			break
		}
	}
	return args, kwargs
}

func (p *Parser) parsePrimary() ast.Expr {
	tok := p.peek()
	switch tok.Kind {
	case lexer.TokNumber:
		p.p++
		val, ok := new(big.Rat).SetString(tok.Text)
		if !ok { // 词法器已保证格式合法，这里只是兜底
			p.diags = append(p.diags, diag.New(diag.CodeBadNumber, diag.SevError, pos(tok),
				diag.Args{"原文": tok.Text}))
			val = new(big.Rat)
		}
		return &ast.NumLit{Pos: pos(tok), Val: val}
	case lexer.TokString:
		p.p++
		return &ast.TextLit{Pos: pos(tok), Val: unescape(tok.Text)}
	case lexer.TokTemplate:
		p.p++
		return p.compileTemplate(tok)
	case lexer.TokTrue:
		p.p++
		return &ast.BoolLit{Pos: pos(tok), Val: true}
	case lexer.TokFalse:
		p.p++
		return &ast.BoolLit{Pos: pos(tok), Val: false}
	case lexer.TokNull:
		p.p++
		return &ast.NullLit{Pos: pos(tok)}
	case lexer.TokIdent:
		p.p++
		return &ast.Var{Pos: pos(tok), Name: tok.Text}
	case lexer.TokLParen:
		p.p++
		inner := p.ParseExpression()
		p.expect(lexer.TokRParen, ")", "括号要成对出现")
		return inner
	case lexer.TokLBracket:
		return p.parseListLit()
	case lexer.TokLBrace:
		return p.parseDictLit()
	}
	// 走到这里 = 这里本该有值却没有（规范 7.2 常见场景）。
	p.diags = append(p.diags, diag.New(diag.CodeExpectedExpression, diag.SevError, pos(tok),
		diag.Args{"实际": orElse(tok.Text, "换行/文件结束")}))
	p.p++ // 弹性恢复：吞掉一个 token 继续
	return &ast.NullLit{Pos: pos(tok)}
}

// compileTemplate：把 Token.Parts 变成"字面文本 | 已解析表达式"的交替序列。
// 插值内部调用 lexer + parser 各一次（3.5 的取舍），位置带上真实行列。
func (p *Parser) compileTemplate(tok lexer.Token) ast.Expr {
	parts := make([]ast.TemplatePartExpr, 0, len(tok.Parts))
	for _, part := range tok.Parts {
		if !part.IsExpr {
			parts = append(parts, ast.TemplatePartExpr{Text: part.Text})
			continue
		}
		sub, subDiags := p.scanInterp(part)
		p.diags = append(p.diags, subDiags...)
		parts = append(parts, ast.TemplatePartExpr{Expr: sub})
	}
	return &ast.StringTemplate{Pos: pos(tok), Parts: parts}
}

// scanInterp 是 lexer.ExprScanner 接口的实现：
// 把插值片段当成一小段程序重新走一遍 Lexer->Parser。
func (p *Parser) scanInterp(part lexer.TemplatePart) (ast.Expr, []diag.Diagnostic) {
	sub := lexer.New([]byte(part.Text), p.file, part.Line, part.Col)
	sub.SetExprScanner(p)
	toks, diags := sub.Scan()
	subParser := New(toks, p.file)
	subParser.SetExprScanner(p) // 支持插值里再套插值
	expr := subParser.ParseExpression()
	diags = append(diags, subParser.diags...)
	return expr, diags
}
```

**错误恢复策略（对新手至关重要）**

1. **不 panic、不 early return，收集诊断**。解析器遇到错误时尽量"跳过一小段"继续，一次运行报出多个问题比"报一个改一个"体验好得多。所有 `expect`/`parsePrimary` 的失败路径都返回一个**可用的占位节点**（`NullLit`），让 AST 始终能够被构建与打印。
2. **同步点 = 语句终结符**：跳 token 直到遇见 `TokNewline`、`完毕/end`、`否则/else`、`又如/elif`、`EOF` 之一。实现上由 `parseBlock` 的 `skipNewlines` + 终结符判定共同完成。
3. **一个块缺少 `完毕` 时，不在缺它的位置报错，而是在块开始处报错**并给出建议——否则用户会看到一串被"传染"的错误。实现上 `parseIf` 把 `start` token 传给 `parseBlock`，并在 `expect(TokEnd, ...)` 的 `fixHint` 里带上"这个块从第 N 行开始"。
4. **`end` 多余时给专门错误码** `CodeStrayEnd`，文案指明"这里多了一个 `完毕`，它没有可以收尾的块"，并提示去检查第 N 行开始的块（规范 7.2 示例 4）。
5. **深度上限保护**：`p.depth` 记录递归深度，超过 200 层（例如用户写了 500 层嵌套括号）时报告"嵌套太深"并终止该分支。**任何用户输入都不许让解释器栈溢出崩溃**（8.5）。
6. **一次最多显示 10 条诊断**（6.3 渲染规则第 5 条），所以解析器允许"已经错了还继续解析"，由渲染层负责截断。

## 5. 求值器设计（树遍历）

### 5.1 环境与作用域链

《02》5.3 把 v1 的作用域简化到极致，实现必须**逐条对齐**：

1. 作用域只有两种：**每个函数一个作用域** + **顶层（主程序）作用域**；
2. `如果`/`又如`/`否则`/`当`/`遍历`/`尝试`/`接住` 的块**不创建新作用域**——块内赋值的变量在块结束后**依然存在**；
3. 函数内第一次给某名字赋值 → 在当前函数作用域**创建**变量（局部变量）；
4. 函数内读取名字 → 先当前作用域，再沿**定义处**的外层作用域找（词法作用域）；
5. 函数内给"外层已存在的名字"赋值 → **不改外层**，在当前作用域创建一个同名新变量（**遮蔽**）；
6. 参数是函数作用域的局部变量，调用结束后消失；列表/字典是**引用语义**，修改共享对象对调用者可见。

```go
// internal/interp/env.go
package interp

import "sahou/internal/parser/ast"

// Environment 是一个函数作用域（或顶层作用域）。
// 注意：块不建 Environment（规范 5.3 第 2 条），所以这里没有 "block" 的概念。
type Environment struct {
	vars   map[string]Value
	parent *Environment // 定义处的外层作用域（词法作用域）
	name   string       // 报错时显示"在 函数 乘法表 里"
}

func NewEnvironment(parent *Environment, name string) *Environment {
	return &Environment{vars: make(map[string]Value, 8), parent: parent, name: name}
}

// Define 在当前层定义/覆盖（参数绑定、函数定义、首次赋值都走这里）。
func (e *Environment) Define(name string, v Value) { e.vars[name] = v }

// Get 沿作用域链向上查找；找不到时返回 nil，由调用方产出带建议的诊断。
func (e *Environment) Get(name string) (Value, bool) {
	for env := e; env != nil; env = env.parent {
		if v, ok := env.vars[name]; ok {
			return v, true
		}
	}
	return nil, false
}

// Assign 实现规范 5.3 第 3、5 条：**只在当前作用域写**。
// 外层已有同名变量时不改它，而是在当前层新建一个同名局部变量（遮蔽）。
// 这一条与 Python 的 global/nonlocal 语义不同，但与教学直觉一致：
// "函数里的变量就是函数自己的"，孩子不需要理解"我现在在哪个作用域"。
func (e *Environment) Assign(name string, v Value) { e.vars[name] = v }

// Names 返回当前可见的全部名字，供"你是不是想写"使用（6.4）。
func (e *Environment) Names() map[string]struct{} {
	out := make(map[string]struct{}, 16)
	for env := e; env != nil; env = env.parent {
		for n := range env.vars {
			out[n] = struct{}{}
		}
	}
	return out
}

// LookupLocal 判断名字是否在**当前**作用域（用于函数内 设/let 的重复定义提示）。
func (e *Environment) LookupLocal(name string) (Value, bool) {
	v, ok := e.vars[name]
	return v, ok
}

// Frame 是调用栈上的一帧：函数名 + 调用发生的行号（规范 7.1 第 6 条的调用链）。
type Frame struct {
	FuncName string
	Line     int
	Env      *Environment
}
```

### 5.2 "数"类型的实现：`math/big.Rat` 精确有理数

简报 D3 要求"用户只看到一种数、整数精确运算内部必须保证"；规范 5.2（S8）进一步要求"小数用十进制 15 位有效数字，使 `0.1 + 0.2 == 0.3` 为真"。Go 版把这两条要求一次性解决：**"数"的唯一内部表示是 `*big.Rat`（任意精度有理数）**。

**核心事实**：整数就是**分母为 1 的有理数**，所以"任意精度整数天然成立"——`10`、`10.0`、`4 / 2` 在内部都是同一个值 `10/1`，`10 == 10.0` 是**同一个对象值的比较**，而不是"跨类型转换后碰巧相等"。小数运算（`+ - * / %`）全部精确：`0.1` 是 `1/10`、`0.2` 是 `1/5`，`0.1 + 0.2` 精确等于 `3/10`，`0.3` 也是 `3/10`，所以 `0.1 + 0.2 == 0.3` **恒为真**。

**只在显示时舍入到 15 位有效数字**：规范允许"内部精确、显示有限"。实现按用户指定的做法——先 `big.Float.Text('g', 15)` 得到 15 位有效数字，再转回普通十进制、去掉尾随零：

```go
// internal/interp/number.go
package interp

import (
	"math/big"
	"strings"
)

// Number 是 卅 唯一的数值类型（简报 D3）。
// 内部表示是精确有理数：整数即分母为 1 的有理数。
//
// 注意它是**指针类型**（*Number）：Value 接口要同时被 *ListValue / *DictValue
// 与 Number 实现，统一用指针可以让 value.go 里的类型 switch 不必分两套写法。
type Number struct {
	r *big.Rat
}

// TypeName 实现 Value 接口（规范 6.2：类型(值) 返回英文类型名）。
func (n *Number) TypeName() string { return "number" }

// ── 构造 ─────────────────────────────────────────────────

func NewNumberInt64(n int64) *Number { return &Number{r: new(big.Rat).SetInt64(n)} }

func NewNumberFromInt(i *big.Int) *Number { return &Number{r: new(big.Rat).SetInt(i)} }

// NewNumberFromDecimal 解析十进制字面量（"10"、"3.5"、"10.0"）。
// big.Rat.SetString 对 "3.5" 给出精确的 7/2，对 "10" 给出 10/1，
// 因此 "10.0" 会被规范化成 10/1——这就是 10 == 10.0 的实现基础。
func NewNumberFromDecimal(text string) (*Number, bool) {
	r, ok := new(big.Rat).SetString(text)
	if !ok {
		return nil, false
	}
	return &Number{r: r}, true
}

// NewNumberFromFloat64 把宿主浮点值变成"恰好等于该 float64 的有理数"。
// 用途：平方根等不可避免要经过浮点的运算。注意它保持的是 float64 的精确值，
// 显示阶段仍会按 15 位有效数字收敛（规范 5.2）。
func NewNumberFromFloat64(f float64) *Number {
	if f == 0 {
		return NewNumberInt64(0)
	}
	return &Number{r: new(big.Rat).SetFloat64(f)}
}

func NewNumberFromBigFloat(f *big.Float) *Number {
	r, _ := f.Rat(nil)
	return &Number{r: r}
}

// ── 判定与取值 ───────────────────────────────────────────

func (n *Number) Rat() *big.Rat { return n.r }

// IsInt 判断是不是整数值（分母为 1）。索引、重复次数、步长、键都必须过这一关。
func (n *Number) IsInt() bool { return n.r.IsInt() }

// Int 返回整数形式（调用方必须先确认 IsInt）。
func (n *Number) Int() *big.Int { return new(big.Int).Set(n.r.Num()) }

// ToInt64 供"必须是小整数"的位置使用（如小数位数）；不是整数或太大时返回 false。
func (n *Number) ToInt64() (int64, bool) {
	if !n.r.IsInt() || !n.r.Num().IsInt64() {
		return 0, false
	}
	return n.r.Num().Int64(), true
}

func (n *Number) Sign() int { return n.r.Sign() }

// CmpNumber 是数与数比较的唯一实现（规范 3.3：按数学值比较）。
func CmpNumber(a, b *Number) int { return a.r.Cmp(b.r) }

func EqualNumber(a, b *Number) bool { return a.r.Cmp(b.r) == 0 }

// IsZero 为真值规则服务（规范 5.4：0 是假值，0.0 与 0 是同一个数）。
func (n *Number) IsZero() bool { return n.r.Sign() == 0 }

// ── 运算：全部精确 ───────────────────────────────────────

type ArithError struct {
	Code string // "divide_by_zero" | "mod_by_zero" | ...
	Pos  ast.Pos
}

func (a *ArithError) Error() string { return a.Code }

// Arith 执行 + - * / %，全部在有理数域内精确进行（规范 5.2）。
func Arith(op ast.BinaryOp, a, b *Number, p ast.Pos) (*Number, error) {
	switch op {
	case ast.OpAdd:
		return &Number{r: new(big.Rat).Add(a.r, b.r)}, nil
	case ast.OpSub:
		return &Number{r: new(big.Rat).Sub(a.r, b.r)}, nil
	case ast.OpMul:
		return &Number{r: new(big.Rat).Mul(a.r, b.r)}, nil
	case ast.OpDiv:
		if b.r.Sign() == 0 {
			return nil, &ArithError{Code: "divide_by_zero", Pos: p}
		}
		// ★ 能整除时结果自动保持整数形式：4/2 的 big.Rat 就是 2/1，
		//   不必写任何"归一化"代码——有理数约分是 big.Rat 的内建行为。
		return &Number{r: new(big.Rat).Quo(a.r, b.r)}, nil
	case ast.OpMod:
		if b.r.Sign() == 0 {
			return nil, &ArithError{Code: "mod_by_zero", Pos: p}
		}
		// 余数符号跟随被除数（规范 3.3：-7 % 3 得 2，与 Python 一致）。
		return &Number{r: new(big.Rat).Rem(a.r, b.r)}, nil
	}
	return nil, &ArithError{Code: "bad_op", Pos: p}
}

// ── 显示：15 位有效数字、去尾零、整数不带小数点（规范 5.2、5.10） ──

const displaySigDigits = 15

// FormatNumber 把数渲染成用户看到的文本。规则（规范 5.2、5.10）：
//  1. 整数值（含"除出来正好是整数"的 4/2）：直接输出整数，不带小数点；
//  2. 其它值：舍入到 15 位有效数字，十进制书写，去掉尾随零与孤零零的小数点；
//  3. 永不输出科学计数法——新手看到 "1e-07" 只会更困惑。
//
// 用户要求的口径是"big.Float.Text('g',15) 之后再转普通十进制、去尾零"。
// 这里把同一口径**直接写成定点十进制展开**：结果与它等价（15 位有效数字、
// half-up 舍入、去尾零），但更短、更稳，也天然不会掉进 'g' 的指数区间
// （big.Float.Text('g',15) 对 33.333… 会给出 "33.3333333333333"，
//  对大数给出 "1.23456789012345e+20"，后者还要再转回来）。
func FormatNumber(n Number) string {
	if n.r.Sign() == 0 {
		return "0"
	}
	if n.r.IsInt() {
		return n.r.Num().String() // 整数：无损、无小数点
	}
	neg := n.r.Sign() < 0
	num := new(big.Int).Abs(n.r.Num()) // |分子|
	den := new(big.Int).Set(n.r.Denom())

	// mag 是十进制指数：保证 1 <= |值|/10^mag < 10。
	mag := decimalMagnitude(num, den)

	// after：小数点后保留几位，使总有效数字恰为 15 位。
	//   mag 很大（如 1e19 的小数）时 after 为负 -> 舍入到整数的高位；
	//   mag 很负（如 1e-20）时 after 可能超过 15 -> 用全部 15 位不够写，
	//   此时按 after 截断，并在下面自然得到 0.000…0。
	after := displaySigDigits - 1 - mag
	if after < -displaySigDigits { // 值太小：15 位有效数字之外全是零
		after = -displaySigDigits
	}
	var scale *big.Int
	if after >= 0 {
		scale = pow10(after)
	} else {
		scale = pow10(-after)
	}

	// 统一成"整数除法 + 四舍五入"：|值| * 10^after 的整数部分。
	numerator := new(big.Int).Mul(num, scale)
	var divisor *big.Int
	if after >= 0 {
		divisor = den
	} else {
		divisor = new(big.Int).Mul(den, scale)
	}
	q, r := new(big.Int).QuoRem(numerator, divisor, new(big.Int))
	// half-up：余数 * 2 >= 除数 就进位（0.5 向上，符合中文"四舍五入"）。
	if new(big.Int).Lsh(r, 1).Cmp(divisor) >= 0 {
		q.Add(q, big.NewInt(1))
	}
	digits := q.String()

	// 把纯数字串折回小数点。整数部分应有 after 位（可能 <= 0，需要左侧补零）。
	var out string
	switch {
	case after <= 0:
		out = digits // 已经是整数形式（值 >= 1e15 的小数被舍入到整数）
	case after >= len(digits):
		// 有效数字不足 after 位：说明原值小于 10^-15，补零后交给去尾零处理。
		out = "0." + strings.Repeat("0", after-len(digits)) + digits
	default:
		out = digits[:len(digits)-after] + "." + digits[len(digits)-after:]
	}
	// 去尾零、去尾部小数点（所以永远看不到 "10.0" 或 "14.00"）。
	if strings.Contains(out, ".") {
		out = strings.TrimRight(out, "0")
		out = strings.TrimSuffix(out, ".")
	}
	if neg && out != "0" {
		out = "-" + out
	}
	return out
}

func pow10(n int) *big.Int { return new(big.Int).Exp(big.NewInt(10), big.NewInt(int64(n)), nil) }

// decimalMagnitude 返回十进制指数 mag，使 1 <= |num/den| / 10^mag < 10。
// 只用整数比较，不引入任何浮点。
func decimalMagnitude(num, den *big.Int) int {
	m := len(num.String()) - len(den.String())
	if m >= 0 {
		// 比较 num 与 den * 10^m
		if num.Cmp(new(big.Int).Mul(den, pow10(m))) < 0 {
			m--
		}
	} else {
		// 比较 num * 10^(-m) 与 den
		if new(big.Int).Mul(num, pow10(-m)).Cmp(den) < 0 {
			m--
		}
	}
	return m
}
```

**规范 5.2 的六个例子逐条兑现**：

| 写法 | 内部值（精确有理数） | 显示 |
|---|---|---|
| `print(10)` | `10/1` | `10` |
| `print(3.5)` | `7/2` | `3.5` |
| `print(10 == 10.0)` | 比较 `10/1` 与 `10/1` | `真` |
| `print(10 / 3)` | `10/3`（精确！） | `3.33333333333333`（15 位有效数字） |
| `print(4 / 2)` | `2/1`（自动约分，**保持整数形式**） | `2` |
| `print(10 % 3)` | `1/1` | `1` |
| `0.1 + 0.2 == 0.3` | `3/10 == 3/10` | `真`（恒真） |
| `print(1 / 4)` | `1/4` | `0.25` |

**几条实现纪律**（对应旧版的"单一出口"设计）：

1. 解释器任何位置都**不许**用 `switch v.(type)` 之外的手段判断"是不是数"，必须调用 `value.go` 里的 `IsNumber(v)` / `AsNumber(v)`；
2. 索引、重复次数、步长、小数位数必须走 `toIndexValue(...)`：它保证是**整数**并给出友好错误（`列表的编号必须是整数，你给的是 2.5`；`下标不能是负数，你可能是想取最后一个元素`，规范 7.2 示例 7、8）；
3. 所有算术必须走 `Arith`，不许在任何内置函数里直接对 `big.Rat` 做 `Add`——否则"除零报错可被接住"这条语义会在别处被绕过；
4. 显示必须走 `FormatNumber`，`打印`/`文本()`/字符串插值三处共用它，保证 `print(10/3)` 与 `"{10/3}"` 显示**逐字一致**（规范 6.1）。

**关于 `%`**：`big.Rat.Rem` 对有理数给出与被除数同号的余数，与规范 3.3"余数的符号跟随被除数（`-7 % 3` 得 `2`）"一致。若两边都是整数，结果也是整数（分母为 1）。

**关于"精度"**：`10 / 3` 的**值**永远是精确的 `10/3`，显示时才舍入。这意味着 `(10 / 3) * 3 == 10` 为**真**——这在用 `float64` 的实现里是做不到的，也是"精确有理数"相比旧版 Python `float` 方案最实质的改进。

### 5.3 求值器骨架

先定义统一的 `Value` 与一组"跨包可见的辅助方法"。后者不是可选项：`internal/builtins` 要调用求值器的语义出口，所以这些方法必须**导出**（大写开头），而 `errf`、`KwText`、`AsNumber` 就是它们的正式名字。

// dictKey 把键归一化成可比较的字符串。规范 5.6：键只能是文本或数。

**两条实现纪律**（8.5 会检查）：

- 数字转文本统一走 `strconv.Itoa`（`itoa` 是它的包内别名），不要用 `fmt.Sprintf`——解释器热路径上的格式化开销要省，且 `fmt` 的输出格式随参数类型变化，不适合出现在报错文案里；
- 用户写的名字回显统一走 `quote`：它**只加半角引号、不做任何转义**，所以用户写 `完毕` 报错里就是 `"完毕"`，用户写 `nmae` 报错里就是 `"nmae"`（规范 7.1 第 1 条"回显原文"）。

```go
// internal/interp/eval.go
package interp

// Interpreter 是树遍历求值器。所有对外副作用（stdout/stderr/stdin）
// 都通过字段注入，测试可以换成 bytes.Buffer 做逐字节断言（8.1）。
type Interpreter struct {
	globals  *Environment
	stdout   io.Writer
	stderr   io.Writer
	stdin    *bufio.Reader
	diags    []diag.Diagnostic
	exitCode int
	frames   []Frame // 调用栈，用于规范 7.1 第 6 条的调用链
	depth    int
	maxDepth int
}

// runSignal 是"返回"的展开机制：用 panic/recover 之外的显式 error 通道，
// 保证它**不会**被 尝试/接住 捕获（规范 5.9：返回 穿过 尝试 块正常返回）。
type runSignal struct{ value Value }

func (r *runSignal) Error() string { return "return" }

// 卅Error 是所有 卅 运行时错误的载体。
// 简报 D8：错误对象就是一个文本 —— 因此 msg 就是绑定给 接住 的那个值。
type 卅Error struct {
	msg    string
	pos    ast.Pos
	code   diag.ErrorCode
	frames []Frame
	hint   string
}

func (e *卅Error) Error() string { return e.msg }

func (in *Interpreter) ExecProgram(prog *ast.Program) {
	for _, stmt := range prog.Body {
		if err := in.execStmt(stmt, in.globals); err != nil {
			if rs, ok := err.(*runSignal); ok {
				// 顶层 返回 表示结束整个程序（规范 5.8、S12）；
				// 带值时打印提示，不带值时静默退出。
				if rs.value != nil {
					if _, isNull := rs.value.(NullValue); !isNull {
						fmt.Fprintln(in.stdout, FormatValue(rs.value))
					}
				}
				return
			}
			in.report(err) // 未接住的错误：渲染诊断 + 调用链，退出码 1
			return
		}
	}
}

func (in *Interpreter) execBlock(body []ast.Stmt, env *Environment) error {
	for _, stmt := range body {
		if err := in.execStmt(stmt, env); err != nil {
			return err
		}
	}
	return nil
}

func (in *Interpreter) execStmt(node ast.Stmt, env *Environment) error {
	switch n := node.(type) {
	case *ast.ExprStmt:
		_, err := in.eval(n.Expr, env)
		return err

	case *ast.Assign:
		val, err := in.eval(n.Value, env)
		if err != nil {
			return err
		}
		switch target := n.Target.(type) {
		case *ast.Var:
			// ★ 规范 5.3 第 3、5 条：赋值只落在当前作用域（遮蔽）。
			env.Assign(target.Name, val)
			return nil
		case *ast.Index:
			container, err := in.eval(target.Target, env)
			if err != nil {
				return err
			}
			key, err := in.eval(target.Index, env)
			if err != nil {
				return err
			}
			return in.setIndex(container, key, val, n.Pos)
		case *ast.Attr:
			container, err := in.eval(target.Target, env)
			if err != nil {
				return err
			}
			return in.setAttr(container, target.Name, val, n.Pos)
		}
		return in.errf(diag.CodeBadLValue, n.Pos, "这里不能赋值", nil)

	case *ast.FuncDef:
		env.Define(n.Name, &UserFunc{Name: n.Name, Params: n.Params, Body: n.Body, Closure: env})
		return nil

	case *ast.If:
		for _, br := range n.Branches {
			cond, err := in.eval(br.Cond, env)
			if err != nil {
				return err
			}
			if in.IsTruthy(cond) {
				// ★ 块不创建作用域（规范 5.3 第 2 条）：直接复用 env。
				return in.execBlock(br.Body, env)
			}
		}
		if n.Orelse != nil {
			return in.execBlock(n.Orelse, env)
		}
		return nil

	case *ast.While:
		for {
			cond, err := in.eval(n.Cond, env)
			if err != nil {
				return err
			}
			if !in.IsTruthy(cond) {
				return nil
			}
			if err := in.execBlock(n.Body, env); err != nil {
				return err
			}
		}

	case *ast.For:
		iter, err := in.eval(n.Iterable, env)
		if err != nil {
			return err
		}
		items, err := in.toIterable(iter, n.Pos) // 列表给元素、文本给字符、字典给键
		if err != nil {
			return err
		}
		for _, item := range items {
			// ★ 循环变量定义在**当前**作用域，所以循环结束后它仍然存在（规范 5.9）。
			env.Assign(n.Var, item)
			if err := in.execBlock(n.Body, env); err != nil {
				return err
			}
		}
		return nil

	case *ast.Try:
		err := in.execBlock(n.Body, env)
		if err == nil {
			return nil
		}
		if _, isReturn := err.(*runSignal); isReturn {
			return err // ★ 返回 不被 接住（规范 5.9 最后一条）
		}
		se, ok := err.(*卅Error)
		if !ok {
			return err
		}
		// 规范 D8：错误对象就是一个文本，直接绑定给 接住 的名字。
		env.Assign(n.CatchName, TextValue(se.msg))
		return in.execBlock(n.Handler, env)

	case *ast.Return:
		if n.Value == nil {
			return &runSignal{value: NullValue{}}
		}
		v, err := in.eval(n.Value, env)
		if err != nil {
			return err
		}
		return &runSignal{value: v}
	}
	return in.errf(diag.CodeBadStmt, node.NodePos(), "我不认识这个语句", nil)
}

func (in *Interpreter) eval(node ast.Expr, env *Environment) (Value, error) {
	switch n := node.(type) {
	case *ast.NumLit:
		return &Number{r: n.Val}, nil
	case *ast.TextLit:
		return TextValue(n.Val), nil
	case *ast.BoolLit:
		return BoolValue(n.Val), nil
	case *ast.NullLit:
		return NullValue{}, nil

	case *ast.StringTemplate:
		return in.evalTemplate(n, env)

	case *ast.Var:
		if v, ok := env.Get(n.Name); ok {
			return v, nil
		}
		// 未定义名字：候选集合 = 当前可见名字 + 内置函数名（6.4 表第 1 行）。
		cands := env.Names()
		for name := range in.builtinNames() {
			cands[name] = struct{}{}
		}
		return nil, in.errf(diag.CodeUndefinedName, n.Pos,
			"变量 "+quote(n.Name)+" 还没有定义", diag.Args{"名字": n.Name},
			diag.WithCandidates(n.Name, cands))

	case *ast.ListLit:
		elems := make([]Value, 0, len(n.Items))
		for _, it := range n.Items {
			v, err := in.eval(it, env)
			if err != nil {
				return nil, err
			}
			elems = append(elems, v)
		}
		return &ListValue{Elems: elems}, nil

	case *ast.DictLit:
		d := NewDictValue()
		for _, pair := range n.Pairs {
			k, err := in.eval(pair.Key, env)
			if err != nil {
				return nil, err
			}
			v, err := in.eval(pair.Value, env)
			if err != nil {
				return nil, err
			}
			// 重复键：后者覆盖前者 + 警告级提示（规范 5.6、S10）。
			if _, existed := d.Set(k, v); existed {
				in.warnf(diag.CodeDuplicateKey, pair.Key.NodePos(), "重复的键，后面的值覆盖了前面的", nil)
			}
		}
		return d, nil

	case *ast.Unary:
		v, err := in.eval(n.Operand, env)
		if err != nil {
			return nil, err
		}
		return in.unary(n.Op, v, n.Pos)

	case *ast.Binary:
		return in.binary(n, env)

	case *ast.Index:
		target, err := in.eval(n.Target, env)
		if err != nil {
			return nil, err
		}
		key, err := in.eval(n.Index, env)
		if err != nil {
			return nil, err
		}
		return in.getIndex(target, key, n.Pos)

	case *ast.Attr:
		target, err := in.eval(n.Target, env)
		if err != nil {
			return nil, err
		}
		return in.getAttr(target, n.Name, n.Pos)

	case *ast.Call:
		fn, err := in.eval(n.Callee, env)
		if err != nil {
			return nil, err
		}
		args := make([]Value, 0, len(n.Args))
		for _, a := range n.Args {
			v, err := in.eval(a, env)
			if err != nil {
				return nil, err
			}
			args = append(args, v)
		}
		kwargs := make(map[string]Value, len(n.Kwargs))
		for _, kw := range n.Kwargs {
			v, err := in.eval(kw.Value, env)
			if err != nil {
				return nil, err
			}
			kwargs[kw.Name] = v
		}
		return in.call(fn, args, kwargs, n.Pos)

	case *ast.Lambda:
		// 匿名函数体是表达式：包成一条 Return 语句复用同一个调用路径（规范 5.8）。
		return &UserFunc{
			Name:    "<匿名函数>",
			Params:  n.Params,
			Body:    []ast.Stmt{&ast.Return{Pos: n.Body.NodePos(), Value: n.Body}},
			Closure: env, // ★ 闭包捕获定义处环境（词法作用域）
		}, nil
	}
	return nil, in.errf(diag.CodeBadExpr, node.NodePos(), "我不认识这个算式", nil)
}

// binary：and/or 必须短路，其余走统一的语义出口。
func (in *Interpreter) binary(n *ast.Binary, env *Environment) (Value, error) {
	// ★ 短路必须在求值层特判，不能走通用算术分支；否则右边会被无条件求值，
	//   循环里的 i < 长度(列表) 并且 列表[i] > 0 就会越界（规范 3.3）。
	if n.Op == ast.OpAnd {
		left, err := in.eval(n.Left, env)
		if err != nil {
			return nil, err
		}
		if !in.IsTruthy(left) {
			return BoolValue(false), nil
		}
		right, err := in.eval(n.Right, env)
		if err != nil {
			return nil, err
		}
		return BoolValue(in.IsTruthy(right)), nil
	}
	if n.Op == ast.OpOr {
		left, err := in.eval(n.Left, env)
		if err != nil {
			return nil, err
		}
		if in.IsTruthy(left) {
			return BoolValue(true), nil
		}
		right, err := in.eval(n.Right, env)
		if err != nil {
			return nil, err
		}
		return BoolValue(in.IsTruthy(right)), nil
	}

	left, err := in.eval(n.Left, env)
	if err != nil {
		return nil, err
	}
	right, err := in.eval(n.Right, env)
	if err != nil {
		return nil, err
	}
	return in.binaryValues(n.Op, left, right, n.Pos)
}

// evalTemplate：插值求值（D6、规范 5.5）。每次执行到这行文本都重新求值。
func (in *Interpreter) evalTemplate(n *ast.StringTemplate, env *Environment) (Value, error) {
	var sb strings.Builder
	for _, part := range n.Parts {
		if part.Expr == nil {
			sb.WriteString(part.Text)
			continue
		}
		v, err := in.eval(part.Expr, env)
		if err != nil {
			return nil, err
		}
		sb.WriteString(FormatValue(v)) // 与 文本()/打印 共用同一套转换
	}
	return TextValue(sb.String()), nil
}
```

**几个不可省略的实现细节**

1. **`and`/`or` 短路**：必须在 `binary` 里特判，不能走 `Arith`/比较分支；否则右侧表达式会被无条件求值，循环里的 `i < 长度(列表) 并且 列表[i] > 0` 就会越界。
2. **`尝试/接住` 用显式 `error` 通道实现**：`抛出("...")` 返回一个 `*卅Error`；内部错误（类型错、除零、索引越界、名字未定义）都是同一个类型。这样"接住一切"的语义自然成立，且不需要额外的错误传播机制。
3. **`runSignal` 独立于 `卅Error`**：它可以在任何层的 `execBlock` 里穿过，但**不能被 `尝试/接住` 捕获**（`Try` 分支里先判断 `*runSignal` 再判断 `*卅Error`），语义正确——`返回` 写在 `尝试` 块里会正常返回，不执行 `接住`（规范 5.9）。
4. **循环变量的作用域**：`for` **不**新建作用域，循环变量直接写进当前作用域，所以循环结束后它**仍然存在**、值是最后一轮的值（规范 5.9、示例 `print(i) # 3`）。这与旧版本文档的写法相反，也是本次改写对齐规范的修正之一。
5. **块不建作用域**：`如果`/`当`/`遍历`/`尝试` 直接复用当前 `env`，块内赋值的变量在块结束后可见（规范 5.3 第 2 条）。
6. **`UserFunc` 保存 `Closure` + `Params` + `Body`**，调用时新建 `Environment(parent=Closure, name="函数 X 里")`，绑定参数后检查形参数量与实参数量，给出教学化提示（规范 7.2 示例 10）。
7. **列表/字典按引用传递**：`ListValue`/`DictValue` 用指针，`动物["饥饿"] = ...` 修改的是共享对象本身，调用者看得见（规范 5.3、8.2 示例能工作的原因）。数、文本、布尔、空值是不可变值类型，对它们"修改"只能是重新赋值。

### 5.4 内置函数注册表（29 个，与规范 6.2 逐行对应）

```go
// internal/builtins/registry.go
package builtins

// Param 描述一个命名参数（规范 6.1：参数名同样中英双名）。
type Param struct {
	CN       string // 中文名，如 "结尾"
	EN       string // 英文名，如 "end"
	Default  Value  // 省略时的默认值（nil 表示必填）
}

// Builtin 是一个内置函数的完整描述。一个实现可以挂多个名字（中英双名）。
type Builtin struct {
	Names    []string // 主要名字（含别名），如 {"从a到b", "range_to"}
	Aliases  []string // 额外等价别名，如 {"文本转数", "str_to_num"}
	MinArgs  int
	MaxArgs  int      // -1 表示不限
	Params   []Param  // 允许的命名参数
	DocCN    string   // 中文说明：帮助(...) 直接返回它，文档与实现同源
	Fn       NativeImpl
}

// NativeImpl 是内置函数实现体。pos 是调用点，用于错误定位。
// 约定：实现体只允许返回 *卅Error 或 nil，绝不 panic、绝不漏出宿主错误。
type NativeImpl func(in *Interpreter, args []Value, kw map[string]Value, pos ast.Pos) (Value, error)

// Registry 是全局唯一的注册表。注册在 init 阶段完成，运行期只读。
type Registry struct {
	byName map[string]*Builtin
}

var Default = &Registry{byName: make(map[string]*Builtin, 40)}

// Register 注册一个内置函数；重名直接 panic —— 这是程序员错误，不是用户错误，
// 应该在启动自检时立刻暴露（8.5 的"注册表自检"）。
func (r *Registry) Register(b *Builtin) {
	for _, name := range append(append([]string{}, b.Names...), b.Aliases...) {
		if prev, dup := r.byName[name]; dup {
			panic("内置函数重名: " + name + "（已被 " + prev.Names[0] + " 占用）")
		}
		r.byName[name] = b
	}
}

func (r *Registry) Lookup(name string) (*Builtin, bool) {
	b, ok := r.byName[name]
	return b, ok
}

// Names 返回全部可见名字（含别名），供拼写建议与"数量 ≤30"断言使用。
func (r *Registry) Names() []string {
	out := make([]string, 0, len(r.byName))
	for n := range r.byName {
		out = append(out, n)
	}
	sort.Strings(out) // ★ 排序：快照测试与建议列表都要求确定性输出
	return out
}

// Count 是"函数个数"（别名不重复计数），用于断言 ≤ 30。
func (r *Registry) Count() int {
	seen := map[*Builtin]bool{}
	for _, b := range r.byName {
		seen[b] = true
	}
	return len(seen)
}
```

// internal/builtins/core.go（节选：两个最能说明"语义出口"的函数）
package builtins

// biPrint：结尾 的默认值来自 Param；参数类型校验在注册表层统一做。
func biPrint(in *Interpreter, args []Value, kw map[string]Value, pos ast.Pos) (Value, error) {
	ending, err := in.KwText(kw, "结尾", "\n", pos)
	if err != nil {
		return nil, err
	}
	// ★ 与字符串插值共用 FormatValue：保证 print(10/3) 与 "{10/3}" 显示一致。
	if _, err := io.WriteString(in.Stdout(), FormatValue(args[0])+ending); err != nil {
		return nil, in.WrapIOError(err, pos, "写屏幕时出错")
	}
	return NullValue{}, nil
}

// biRangeTo：生成结果是一个**真实列表**（不是惰性对象），可以 print 出来（D7）。
func biRangeTo(in *Interpreter, args []Value, kw map[string]Value, pos ast.Pos) (Value, error) {
	a, err := in.AsNumber(args[0], "从a到b 的第 1 个参数", pos)
	if err != nil {
		return nil, err
	}
	b, err := in.AsNumber(args[1], "从a到b 的第 2 个参数", pos)
	if err != nil {
		return nil, err
	}
	step, err := in.KwNumber(kw, "步长", NewNumberInt64(1), pos)
	if err != nil {
		return nil, err
	}
	if step.IsZero() {
		return nil, in.errf(diag.CodeBadStep, pos, "从a到b 的步长不能是 0", nil)
	}
	out := &ListValue{}
	cur := a
	for {
		if step.Sign() > 0 && cur.Rat().Cmp(b.Rat()) >= 0 {
			break
		}
		if step.Sign() < 0 && cur.Rat().Cmp(b.Rat()) <= 0 {
			break // 方向与步长不符得空列表，不报错（规范 S15）
		}
		out.Elems = append(out.Elems, cur)
		next, err := Arith(ast.OpAdd, cur, step, pos)
		if err != nil {
			return nil, err
		}
		cur = next
	}
	return out, nil
}

**注册表的实现要点**

- **一个实现挂多个名字**：`打印`/`print` 指向同一个 `*Builtin`，报错时把别名一起列出；不要写两份实现。
- **参数校验在注册表层统一做**（`in.call` 里先按 `MinArgs`/`MaxArgs` 检查，再按 `Params` 把命名参数绑成"位置参数 + 默认值"），错误消息由 `internal/diag` 统一生成：
  - 参数太少 → `函数 "从a到b" 需要至少 2 个参数，你给了 1 个。试试 从a到b(1, 10)？`
  - 多余的命名参数 → `函数 "print/打印" 没有叫 "结尾符" 的参数。你是不是想写 "结尾"？`（走 6.4 的拼写建议管线）
- **文档内嵌**：`DocCN` 让 `帮助("从a到b")` 这种可选的调试内置函数零成本实现，也让文档与实现对得上。v1 不把 `帮助` 计入 29 个（它属于调试开关，见 8.5）。
- **数量断言**：`go test` 里有一条 `TestBuiltinCount`：`if n := builtins.Default.Count(); n > 30 { t.Fatalf(...) }`，把简报 D9 的硬约束变成可执行测试；另有一条 `TestEveryBuiltinHasChineseName` 断言每个 `Builtin` 至少有一个中文名。
- **纯 Go 标准库实现**：`读取文件` 用 `os.ReadFile` + `utf8.Valid` 校验；错误一律转成 `*卅Error`，绝不把 `*os.PathError` 直接漏给用户（新手看不懂）。消息形如：`第 3 行：读不到文件 "故事.txt"。检查文件名有没有写错，或者文件在不在这个文件夹里。`
- **`print` 的命名参数**是简报示例 `print("...", 结尾: "  ")` 的直接要求；`结尾` 为 `""` 时表示"不换行"，实现上就是拼接空串。
- **路径以被运行脚本所在目录为基准**（不是进程 cwd），否则 `sahou run sub/a.saho` 会找不到同目录文件——这是新手高频坑。实现上 `Interpreter` 持有 `scriptDir` 字段，`file.go` 里的三个函数统一过一层 `resolvePath()`。
- **内置函数不超过 30 个**（D9 硬约束）：v1 实为 29 个，留 1 个名额余量（规范 6.2 数量说明），`文本转数/str_to_num` 是别名不计数。

**成员函数白名单**（规范 6.4，不占 30 个名额）。`Attr` 节点先查白名单、再回退到字典字段访问：

		// ★ 字典优先按键解释：动物.名字 ≡ 动物["名字"]（规范 5.7）。
		if v, found := d.Get(TextValue(name)); found {

		}

			return &BoundMethod{Recv: d, Impl: impl, Name: name, Pos: pos}, nil

		return nil, in.errf(diag.CodeMissingKey, pos,

### 5.5 数值、真值、相等与显示：唯一语义出口

规范把这几件事分散写在各节，实现必须把它们**收拢到少数几个函数**，否则"只有一个数类型"的承诺会从内部裂开：

```go
// internal/interp/value.go（语义出口）
package interp

// IsTruthy 实现规范 5.4：只有 6 个值是假，其余全真。
func (in *Interpreter) IsTruthy(v Value) bool {
	switch x := v.(type) {
	case BoolValue:
		return bool(x)
	case NullValue:
		return false
	case *Number:
		return !x.IsZero() // 0 与 0.0 是同一个数
	case TextValue:
		return len([]rune(string(x))) > 0
	case *ListValue:
		return len(x.Elems) > 0
	case *DictValue:
		return len(x.entries) > 0
	default: // 函数值等一律为真
		return true
	}
}

// EqualValues 实现规范 5.10：深度相等；跨类型 == 返回假而不报错（S7）。
func (in *Interpreter) EqualValues(a, b Value, seen map[[2]uintptr]bool) (bool, error) {
	switch x := a.(type) {
	case *Number:
		y, ok := b.(*Number)
		return ok && EqualNumber(x, y), nil
	case TextValue:
		y, ok := b.(TextValue)
		return ok && x == y, nil
	case BoolValue:
		y, ok := b.(BoolValue)
		return ok && x == y, nil
	case NullValue:
		_, ok := b.(NullValue)
		return ok, nil
	case *ListValue:
		y, ok := b.(*ListValue)
		if !ok {
			return false, nil
		}
		if x == y {
			return true, nil
		}
		if seen[[2]uintptr{ptr(x), ptr(y)}] {
			return false, in.errf(diag.CodeCyclicCompare, ast.Pos{}, "自引用的容器不能比较（会无限递归）", nil)
		}
		seen[[2]uintptr{ptr(x), ptr(y)}] = true
		if len(x.Elems) != len(y.Elems) {
			return false, nil
		}
		for i := range x.Elems {
			eq, err := in.EqualValues(x.Elems[i], y.Elems[i], seen)
			if err != nil || !eq {
				return false, err
			}
		}
		return true, nil
	case *DictValue:
		y, ok := b.(*DictValue)
		if !ok {
			return false, nil
		}
		if len(x.entries) != len(y.entries) {
			return false, nil // 键的顺序不影响相等（规范 5.10）
		}
		for _, e := range x.entries {
			ov, found := y.Get(e.Key)
			if !found {
				return false, nil
			}
			eq, err := in.EqualValues(e.Value, ov, seen)
			if err != nil || !eq {
				return false, err
			}
		}
		return true, nil
	}
	return false, nil // 跨类型（或函数值）比较：== 得假，不报错
}

// ptr 把容器指针转成 uintptr，用于"循环引用"检测的去重集合键。
// 只对 *ListValue / *DictValue 调用；数、文本、布尔、空值是不可变值，不需要检测。
func ptr(v any) uintptr {
	switch x := v.(type) {
	case *ListValue:
		return reflect.ValueOf(x).Pointer()
	case *DictValue:
		return reflect.ValueOf(x).Pointer()
	}
	return 0
}

// FormatValue 是 文本()/插值/打印 的唯一转换出口（规范 5.10）。
// 递归深度上限与 32 层，自引用容器输出 <循环引用>，绝不死循环（S11）。
func FormatValue(v Value) string { return formatValue(v, 0, map[uintptr]bool{}) }

func formatValue(v Value, depth int, seen map[uintptr]bool) string {
	if depth > 32 {
		return "<循环引用>"
	}
	switch x := v.(type) {
	case *Number:
		return FormatNumber(x) // 唯一的数值显示出口
	case TextValue:
		return string(x) // 不带引号
	case BoolValue:
		if bool(x) {
			return "真"
		}
		return "假"
	case NullValue:
		return "空值"
	case *ListValue:
		if seen[ptr(x)] {
			return "<循环引用>"
		}
		seen[ptr(x)] = true
		defer delete(seen, ptr(x))
		parts := make([]string, 0, len(x.Elems))
		for _, e := range x.Elems {
			parts = append(parts, formatValue(e, depth+1, seen))
		}
		return "[" + strings.Join(parts, ", ") + "]"
	case *DictValue:
		if seen[ptr(x)] {
			return "<循环引用>"
		}
		seen[ptr(x)] = true
		defer delete(seen, ptr(x))
		parts := make([]string, 0, len(x.entries))
		for _, e := range x.entries { // 保持插入顺序（S10）
			parts = append(parts, formatValue(e.Key, depth+1, seen)+": "+formatValue(e.Value, depth+1, seen))
		}
		return "{" + strings.Join(parts, ", ") + "}"
	case *UserFunc:
		return "<函数 " + x.Name + ">"
	case *NativeFunc:
		return "<内置函数 " + x.Builtin.Names[0] + ">"
	}
	return "<未知值>"
}
```

// internal/diag/render.go
package diag

// Renderer 负责把诊断变成人类可读文本。分离出来的好处：
// 快照测试可以只渲染不染色（CI 里没有 TTY），本地运行可以加颜色。
type Renderer struct {
	Sources  map[string][]string // 文件名 -> 源码行（1 起）
	Color    bool                // 是否启用 ANSI 颜色
	MaxItems int                 // 默认 10（6.3 规则 5）
}

func (r *Renderer) RenderAll(file string, ds []Diagnostic, w io.Writer) {
	shown := ds
	if len(shown) > r.MaxItems {
		shown = shown[:r.MaxItems]
	}
	for i, d := range shown {
		if i > 0 {
			fmt.Fprintln(w)
		}
		r.RenderOne(file, d, w)
	}
	if rest := len(ds) - len(shown); rest > 0 {
		fmt.Fprintf(w, "\n还有 %d 个问题没显示。\n", rest)
	}
}

func (r *Renderer) RenderOne(file string, d Diagnostic, w io.Writer) {
	// 1. 位置 + 中文主消息（中文优先）
	fmt.Fprintf(w, "第 %d 行 第 %d 列：%s\n", d.Pos.Line, d.Pos.Col, d.MessageCN)
	// 2. 英文副消息另起一行加 [EN] 前缀
	if d.MessageEN != "" {
		fmt.Fprintf(w, "  [EN] %s\n", d.MessageEN)
	}
	// 3. 回显出错那一行源码，行号右对齐
	lines := r.Sources[file]
	if d.Pos.Line-1 < len(lines) {
		src := lines[d.Pos.Line-1]
		fmt.Fprintf(w, "\n  %d | %s\n", d.Pos.Line, src)
		// 4. 用 ^ 与 ~ 精确指出范围（中文按列宽 2 计，画得更准）
		fmt.Fprintf(w, "    | %s%s\n", caretPadding(src, d.Pos.Col), strings.Repeat("~", max(1, d.Length)))
	}
	// 5. 建议与教学化补充
	if d.Suggestion != "" {
		fmt.Fprintf(w, "  %s\n", d.Suggestion)
	}
	if d.HelpCN != "" {
		fmt.Fprintf(w, "  %s\n", d.HelpCN)
	}
}
```

渲染规则（与规范 7.1 的硬性规则一一对应）：

1. 第一行给**位置**（行 + 列），中文优先，英文另起一行加 `[EN]` 前缀；
2. 然后回显**出错那一行源码**，行号右对齐；
3. 再用 `^` 与 `~` 精确指出范围（`Diagnostic.Length` 控制长度，中文按列宽 2 计算更美观）；
4. 最后输出建议（`你是不是想写 ……`），缩进两格；
5. 多个诊断之间空一行，最多显示前 10 条，末尾提示 `还有 N 个问题没显示`；
6. **缩进与空格问题永不报错**（规范 7.1 第 7 条）：词法器不产生缩进 token，渲染层也没有任何"缩进检查"代码——这是一条"用不写代码来保证"的规则。

### 6.4 "你是不是想写" 的实现思路

三层候选来源 + 编辑距离排序 + 阈值过滤：

```go
// internal/diag/suggest.go
package diag

// EditDistance 是带提前退出的 Levenshtein 距离（超过 limit 直接返回 limit+1）。
func EditDistance(a, b string, limit int) int {
	ra, rb := []rune(a), []rune(b)
	if abs(len(ra)-len(rb)) > limit {
		return limit + 1
	}
	prev := make([]int, len(rb)+1)
	for j := range prev {
		prev[j] = j
	}
	for i := 1; i <= len(ra); i++ {
		cur := make([]int, len(rb)+1)
		cur[0] = i
		best := cur[0]
		for j := 1; j <= len(rb); j++ {
			cost := 1
			if ra[i-1] == rb[j-1] {
				cost = 0
			}
			cur[j] = min3(prev[j]+1, cur[j-1]+1, prev[j-1]+cost)
			if cur[j] < best {
				best = cur[j]
			}
		}
		if best > limit { // 整行都超限：提前退出，省时间
			return limit + 1
		}
		prev = cur
	}
	return prev[len(rb)]
}

// SuggestName 按"距离小 -> 同语言偏好 -> 名字短"排序，返回最合适的一个。
// 宁缺勿滥：找不到足够近的候选时返回 ""（调用方据此**不输出**建议半句）。
func SuggestName(typo string, candidates map[string]struct{}) string {
	type scored struct {
		dist     int
		otherLang int
		length   int
		name     string
	}
	var list []scored
	for cand := range candidates {
		if cand == typo {
			continue
		}
		d := EditDistance(typo, cand, 2)
		if d > 2 {
			continue
		}
		other := 1
		if sameScript(typo, cand) {
			other = 0 // 同语言加分：中文 typo 优先推荐中文候选（英文同理）
		}
		list = append(list, scored{d, other, len([]rune(cand)), cand})
	}
	if len(list) == 0 {
		return ""
	}
	sort.Slice(list, func(i, j int) bool {
		if list[i].dist != list[j].dist {
			return list[i].dist < list[j].dist
		}
		if list[i].otherLang != list[j].otherLang {
			return list[i].otherLang < list[j].otherLang
		}
		if list[i].length != list[j].length {
			return list[i].length < list[j].length
		}
		return list[i].name < list[j].name // ★ 兜底按字典序：保证建议稳定可快照
	})
	return list[0].name
}

// sameScript 判断两个名字是否同属"中日韩"或"拉丁"体系。
func sameScript(a, b string) bool { return hasCJK(a) == hasCJK(b) }

func hasCJK(s string) bool {
	for _, r := range s {
		if r >= 0x4E00 && r <= 0x9FFF {
			return true
		}
	}
	return false
}
```

**三类触发场景与专门的建议器**

| 场景 | 候选集合 | 建议文案 |
|---|---|---|
| 名字未定义（`CodeUndefinedName`） | 当前作用域可见变量名 + 所有内置函数别名 | `你是不是想写 "name"？` |
| 内置函数名/关键字拼错 | `builtins.Default.Names()` + 关键字原文表（含中文） | `你是不是想写 "从a到b"？` |
| 命名参数名错（`print(..., 结尾符: "")`） | 该内置函数的 `Params` 名（中英都算） | `你是不是想写 "结尾"？` |
| 类型错（`"abc" + 1`） | 不需要编辑距离，走**规则表** | `你可能是想把数字变成文本，试试 文本(数量)？` |
| 括号不匹配 | 栈式扫描，记录未闭合 `(` 的位置 | `第 3 行 第 12 列的 ( 没有找到配对的 )。` |
| 全角标点 | 不需要编辑距离，走 `fullwidthPairs` 映射表 | `这里应该是半角逗号 ","，你打成了中文逗号 "，"。` |

**关键约束**（写进测试，8.1）：建议必须**宁缺勿滥**——距离阈值 2（中文关键字与非常短的标识符可以放宽到 1），候选为空或都不够近时**不要输出"你是不是想写"这半句**，绝不输出荒谬建议（这是新手信任感的关键）。`TestSuggestNameNoFalsePositive` 专门喂一批"毫无关系的名字"断言返回空串。

### 6.5 运行时错误的调用栈回溯

新手最难自查的错误是"在很深的地方出错了"（例如 `喂食(小猫)` 里的字典键写错）。因此 `*卅Error` 在向上传播时**逐层追加帧信息**：

```
第 5 行 第 9 列：字典里没有 "饥饿度" 这个键，它现在只有 ["名字", "饥饿"]。

  5 |     动物["饥饿度"] = 10
    |          ^~~~~~~~~

调用过程（从最近的一次调用看起）：
  函数 喂食(动物)      第 5 行
  全局                 第 12 行
```

实现：`call` 里用一个 `defer` 捕获返回的 `*卅Error` 并追加帧，只保留最近 8 帧，避免刷屏：

```go
// internal/interp/call.go（节选）
func (in *Interpreter) callUser(fn *UserFunc, args []Value, kwargs map[string]Value, pos ast.Pos) (Value, error) {
	if len(args)+len(kwargs) != len(fn.Params) {
		// 参数个数不符：给"它的参数是 a, b"的提示（规范 7.2 示例 10）
		return nil, in.argf(fn.Name, len(fn.Params), len(args)+len(kwargs), fn.Params, pos)
	}
	if in.depth >= in.maxDepth {
		return nil, in.errf(diag.CodeRecursionTooDeep, pos,
			"函数 "+quote(fn.Name)+" 调用太深了", diag.Args{"名字": fn.Name, "上限": itoa(in.maxDepth)})
	}
	in.depth++
	in.frames = append(in.frames, Frame{FuncName: fn.Name, Line: pos.Line})
	defer func() { in.depth--; in.frames = in.frames[:len(in.frames)-1] }()

	local := NewEnvironment(fn.Closure, "函数 "+fn.Name+" 里") // ★ 父环境是定义处（词法作用域）
	for i, name := range fn.Params {
		local.Define(name, args[i])
	}
	err := in.execBlock(fn.Body, local)
	if rs, ok := err.(*runSignal); ok {
		return rs.value, nil // 正常返回：信号在这里被消化
	}
	if se, ok := err.(*卅Error); ok {
		se.frames = append(se.frames, Frame{FuncName: fn.Name, Line: pos.Line}) // ★ 逐层追加
		if len(se.frames) > 8 {
			se.frames = se.frames[len(se.frames)-8:]
		}
	}
	return nil, err
}
```

### 6.6 退出码与输出通道约定

| 情形 | stdout | stderr | 退出码 |
|---|---|---|---|
| 正常运行 | 程序输出 | 空 | 0 |
| 有诊断但修复后仍运行（如重复键警告） | 程序输出 | 诊断 | 0 |
| 词法/语法错误 | 空（不执行） | 诊断 | 1 |
| 未捕获的运行时错误 | 已产生的输出 | 诊断 + 回溯 | 1 |
| 文件不存在 / 用法错误 | 空 | 诊断 | 2 |

**原则**：程序输出只走 stdout，诊断只走 stderr——这样 `sahou run x.saho > out.txt` 的输出干净可对比（快照测试与示例回归都依赖这一点）。Go 版把这条约定**落实在类型上**：`Interpreter.stdout` 与 `Interpreter.stderr` 是两个独立注入的 `io.Writer`，`diag.Renderer` 只持有 stderr，任何内置函数都拿不到 stderr。

```go
// cmd/卅/main.go（节选）
func main() {
	// ★ 兜底：任何未预期的 panic 都翻译成一条"内部错误"诊断，
	//   绝不让用户看到 Go 的 panic 堆栈（规范 7.1 第 5 条：不泄露实现语言）。
	defer func() {
		if r := recover(); r != nil {
			fmt.Fprintf(os.Stderr, "卅 内部出错了（这是解释器的 bug，不是你的代码的问题）：%v\n", r)
			os.Exit(70)
		}
	}()
	os.Exit(run(os.Args[1:], os.Stdout, os.Stderr, os.Stdin))
}
```

## 7. 标准库（内置函数）实现要点

简报 D9 的约束是**硬约束**：不超过 30 个、全部小写蛇形（英文名）、中英双名、v1 全局可见、没有模块系统。规范 6.2 已经给出了完整的 29 个函数清单，本节只讲实现要点。

1. **全部实现在 `internal/builtins` 内，只用 Go 标准库**，`go.mod` 零 `require`——保证"编译出来就能跑"。
2. **别名等价**：注册时给出 `Names`/`Aliases`，注册表把多个名字指向同一实现；`Default.Count() <= 30` 与"每个 Builtin 至少一个中文名"写进 `go test` 断言。
3. **错误一律转 `*卅Error`**，并带上 `pos`（调用点位置）与 `suggestion`；绝不让 Go 的 `io.EOF`、`*os.PathError`、`strconv.NumError` 冒到用户面前。
4. **参数语义写进 `DocCN`**，与文档同源；`帮助/help`（调试用，不计入 29）直接返回它。
5. **典型函数要点**（清单与命名以规范 6.2 为准，此处只列实现要点）：

| # | 函数 | 实现要点 |
|---|---|---|
| 1 | `打印/print` | `结尾` 命名参数（默认 `"\n"`）；值经 `FormatValue` 转文本，与插值共用一套转换，保证 `print(10/3)` 与 `"{10/3}"` 显示一致；UTF-8 直接写 `io.Writer` |
| 2 | `输入/input` | 提示经 `FormatValue`；用 `bufio.Reader.ReadString('\n')`；**剥掉行尾 `\r\n`/`\n`**；EOF 时返回空文本而不是报错 |
| 3 | `数/num`（别名 `文本转数/str_to_num`） | 走 `NewNumberFromDecimal`；`数("九十五")` 报 `文本 "九十五" 不是数字，转不成数。你是不是想写 95？`（中文数字→阿拉伯数字的候选建议） |
| 4 | `文本/str` | 直接 `FormatValue`，与插值同源 |
| 5 | `列表/list` | 无参得空列表；`列表(列表)` 浅拷贝；`列表(字典)` 得键的列表（按插入顺序） |
| 6 | `字典/dict` | 无参得空字典；入参为 `[[键, 值], ...]` 配对列表；配对数不是 2 报错 |
| 7 | `从a到b/range_to` | 返回**真实列表**；步长 0 报错；方向不符得空列表（S15）；全程 `big.Rat` 精确递增 |
| 8 | `长度/len` | 列表 `len(Elems)`、文本 `len([]rune(s))`、字典 `len(entries)`；对数/布尔/空值报错 |
| 9 | `取/slice` | 半开区间 `[起, 止)`；`止` 省略；`步长` 支持；索引与边界检查集中在 `toIndexValue` 一处 |
| 10 | `抛出/throw` | 返回 `*卅Error{msg: FormatValue(消息)}`；在 `尝试/接住` 外调用会终止程序（D8） |
| 11 | `类型/type_of` | 返回 `Value.TypeName()`：`"number"`、`"string"`、`"list"`、`"dict"`、`"bool"`、`"null"`、`"function"` |
| 12 | `包含/contains` | 列表看深度相等、字典看是否含键（键归一化后查 `index`）、文本看子串（`strings.Contains`） |
| 13 | `求和/sum` | 累加必须走 `Arith(OpAdd)`；空列表得 `0`；非数元素报错并**指出第一个出问题的位置** |
| 14/15 | `最大值/max`、`最小值/min` | 空列表报错；元素必须同为数或同为文本；比较走 `CmpNumber`/字符串比较；混合类型报"不能比较" |
| 16 | `排序/sorted` | 复制一份再 `sort.SliceStable`；`降序: 真` 反转；混合类型报错 |
| 17 | `反转/reversed` | 列表与文本都支持，返回**新**值，不改原值 |
| 18 | `连接/join` | 元素经 `FormatValue`；`分隔` 默认 `""` |
| 19 | `分割/split` | `strings.Split`；分隔符不出现在结果里 |
| 20 | `替换/replace` | `strings.ReplaceAll`；`旧` 为空文本时报错（会无限匹配） |
| 21 | `修剪/trim` | `strings.TrimSpace` |
| 22/23 | `转大写/upper`、`转小写/lower` | `strings.ToUpper/ToLower`；非字母原样保留 |
| 24 | `绝对值/abs` | `new(big.Rat).Abs` |
| 25 | `平方根/sqrt` | 用 `big.Float.Sqrt` 取高精度，再 `NewNumberFromBigFloat`；**负数报错**并提示"负数没有实数平方根" |
| 26 | `四舍五入/round` | `小数位` 为负时对整数位取整；用定点十进制缩放 + half-up，与 `FormatNumber` 的舍入规则一致 |
| 27 | `读取文件/read_file` | `os.ReadFile` + `utf8.Valid` 校验；路径相对**脚本目录**；错误转成"读不到文件 …" |
| 28 | `写入文件/write_file` | `os.WriteFile(..., 0o644)`；内容经 `FormatValue`；路径规则同上 |
| 29 | `文件存在/file_exists` | `os.Stat`；文件或目录都返回真；**不报错**，只回真假 |

6. **`IsTruthy`/`FormatValue`/`IsNumber`/`Arith` 是唯一语义出口**：内置函数必须复用它们，不许自己写判断，否则"只有一个数类型"的承诺会从内部裂开。这条纪律在 code review 里查，也在 8.1 的性质测试里被间接断言。
7. **`平方根` 是唯一"不得不经过浮点"的函数**：它先用 `big.Float` 以 256 位精度算，再转回 `*big.Rat`。结果是"256 位精度的有理数"，显示时仍收敛到 15 位有效数字——对用户而言仍是"一种数、一个显示规则"。

## 8. 测试策略

测试是这门语言**报错质量**的保障机制。目标：任何一次改动导致"某条报错文案变差"或"某个示例跑不出原结果"，CI 必须拦住。Go 的 `testing` 标准库足够完成全部工作，**零第三方测试依赖**（与"零依赖部署"保持一致）。

| 引用语义 | `internal/interp/scope_test.go` | 列表/字典按引用传递；整体重新赋值不影响调用者 | 规范 8.2 示例的 `喂食(小猫)` |
| 分层方向 | `internal/arch/imports_test.go` | 读各包 import 清单，断言无反向依赖（1.1） | `interp` 不 import `parser`/`lexer` |

**纪律**：

- 所有 `eval` 测试都通过一个 `runSource(t, code) RunResult` 辅助函数（内部串起 Lexer→Parser→Interpreter 并捕获诊断），保证测试与真实执行路径一致，而不是直接调内部方法；
- 表驱动（table-driven）是 Go 的默认写法，错误路径也必须进表，不能只测 happy path；
- 测试用 `t.Parallel()`，`RunResult.ScriptDir` 指向 `t.TempDir()`，避免测试之间互相污染文件。

```go
// internal/interp/eval_test.go（节选，展示 RunResult 的形状）
type RunResult struct {
	Stdout   string
	Stderr   string
	Value    Value
	Diags    []diag.Diagnostic
	ExitCode int
}

func runSource(t *testing.T, code string) RunResult {
	t.Helper()
	toks, lexDiags := lexer.New([]byte(code), "<测试>", 1, 1).Scan()
	prog, parseDiags := parser.New(toks, "<测试>").ParseProgram()
	var out, errBuf bytes.Buffer
	in := interp.New(&out, &errBuf, strings.NewReader(""), builtins.Default)
	in.ExecProgram(prog)
	return RunResult{
		Stdout: out.String(), Stderr: errBuf.String(),
		Diags: append(lexDiags, parseDiags...), ExitCode: in.ExitCode(),
	}
}

func TestNumberSemantics(t *testing.T) {

### 8.2 快照测试（golden / 回归护栏）

快照测试是防止"文案悄悄变差"的唯一有效手段。Go 的标准做法是 `testdata/` + `-update`：

```go
// internal/parser/snapshot_test.go（节选）
import (
	"flag"
	"os"
	"path/filepath"
	"strings"
	"testing"
)

var update = flag.Bool("update", false, "重新生成全部快照")

func TestASTSnapshots(t *testing.T) {
	files, _ := filepath.Glob(filepath.Join("..", "..", "tests", "examples", "*.saho"))
	for _, f := range files {
		name := strings.TrimSuffix(filepath.Base(f), ".saho")
		t.Run(name, func(t *testing.T) {
			got := ast.Dump(parseFile(t, f)) // 缩进良好的 AST 文本，字段顺序固定
			golden := filepath.Join("..", "..", "tests", "snapshots", "ast", name+".txt")
			if *update {
				os.WriteFile(golden, []byte(got), 0o644)
				return
			}
			want, err := os.ReadFile(golden)
			if err != nil || string(want) != got {
				t.Errorf("AST 快照不一致：%s\n--- got ---\n%s", golden, got)
			}
		})
	}
}
```

1. **AST 快照**：对 `tests/examples/*.saho` 生成缩进良好的 AST 文本，存进 `tests/snapshots/ast/*.txt`。任何解析器改动导致的 AST 变化都会显式暴露在 diff 里。
2. **诊断快照**：把**一整个 `tests/errors/*.saho` 目录**的报错输出（含行号、`^` 指示、双语、建议）完整存成 `tests/snapshots/diag/*.txt`。这个目录**故意装满错误程序**：缺 `完毕`、`完毕` 多余、中文关键字打错、字符串未闭合、`如果` 写成 `如何`、`从a到c`、`print(..., 结尾符: "")`、全角逗号、比较连写、负下标……
3. 更新流程：`go test ./... -run Snapshot -update` 更新，但 diff 必须在 code review 中被**逐行阅读**——快照测试的价值全在于"改动是被人看见并同意的"。
4. **脆弱点规避**：快照里不许出现绝对路径、时间戳、内存地址、`map` 迭代顺序不稳的内容。Go 的 `map` 迭代顺序是**故意随机**的，因此：AST 快照的字段顺序由 `ast.Dump` 手写固定；诊断列表在渲染前按 `(Line, Col, Code)` 排序；`Registry.Names()` 内部 `sort.Strings`；字典的 `entries` 切片天然有序。这条纪律在 Go 里比 Python 更容易违反，必须有意识地处理。
5. **不染色**：快照测试里 `Renderer.Color = false`（CI 无 TTY），本地才开颜色。

### 8.3 示例程序回归（端到端）

- `tests/examples/` 下每个 `.saho` 配一个同名 `.out`（期望 stdout）与可选 `.in`（stdin）。测试逐一运行并比较 stdout，**同时断言退出码为 0**。
- **简报第 3 节的三段示例必须逐字原样收录**（九九乘法表、字典代替对象、尝试/接住 与 抛出），作为最高优先级的验收标准；它们同时也是 02/03 文档的引用基准。

### 8.4 一致性测试（conformance）：`go test` + `tests/cases/*.saho` + `*.out` 快照

这是**本文最重要的测试设施**，也是 2.2 迁移路径的验收标准。语料库用 Go 的 `testing` 驱动，每个用例是**一对文件**：

```
tests/cases/
├─ case001_number_integer.saho        # 源码
├─ case001_number_integer.out         # 期望：stdout + 诊断 + 退出码（快照）
├─ case002_number_float_exact.saho
├─ case002_number_float_exact.out
├─ case017_missing_end.saho
├─ case017_missing_end.out            # 这个 .out 里就是完整的诊断文本（含行号与 ^ 指示）
└─ ...
```

`.out` 的格式是**自解释的**，用三个段标记，既方便人读也方便机读：

```
=== stdout ===
1×1=1
1×2=2  2×2=4
=== stderr ===
（空）
=== exit ===
0
```

驱动器只有 40 行，但它同时锁住了"输出""诊断""退出码"三件事：

```go
// tests/conformance_test.go
package tests

import (
	"flag"
	"os"
	"path/filepath"
	"strings"
	"testing"
)

var update = flag.Bool("update", false, "重新生成全部快照（包括 conformance 的 .out）")

// runFile 走的是与真实 CLI 完全相同的路径：读文件 -> Lexer -> Parser
// -> Interpreter -> Renderer，然后把三样东西拼成快照文本。
func runFile(t *testing.T, path string) string {
	t.Helper()
	src, err := os.ReadFile(path)
	if err != nil {
		t.Fatalf("读不到 %s: %v", path, err)
	}
	var stdout, stderr bytes.Buffer
	code := 卅.Run(src, path, &stdout, &stderr, bytes.NewReader(nil))
	var sb strings.Builder
	sb.WriteString("=== stdout ===\n")
	sb.WriteString(stdout.String())
	sb.WriteString("=== stderr ===\n")
	sb.WriteString(stderr.String())
	sb.WriteString("=== exit ===\n")
	sb.WriteString(strconv.Itoa(code) + "\n")
	return sb.String()
}

// TestConformance 跑通 tests/cases 下的全部语料。
// 语料是**语言行为的唯一契约**：任何实现（Go VM、Rust 版、未来的自举版）
// 只要跑通这里全部用例，就是"同一个 卅"。
func TestConformance(t *testing.T) {
	cases, err := filepath.Glob("cases/*.saho")
	if err != nil || len(cases) == 0 {
		t.Fatalf("没有找到任何 conformance 语料：%v", err)
	}
	for _, src := range cases {
		src := src
		t.Run(filepath.Base(src), func(t *testing.T) {
			t.Parallel()
			got := runFile(t, src)
			golden := strings.TrimSuffix(src, ".saho") + ".out"
			if *update {
				if err := os.WriteFile(golden, []byte(got), 0o644); err != nil {
					t.Fatal(err)
				}
				return
			}
			want, err := os.ReadFile(golden)
			if err != nil {
				t.Fatalf("缺少期望输出 %s（第一次生成请跑 go test ./tests -run Conformance -update）", golden)
			}
			// ★ 只用标准库比较：go.mod 里零第三方依赖是硬约束（2.1），
			//   所以这里不引入 go-cmp；差异按行打印，够读就行。
			if string(want) != got {
				t.Errorf("%s 与快照不一致\n%s", golden, lineDiff(string(want), got))
			}
		})
	}
}

// lineDiff 打印第一个不同的行以及前后文，避免把整份输出刷进日志。
func lineDiff(want, got string) string {
	w, g := strings.Split(want, "\n"), strings.Split(got, "\n")
	for i := 0; i < len(w) || i < len(g); i++ {
		var a, b string
		if i < len(w) {
			a = w[i]
		}
		if i < len(g) {
			b = g[i]
		}
		if a != b {
			return "第 " + strconv.Itoa(i+1) + " 行不同：\n  want: " + strconv.Quote(a) + "\n   got: " + strconv.Quote(b)
		}
	}
	return "（内容相同，仅尾部换行不同）"
}
```

**语料编写规则**：

1. **只依赖语言行为，不依赖实现语言**：语料里不许出现 "Go"、"golang"、"Python"、"py" 字样，也不许断言内部数据结构。断言只允许是：stdout 字节、stderr 文案、退出码。
2. **每个用例只考一件事**，文件名要能读懂考什么：`case003_div_exact_keeps_int.saho`、`case004_float_exact_010_020.saho`、`case011_scope_shadowing.saho`、`case012_for_var_survives.saho`、`case016_interp_nested_quote.saho`。
3. **覆盖矩阵**（最低要求，随语言演进而扩充）：
   - **数值语义**：整数精确、`10 == 10.0`、`4/2` 显示 `2`、`10/3` 显示 15 位、`0.1+0.2==0.3`、`(10/3)*3==10`、取余符号、除零报错、取余零报错、大整数（超出 `int64`，验证"任意精度天然成立"）；
   - **关键字**：18 对拼写的等价性（可与 8.3 的跨语言用例合并）、关键字不能作变量名；
   - **块与作用域**：块不建作用域、函数内遮蔽、`for` 循环变量在循环后仍存在、闭包读外层、递归与调用过深；
   - **控制流**：嵌套双层循环、`当` 循环、`又如` 多分支、布尔标志代替 `break`（规范 10 的写法）；
   - **容器**：列表/字典字面量、下标读写、成员函数（`添加`/`去重`/`删除`）、字典插入顺序、重复键警告；
   - **文本**：插值（含嵌套引号与嵌套花括号）、转义 `\{`、未知转义报错、`剪掉`/`分割`/`连接`/`替换`、全角标点专门报错；
   - **错误传播**：`抛出`、`接住` 绑定错误文本、`返回` 穿过 `尝试`、未接住错误的调用链、`接住` 块自己出错向外传播；
   - **内置函数边界**：参数个数不符、命名参数拼错、越界、负下标、`从a到b` 步长 0、空列表的 `最大值`、混合类型比较；
   - **报错文本**：规范 7.2 的 18 个示例**每个都要有一个用例**，逐字锁定文案。
4. **`退出码` 也进快照**：这样"哪一类错误应该退出 1、哪一类是 2"同样被锁住（6.6 的表）。
5. **发布门槛**：任何新实现（阶段 C 的字节码 VM、阶段 D 的 Rust 版、未来的自举版）以"**跑通全部 conformance 用例**"为发布门槛；Go 树遍历版是这套语料的**第一个实现**，它的输出就是基准。

**为什么这套设计比"只写单元测试"更值钱**：单元测试与实现绑定（测的是 `internal/interp` 的函数），而 conformance 语料与实现解耦（测的是"`.saho` 文件进去、字节出来"）。前者在换实现时全部作废，后者可以原封不动地跑在新实现上——这正是 2.2 迁移路径能成立的前提。

**与旧版本文档（Python 实现）的行为差异说明**（本次改写按规范对齐，均已在上文标注 ★）：

1. **块不再建立新作用域**：旧版给 `如果`/`当`/`遍历` 各建一层 `Environment`，与规范 5.3 第 2 条冲突。现改为直接复用当前作用域，于是"块内赋值的变量在块结束后依然存在"与"`for` 循环变量在循环后仍存在（规范 5.9 示例 `print(i) # 3`）"同时成立。
2. **函数内给外层名字赋值是遮蔽，不是改写外层**：旧版 `Environment.assign` 会沿链找到第一处已存在的名字并改它，与规范 5.3 第 5 条及示例（`计数 = 0` 后函数里 `计数 = 计数 + 99`，最终 `print(计数)` 得 `0`）冲突。现改为只写当前作用域。
3. **数值改为精确有理数**：旧版用 `int` + `float`，`0.1 + 0.2` 内部是 `0.30000000000000004`；现在内部是 `3/10`，`==` 比较也精确。
4. **`%` 与 `=>` 纳入实现**：旧版按简报猜测"取余未纳入"，规范 3.1/3.2 已明确纳入。
5. **比较不可连写成为硬检查**：旧版 `parse_comparison` 用的是 `while` 循环（等于允许连写并按左结合解析），规范 S5 明确要求报错并给改写建议。
