## 1. 版本路线图

### 1.1 四个阶段的目标与验收

**v1（已完成设计）：核心解释器**
Go 实现、树遍历求值（04 文档第 1 节流水线），只做"简单、正确、报错清楚"三件事。
验收基准是简报第 3 节的三段示例可运行、可被 AST 快照与报错快照固定。

**v1.1 后端：内置模块 `网络/net`**
目标：让 卅 程序能**在自己内部起一个 HTTP 服务**，也能**调用别人的 HTTP 接口**。
实现方式：模块系统 v2 尚未落地，因此 `网络` 以**内置模块**（预置命名空间）的形式提前提供。
验收：第 2.5 节的待办事项服务示例可运行，用 `curl` 完成"查、增、删"三件事。

**v1.5 前端：`卅->JavaScript` 转译器 + 内置模块 `页面/page`**
目标：让 卅 程序能写**浏览器里真的能跑**的页面（DOM 操作与事件响应）。
实现方式：**复用同一套 lexer/parser/AST**，只新增一个 JS 代码生成器（04 文档的分层铁律不变：代码生成器只读 AST，不回头改 AST、不读源码文本）。
验收：第 3.6 节的计数器页面用 `sahou build 计数器.saho -o 计数器.js` 生成 JS，直接用 `<script src>` 打开即可点。

**v2：模块系统、包管理、在线转译**
- 正式模块系统：`用 "网络" 引入`；v1.1/v1.5 的 `网络`、`页面` 从"预置模块名"变成"外来模块名"，**写法与语义完全不变**——这是提前用内置模块形态提供扩展的最大收益：升级 v2 时用户代码不用改。
- 包管理 `stones`：清单文件 + `sahou 装 <包名>`，包就是 `.saho` 文件目录；生态从 v2 起步。
- 浏览器端在线转译（`<script type="text/saho">`）：**仅开发模式**，理由见 1.4。

### 1.2 铁律：扩展的两条硬约束与"名额账本"

**约束一：扩展只允许做两件事。**
① 预置一个模块命名空间（`网络`、`页面`），成员是**函数值**或普通字典；
② 新增工具链命令与代码生成器（`sahou build`）。
除此之外——不新增关键字、不新增内置函数、不新增类型、不新增语法形式、不新增成员函数。

**约束二：扩展的一切能力必须是模块成员，永不进入全局内置函数表。**
D9 的 29 个内置函数是"全局可见、不需要引入"的；扩展能力是"要写模块名才能用"的。这条分工让
"初学者学的语言"与"能写前后端的语言"在**同一份源码第一屏**上看起来完全一样。

| 名额账本 | 数量 | 是否受 D9 上限（30）约束 |
|---|---|---|
| v1 核心内置函数 | **29**（留 1 个名额余量） | 是 |
| v1.1 `网络/net` 模块成员 | 6 个（服务/路由/监听/请求/自文本/到文本） | **否**，属模块命名空间 |
| v1.5 `页面/page` 模块成员 | 14 个（见 3.5 API 表） | **否**，属模块命名空间 |
| v1.5 JS 运行时前导库 `__saho_*` | 约 20 个 | **否**，是生成代码的私有实现，不是语言内置函数 |
| v1.1/v1.5 新增关键字 | **0** | 关键字总数仍为 **18** |

> 【扩展补充 E1】`网络` 与 `页面` 是**预置模块名**，不是关键字：它们可以被用户在函数作用域里赋值遮蔽（按 v1 作用域规则），
> 遮蔽后只是"用不了这个模块"，不产生任何特殊错误。这一条保证"模块系统 v2"落地前，语言的关键字表一行动也不用改。

### 1.3 v2 的模块引入语句（路线说明，不在本阶段实现）

v2 的模块引入语句写作 `用 "网络" 引入`（英文 `use "net" import` 的对称形式）。
【扩展补充 E2】这句里的 `用/use` 与 `引入/import` 谁是关键字、`引入` 是否降级为可选收尾词（形如 `用 "网络" 引入` / `用 "网络"` 两种写法），
留待 v2 设计时在简报登记。**唯一确定的是：这是 v2 的关键字增量，v1.1/v1.5 不欠这笔账。**

### 1.4 浏览器端在线转译（v2，开发模式）

```html
<!-- 开发模式：sahou.js 在浏览器里现场转译并执行（v2） -->
<script type="text/saho">
数字 = { "值": 0 }
页面.置文本(页面.取元素("#显示"), "开始")
</script>
<script src="sahou.js"></script>
```

- 用途**仅限开发模式**：写一个小 demo 不用安装任何工具、不用 `sahou build`。
- 生产环境仍走构建期转译（`sahou build`），理由三条：① 在线转译要把转译器自己送进浏览器，体积与启动延迟都不划算；
  ② 内联脚本常与站点的 CSP（内容安全策略）冲突；③ 构建期能把编译错误在本地就报清楚（D10），在线转译的报错体验天然更差。
- 在线转译器与 `sahou build` **共用同一个代码生成器**（自举到 JS 的那一份），不允许出现两套转译规则。

## 2. 后端设计（v1.1：内置模块 `网络/net`）

### 2.1 动机

卅 的定位不是后端语言，但"我写的程序别人能打开"是初学者最强的成就感来源。v1 已有 `读取文件`/`写入文件`，
再往前一步就只有"网络"一条路。既然 D9 把内置函数锁死在 29 个，网络能力就**只能**以模块成员的形式出现——
这也正好逼出了本设计最重要的一句话：

> **服务 = 字典 + 函数。**

没有类、没有框架基类、没有注解、没有装饰器（D4、D5）。起一个服务只有三步，一个不多。

### 2.2 语义极简：三步模型

```
服务 = 网络.服务()            # 第一步：创建服务（得到的是一个普通字典）
服务.路由("GET", "/你好", 处理)  # 第二步：注册路由（方法是文本，处理是函数值）
服务.监听(8080)               # 第三步：监听端口（阻塞在这里，Ctrl+C 结束）
```

三点必须讲清楚：

1. `网络.服务()` 返回的是**一个普通字典**，字段值里存着**函数值**（`服务["路由"]`、`服务["监听"]`）。
   这就是简报第 3 节示例二的"用字典代替对象，用函数操作字典"（D4）在扩展里的直接复用：
   `服务.路由(...)` 与 `动物.名字` 一样是成员访问，只不过取出来的成员恰好是个函数，接着被调用。
2. **处理函数是普通 卅 函数**：接收一个请求字典，返回一个响应字典。它不接收 `self`、不接收"上下文对象"、不需要注册类型。
3. `服务.监听(端口)` 是**一条普通语句**，不是特殊语法。它阻塞当前程序直到被中断——因为 v1 明确砍掉了并发（D7、10 节）。

**路由匹配规则**：v1.1 只做**精确匹配**（方法 + 完整路径），不做路径参数、不做通配符、不做正则。
需要"对某一条记录做删除"时，把参数放进**查询串**（见 2.5 示例）。理由：路径参数会立刻引出"参数语法"（`/待办/{序号}`）
这种新的词法规则，那就不是"扩展"而是"改语言"了——留到 v2。

### 2.3 请求对象是字典，响应对象也是字典

**请求字典**（宿主构造，处理函数只读它）：

| 键 | 类型 | 说明 |
|---|---|---|
| `"方法"` | 文本 | `"GET"`、`"POST"`、`"PUT"`、`"DELETE"`，统一大写 |
| `"路径"` | 文本 | 不含查询串的路径，如 `"/待办"` |
| `"查询"` | 字典 | 查询串解析结果，键与值都是**文本**，如 `{"序号": "1"}` |
| `"头"` | 字典 | 请求头，键名按 HTTP 惯例原样（`"Content-Type"`），值都是文本 |
| `"体"` | 文本 | 请求体**原文**，未做任何解析（语言里没有"字节"类型，二进制体不支持） |

**响应字典**（处理函数返回，缺省值由宿主补齐）：

| 键 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `"状态"` | 数 | `200` | HTTP 状态码 |
| `"头"` | 字典 | `{}` | 响应头 |
| `"体"` | 文本 | `""` | 响应体必须是**文本**，要返回 JSON 就自己 `网络.到文本(...)` |

两条刻意的极简取舍：

- **`"体"` 不做自动序列化**。返回列表或字典会报错（可被 `接住`），并给出 D10 式建议：

```
第 8 行：响应的 "体" 必须是文本，这里给的是 列表。
line 8: the response "body" must be 文本 (string), but got 列表 (list).
  提示：想返回 JSON，写 网络.到文本(结果)。
```

  理由：显式一行 `网络.到文本(...)` 换来的是"我知道我在发什么格式"，而自动序列化会在新手心里制造"到底谁转的、为什么是这个格式"的黑盒。
- **请求体不自动解析 JSON**。处理函数里显式写 `网络.自文本(请求["体"])`；解析失败抛出可接住的错误（含出错字符位置与开头内容）。

### 2.4 API 表（双语名，与内置函数同一套命名约定）

| 双语名 | 签名 | 一行说明 |
|---|---|---|
| `网络.服务()` / `net.server()` | `-> 服务字典` | 创建一个服务对象，字段含 `路由`、`监听` |
| `服务.路由(方法, 路径, 函数)` / `server.route(method, path, fn)` | `-> 空值` | 注册一条精确匹配的路由；方法与路径重复注册时**后注册的覆盖先注册的** |
| `服务.监听(端口, 主机: "127.0.0.1")` / `server.listen(port, host)` | `-> 不返回` | 阻塞式监听；端口被占用抛错；默认只绑本机，避免把初学者的电脑暴露到局域网 |
| `网络.请求(网址, 方法: "GET", 头: 空值, 体: "")` / `net.request(url, …)` | `-> 响应字典` | HTTP 客户端，**同步**返回响应字典（服务端宿主可用） |
| `网络.自文本(文本)` / `net.json_from(text)` | `-> 值` | JSON 文本→卅 值（对象→字典、数组→列表、`null`→空值） |
| `网络.到文本(值)` / `net.json_to(value)` | `-> 文本` | 卅 值→JSON 文本；遇到循环引用抛错（对齐规范 S11） |

> 【扩展补充 E3】JSON 编解码的两个名字按既定决策为 `自文本/json_from` 与 `到文本/json_to`。
> 由于 `文本/str` 已是核心内置函数名，本文一律**以模块限定形式**书写与实现（`网络.自文本`、`网络.到文本`），
> 模块内部不会遮蔽全局 `文本`。是否允许不带模块名的简写，留给 v2 模块系统时一并决定。

模块成员**不占**内置函数名额，也不与内置函数重名（`打印`、`文本`、`列表` 都还在全局）。

### 2.5 完整示例：待办事项 REST 服务（36 行）

```saho
# 待办事项 REST 服务（v1.1 网络模块）——内存存储：查、增、删
#   v2 落地后，第一行改为：用 "网络" 引入
待办 = {}            # 键是序号的文本，值是条目字典（用字典存内存，因为字典能原地删除）
状态 = { "下一个序号": 1 }

函数 列出(请求)
    结果 = []
    for 键 于 待办
        结果.添加(待办[键])
    完毕
    返回 { "状态": 200, "头": { "Content-Type": "application/json" }, "体": 网络.到文本(结果) }
完毕

函数 新增(请求)
    条目 = 网络.自文本(请求["体"])
    序号 = 状态["下一个序号"]
    条目["序号"] = 序号
    状态["下一个序号"] = 序号 + 1
    待办[文本(序号)] = 条目
    返回 { "状态": 201, "体": 网络.到文本(条目) }
完毕

函数 删除(请求)
    键 = 请求["查询"]["序号"]
    如果 包含(待办, 键)
        待办.删除(键)
        返回 { "状态": 200, "体": "已删除序号 {键}" }
    完毕
    返回 { "状态": 404, "体": "没有序号 {键} 的待办" }
完毕

服务 = 网络.服务()
服务.路由("GET", "/待办", 列出)
服务.路由("POST", "/待办", 新增)
服务.路由("DELETE", "/待办", 删除)
print("待办服务已启动：http://localhost:8080")
服务.监听(8080)
```

**这个示例里的两处"v1 语义要点"，也是写后端代码最容易踩的坑：**

1. **跨函数共享的可变状态必须放在容器里改，不能整体重新赋值。**
   `状态["下一个序号"] = 序号 + 1` 改的是共享字典对象（规范 5.3 引用语义），所以在 `新增` 里生效；
   如果写成 `下一个序号 = 下一个序号 + 1`，按 v1 作用域规则那只是**在函数内新建一个局部变量**，外层不变，第二个条目还会拿到序号 1。
   同理，删除没有写成 `待办 = 剩下`（那也会变成局部变量），而是用了字典的原地删除 `待办.删除(键)`。
2. **字典保持插入顺序**（规范 S10），所以"列出"里 `for 键 于 待办` 给出的顺序就是添加顺序，`结果` 不需要额外排序。

**运行与调用（宿主命令行，不是 卅 代码）：**

```bash
# 终端 1：启动服务
sahou 待办服务.saho
# 待办服务已启动：http://localhost:8080

# 终端 2：增、查、删
curl -X POST http://localhost:8080/待办 -d '{"事项":"买菜"}'
# {"事项":"买菜","序号":1}
curl http://localhost:8080/待办
# [{"事项":"买菜","序号":1}]
curl -X DELETE "http://localhost:8080/待办?序号=1"
# 已删除序号 1
```

### 2.6 实现注记：v1.1 用 Go `net/http` 做宿主绑定

- **宿主绑定层**：`net/` 模块用标准库 `net/http` 的 `http.Server` + `http.Handler` 实现，每个请求一个 goroutine，而语言层面仍保持 v1 的单线程顺序语义。
  **刻意用单线程的 `HTTPServer`，不用 `ThreadingHTTPServer`**：卅 v1 明确没有并发（10 节"线程、并发 不存在"），
  若宿主多线程排队处理请求，用户代码就会**看不见地**并发执行，`待办` 这类共享字典会出现难以解释的竞态。
  串行处理意味着"一次一个请求"，与语言"顺序执行"的承诺一致；性能不是本阶段目标。若将来要并行，先在 v2 把并发模型定下来。
- **请求/响应字典的构造与回填**：宿主负责把 HTTP 报文映射成 2.3 的字典，并把处理函数返回的响应字典写回报文；
  缺省值（状态 200、头 `{}`、体 `""`）在宿主侧补齐，用户不必写全。
- **路由表**：宿主内部就是一个 `{(方法, 路径): 函数值}` 的字典。没有中间件、没有过滤器链——那会是框架，不是语言扩展。
- **错误映射（D10）**：所有宿主异常都必须翻译成 卅 风格的双语错误，**绝不把 Go 的 `error` 细节或 panic 栈泄露给用户**：

```
第 36 行：端口 8080 已被占用，服务起不来。
line 36: port 8080 is already in use, so the server cannot start.
  提示：换一个端口（如 8081），或者先关掉占用 8080 的程序。
```

```
第 14 行：请求体不是合法的 JSON，第 1 个字符就出问题了。
line 14: the request body is not valid JSON (the problem is at character 1).
  提示：检查是不是少了一个引号或逗号。收到的开头是：{事项: "买菜"}
```

- **错误落在哪一行**：处理函数里的错误带该函数的源码行号、双语消息与调用链（规范 7.1 第 6 条）；
  宿主自己发现的错误（端口占用、JSON 解析失败）报 `服务.监听(...)` 或 `网络.自文本(...)` 调用所在的行。
- **处理函数抛错但没被接住**：宿主返回 `500`，正文是一条文本 `"服务内部出错：<消息>"`，同时把完整双语诊断打印到终端。
  程序**不退出**（一个请求出错不该毁掉整个服务），这也是"错误一旦被接住，程序继续往下走"（规范 6.5）的服务端形态。
- **与未来自举实现的一致性**：v1.1 的实现语言是 Go，但这只是宿主细节。`网络` 的语义唯一来源是本文 2.2–2.4；
  将来 v2/v3 用 卅 自己（或 Rust/Go 宿主）重写 `网络` 时，**接口、字典键名、错误消息、单线程语义必须逐字保持**，
  由一致性语料库（04 文档 8.4）里的后端用例做双向验证。用户代码从 v1.1 起就不必再改。

## 3. 前端设计（v1.5：`卅->JavaScript` 转译器 + `页面/page` 模块）

### 3.1 动机

浏览器只认 JavaScript，这是不可绕过的现实。有两条路：

- **路 A：写一个 卅的浏览器解释器**，在页面里现场解释 `.saho`。
  代价：要把整棵解释器（含诊断与内置函数）送进浏览器，页面首屏要多一次下载与一轮解释开销；且"两份语义实现"极易漂移。
- **路 B（本文选择）：把 卅 转译成 JavaScript**，产出可以直接 `<script src>` 的普通 JS。

选路 B 的三个理由：① 产物是普通 JS，任何静态托管、任何浏览器都能跑，零运行时依赖（除一个很小的前导库）；
② **复用同一套 lexer/parser/AST**，只新增一个代码生成器，语义漂移被压到最小；③ 报错行号能通过 source map 映射回 `.saho`，
D10"必须带行号"的承诺在前端也守得住。

### 3.2 转译管线（与 04 文档同一条流水线，末尾多一个后端）

```
页面.saho
   │ ① lexer/lexer.py（双语关键字归一化在词法阶段完成）
   ▼
Token 流 ──② parser/parser.py（递归下降）──▶ AST
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼                                           ▼
        ③ runtime/interpreter.py（v1 树遍历求值）      ③′ codegen/js.py（v1.5 新增）
                   直接运行 .saho                            输出 页面.js（+ 内联 saho_rt.js）
```

**分层铁律不变**（04 文档 1.3）：`codegen` 只依赖 `parser/nodes.py` 里的 AST 定义，不 import `runtime`，不回读源码文本。
同一份 AST 有两个后端，是"一致性测试语料库双向验证"的前提。

**命令形式**：

```bash
sahou build 页面.saho -o 页面.js      # 生成可直接 <script src> 的 JS（运行时默认内联，单文件部署）
sahou build 页面.saho --watch          # 建议：改 .saho 就重新生成
sahou build 页面.saho --source-map     # 建议：生成 页面.js.map，浏览器控制台定位回 .saho 行
```

**【扩展补充 E4】** 只有 `sahou build 页面.saho -o 页面.js` 这一个是既定决策；`--watch`/`--source-map`/`--runtime 外部`
是建议选项，语义确定后可由工具链自由增删。

### 3.3 转译规则表（契约）

**（1）关键字（18 个，逐一对应）**

| 卅 | JS 生成 | 说明 |
|---|---|---|
| `if` / `如果` | `if` | 条件表达式一律经 `__saho_truthy(...)` 包装（见下） |
| `elif` / `又如` | `else if` | 顺序判断语义一致 |
| `else` / `否则` | `else` | — |
| `while` / `当` | `while` | 条件同样经 `__saho_truthy` |
| `for` / `遍历` … `in` / `于` | `for (const x of __saho_iter(seq))` | 列表→数组、文本→按**字符**迭代、字典→按**键**迭代 |
| `end` / `完毕` | `}` | 块收尾一一对应；转译器不产生任何额外块 |
| `fn` / `函数`（具名） | `function 名(...) { ... }` | 函数声明 |
| `fn` / `函数`（匿名） | `(参数) => 表达式` | 唯一的匿名写法，JS 侧同样是单表达式箭头函数 |
| `return` / `返回` | `return` | 顶层返回靠 IIFE 包裹（见下） |
| `let` / `设` | `let` | `设` 是可写可不写的前缀，生成结果一致 |
| `true` / `真` | `true` | 布尔 |
| `false` / `假` | `false` | 布尔 |
| `null` / `空值` | `null` | 空值 |
| `and` / `并且` | `&&` | 短路语义一致 |
| `or` / `或者` | `\|\|` | 短路语义一致 |
| `not` / `非` | `!__saho_truthy(x)` | 结果永远是布尔 |
| `try` / `尝试` | `try` | — |
| `catch` / `接住 错误信息` | `catch (e) { const 错误信息 = __saho_error_text(e); ... }` | `接住` 绑定的是**文本**（D8） |

**（2）类型与字面量**

| 卅 | JS 生成 | 选择理由 |
|---|---|---|
| 数 / number | `number` | 单一数类型 ↔ JS 的 IEEE-754 double；精度取舍见 3.4 |
| 文本 / string | `string` | 直接对应；模板字符串复刻插值 |
| 列表 / list | `Array` | 顺序、可变、可混合类型，语义最接近；成员函数 `.添加/.去重` 生成 `__saho_append` / `__saho_dedupe` 调用 |
| 字典 / dict | **`Map`** | **不用普通对象**：① 规范 S10 要求字典**保持插入顺序**，而 JS 普通对象会把"看起来像整数"的键（`"1"`、`"2"`）自动排到最前并升序，顺序会变；② 卅 允许**数**作键，普通对象的键一律被转成文本；③ 普通对象有原型链，`d["constructor"]` 之类的键会撞车。`Map` 三条全解决，代价是生成代码可读性略降——用 `__saho_dict_get/set/remove` 三个辅助函数补齐缺键报错与候选键建议 |
| 布尔 / bool | `boolean` | 直接对应 |
| 空值 / null | `null` | 直接对应 |
| 函数值 / function | `function` | 一等公民（D5）在 JS 里也是一等公民，无需包装 |
| `{ "名字": "咪咪" }` | `new Map([["名字", "咪咪"]])` | 字面量构造 |
| `d.名字` / `d["名字"]` | `__saho_dict_get(d, "名字")` | 缺键时报 D10 双语错误并列出候选键 |
| `d["键"] = v` | `__saho_dict_set(d, "键", v)` | 新键合法，旧键覆盖 |
| `列表[0]` | `__saho_index(列表, 0)` | 越界与**负索引**都按 v1 报错（含 `长度(…) - 1` 的改写建议） |
| `取(序列, 起, 止, 步长)` | `__saho_slice(...)` | 半开区间、返回新值 |
| `"你好, {名字}!"` | `` `你好, ${__saho_str(名字)}!` `` | 插值里的值必须经 `__saho_str` 归一 |
| `空值` 的真值 | `__saho_truthy(null) -> false` | — |
| 条件位置的一切值 | `__saho_truthy(v)` | **必须包装**：JS 里 `[]`、`{}`、`"0"`、`"假"` 都是真，而 卅 规定 `[]`、`{}`、`0`、`""` 为假（规范 5.4） |
| `a == b` | `__saho_eq(a, b)` | 列表/字典要**深度相等**（JS 的 `===` 是引用比较），且跨类型 `==` 返回假而不报错（S7） |
| `a < b` 等大小比较 | `__saho_lt(a, b)` 等 | 跨类型报错（S7）；文本按 Unicode 码位比较 |
| `/` | `__saho_div(a, b)` | 真除法；除数为 0 抛可接住错误（JS 会静默给出 `Infinity`） |
| `%` | `__saho_mod(a, b)` | 余数符号跟随被除数：`-7 % 3` 得 `2`，JS 原生 `%` 得 `-1`，必须修正；对 0 取余抛错 |
| `打印(值, 结尾: "…")` | `__saho_print(值, "…")` | 浏览器里走 `console.log`；一次只打印一个值（S16） |
| 其余 28 个内置函数 | 一一映射到 `__saho_*` | 见 3.8 前导库表 |

**（3）语句、作用域与错误**

| 主题 | 规则 |
|---|---|
| 块作用域 | 卅 的 `如果`/`当`/`遍历`/`尝试` 块**不创建作用域**（规范 5.3），而 JS 的 `let` 是块级的。代码生成器把**在每个函数体内被赋值的所有名字**提升为该函数顶部的 `let` 声明，块内只写赋值语句——这样"块内赋值，块外仍可见"与 v1 完全一致 |
| 遮蔽 | 函数内给"外层已有名字"赋值在 v1 里是**新建局部变量**。上文的名字提升策略天然复刻了这一点：函数顶部 `let 计数;` 就遮蔽了外层 `计数` |
| 顶层 `返回` | JS 脚本顶层不允许 `return`。转译器把整个程序包进 `(function () { "use strict"; … })();`，顶层 `返回` 因此合法并结束程序（规范 S12） |
| 标识符 | 中文标识符在 JS 里是合法的（ES 允许 Unicode 标识符），因此变量名/函数名**原样保留**，便于阅读与定位。少数与 JS 保留字冲突的 卅 名字（如 `class`、`new`、`typeof`——它们在 卅 里都不是关键字）统一加 `_` 前缀重命名，并在函数上方生成 `// sahou: 原名 class` 注释 |
| 注释 | 卅 的 `#` 注释**不生成**到 JS（避免把逐行注释搬进产物）；可选 `--comments` 再打开 |
| 文件/输入类内置函数 | `读取文件`、`写入文件`、`文件存在`、`输入` 在浏览器不可用：编译期给**警告**（不是错误，同一份 `.saho` 可能在服务端跑），运行期调用则抛可接住错误：`浏览器里没有文件系统，读取文件 用不了。试试让服务端把内容发过来。` |
| 运行期错误 | `抛出("消息")` → `__saho_throw("消息")`（`SahoError`，消息就是那条文本）。**非 卅 的 JS 原生异常必须被屏蔽**：`__saho_error_text` 对非 `SahoError` 一律返回 `"程序内部出错，请把下面这段报给作者"` 这类文本，并把原始错误单独打到控制台——D10 硬规则"不泄露实现语言"在浏览器里同样成立 |
| 行号 | 每条可执行语句前生成 `// sahou: 第 N 行` 注释；`--source-map` 时额外生成映射文件。运行期错误消息前缀 `[卅 第 N 行]`，让控制台第一眼就看到 `.saho` 行号 |
| 编译期错误 | 与 v1 完全同一套诊断（第 N 行、中文优先、英文、`你是不是想写…`），因为复用同一个 parser 与同一套 diagnostics 模块，**前端不会新增一种报错格式** |

**（4）转译不做的事（与"砍掉清单"对齐）**

不生成 `async`/`await`、不生成 `Promise`、不生成 `class`、不生成生成器、不生成装饰器语法、不引入打包器语义。
`await`、`class`、`Promise` 这些词在 卅 里根本没有对应语法，因此"转译"永远不需要面对它们。

### 3.4 单一数类型映射到 JS `number` 的精度取舍

D3 的用户规则只有三条（只有一种数、`/` 永远真除、整数结果显示成整数），但 v1 规范 S8 在实现层把小数规定为
**十进制、15 位有效数字**。JS 的 `number` 是 IEEE-754 双精度二进制浮点，两者不可能逐位一致，取舍如下：

| 场景 | v1 解释器（权威语义） | 转译后（JS） | 结论 |
|---|---|---|---|
| 安全整数范围 | 精确整数（任意精度，无上限） | 精确到 **±2^53**（9,007,199,254,740,992，约 16 位十进制） | 教学与常见业务都在范围内；超出范围**不再精确**，属已知偏差 |
| `0.1 + 0.2 == 0.3` | `真`（十进制 15 位） | 默认 `假`；经 `__saho_num` 归一到 15 位有效数字后为 `真` | 每个算术运算的结果都过一层 `__saho_num(x) = Number(x.toPrecision(15))`，把二进制误差按 15 位有效数字抹平，使其与解释器一致 |
| `10 / 3` | `3.33333333333333`（15 位有效数字） | `__saho_num(10 / 3)` 得同样 15 位值 | 一致 |
| 除零 / 对零取余 | 可接住的错误 | `__saho_div` / `__saho_mod` 显式检查并抛错 | 一致（不产生 `Infinity`、`NaN`，二者在 卅 里不存在） |
| `-7 % 3` | `2`（余数符号跟随被除数） | `__saho_mod` 用 `((a % b) + b) % b` 修正 | 一致 |
| 打印 | 最短可还原十进制、无尾部 `.0` | `__saho_str`：整数结果不带小数点 | 一致 |

**必须写进文档与报错的边界（D10）**：

1. 绝对值超过 `2^53` 的整数在浏览器端**可能不再精确**。真实的做法是——转译器无法在编译期知道数值大小，因此由
   `__saho_num` 在运行期检测：一旦发现"传入的是整数、归一后与原值不同"，就抛出可接住错误
   `数太大了，浏览器里的数最多精确到 9007199254740992，这个数已经超出。`（而不是安静地给一个错答案）。
2. 这是 v1.5 **唯一**被允许的语义偏差，必须登记进一致性语料库的"允许偏差"清单（04 文档 8.4），
   并在 `sahou build` 的输出里打印一行提示：`提示：浏览器端小数按 15 位有效数字对齐，超大整数（> 2^53）不保证精确。`
3. 需要大整数或高精度计算（比如算阶乘）的程序，属于"高性能计算"这一**非目标**（简报 1 节），文档明确说明写在服务端跑（v1.1）。

### 3.5 DOM 与事件 API：内置模块 `页面/page`

一句话原则：**事件处理就是传函数值**——这是 D5"函数是一等公民"的直接应用，不引入任何新概念。
没有 `addEventListener` 名字、没有事件对象类型、没有 `this`、没有 async/await、没有响应式绑定。

| 双语名 | 签名 | 一行说明 |
|---|---|---|
| `页面.取元素(选择器)` / `page.el(selector)` | `-> 元素` | 按 CSS 选择器取一个元素；找不到返回**空值**（便于 `如果 元素 == 空值` 判断），不报错 |
| `页面.取全部(选择器)` / `page.el_all(selector)` | `-> 列表` | 取所有匹配元素，返回元素列表（可为空列表） |
| `页面.置文本(元素, 文本)` / `page.set_text(el, text)` | `-> 空值` | 设置元素文字内容；非文本值自动按 `文本(...)` 规则转换 |
| `页面.取文本(元素)` / `page.get_text(el)` | `-> 文本` | 读取元素文字内容 |
| `页面.值(元素)` / `page.value(el)` | `-> 文本` | 读取输入框当前值（`<input>`/`<textarea>`/`<select>`） |
| `页面.置值(元素, 文本)` / `page.set_value(el, text)` | `-> 空值` | 设置输入框的值 |
| `页面.置样式(元素, 属性, 值)` / `page.set_style(el, name, value)` | `-> 空值` | 设置内联样式，如 `页面.置样式(盒子, "color", "red")` |
| `页面.置属性(元素, 名称, 值)` / `page.set_attr(el, name, value)` | `-> 空值` | 设置 HTML 属性（如 `"disabled"`、`"href"`） |
| `页面.点击(元素, 函数)` / `page.on_click(el, fn)` | `-> 空值` | 点击事件；`函数` 接收一个参数（事件字典，见下） |
| `页面.输入(元素, 函数)` / `page.on_input(el, fn)` | `-> 空值` | 输入事件，每敲一下就触发一次 |
| `页面.提交(元素, 函数)` / `page.on_submit(el, fn)` | `-> 空值` | 表单提交事件，宿主自动阻止默认跳转 |
| `页面.创建(标签)` / `page.create(tag)` | `-> 元素` | 新建元素，如 `页面.创建("li")` |
| `页面.加入(父元素, 子元素)` / `page.append(parent, child)` | `-> 空值` | 把子元素追加到父元素末尾 |
| `页面.移除(元素)` / `page.remove(el)` | `-> 空值` | 从页面中移除元素 |

**约定与边界（【扩展补充 E5】）**

- **元素是不透明宿主句柄，不是第六种类型**：`类型(元素)` 返回 `"dict"`（它在实现里就是一个由宿主掌控、语言不可直接读写的句柄），
  但它**不能**索引、**不能**成员访问、**不能**参与算术。误用时给的错误是：
  `第 6 行：元素不能这样用。它只能交给 页面 模块的函数，例如 页面.置文本(元素, "你好")。`
  句柄与句柄之间 `==` 按"是不是同一个元素"判断，与其他值比较一律为 `假`。
- **事件字典**：事件处理函数收到的参数是一个普通字典，v1.5 只保证两个键——`"类型"`（如 `"点击"`）与 `"目标"`（元素句柄）。
  刻意不把整套 DOM 事件对象暴露出来：那需要为每种事件定义字段表，等于把浏览器 API 塞进语言。需要更多信息就用 `页面.取元素` 再取一次。
- **没有 `页面.延时`/定时器**：定时器是"将来才执行"的异步语义，与 v1 砍掉 `async/await` 的方向冲突，v1.5 不加（见第 5 节）。
- **`页面` 模块只在浏览器宿主存在**；在服务端解释器里使用它会抛错并提示
  `页面 模块只能在浏览器里用；服务端程序请用 网络 模块。`
- **`网络.请求` 在浏览器端暂不提供**：浏览器主线程不允许同步阻塞地发网络请求，而 v1 没有 `async/await`（D7、砍掉清单）。
  这一能力与"回调式 API"一起留给 v2 与并发模型一同定义（图省事的替代写法是把数据先渲染进 HTML，或用普通表单提交）。
  这条边界一并写进"不做的事"（第 5 节）。

### 3.6 完整示例：点击按钮计数器页面

**页面 HTML（计数器.html）**

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <title>计数器</title>
</head>
<body>
  <p id="显示">还没开始</p>
  <button id="按钮">点我 +1</button>
  <script src="计数器.js"></script>
</body>
</html>
```

**卅 源文件（计数器.saho）**

```saho
# 计数器页面（v1.5 页面模块）—— 事件处理就是传函数值（D5）
#   v2 落地后，第一行改为：用 "页面" 引入
数字 = { "值": 0 }
显示 = 页面.取元素("#显示")
按钮 = 页面.取元素("#按钮")

函数 刷新()
    页面.置文本(显示, "你点了 {数字["值"]} 次")
完毕

函数 点一下(事件)
    数字["值"] = 数字["值"] + 1
    刷新()
完毕

页面.点击(按钮, 点一下)
刷新()
```

**构建与打开**

```bash
sahou build 计数器.saho -o 计数器.js
# 然后用浏览器打开 计数器.html（或任何静态托管）
```

**这个示例要说明的三件事：**

1. `函数 点一下(事件)` 是**普通 卅 函数**，它被当作**值**传给 `页面.点击`——没有事件接口、没有实现类、没有注册类型，
   全靠 D5。想加个"清零"按钮，就再写一个 `函数 清零(事件)`，再传一次，仅此而已。
2. 计数状态放在字典 `数字` 里而不是一个裸变量：处理函数里写 `数字["值"] = …` 改的是共享对象（规范 5.3）；
   若写成 `数字 = 数字 + 1`，因为函数内赋值只创建局部变量，计数永远停在 1。
3. 更新界面靠**显式调用** `刷新()`——没有响应式、没有虚拟 DOM、没有"数据变了界面自己变"。
   这是刻意的：新手能一眼看出"我改了什么"和"我什么时候要求它重画"。

### 3.7 生成结果示意（节选）

```javascript
// 由 sahou build 生成 —— 请勿手改
(function () {
  "use strict";
  const 数字 = new Map([["值", 0]]);
  const 显示 = page.el("#显示");
  const 按钮 = page.el("#按钮");

  function 刷新() {                                    // sahou: 第 7 行
    page.set_text(显示, `你点了 ${__saho_str(__saho_dict_get(数字, "值"))} 次`);
  }
  function 点一下(事件) {                              // sahou: 第 12 行
    __saho_dict_set(数字, "值", __saho_num(__saho_dict_get(数字, "值") + 1));
    刷新();
  }
  page.on_click(按钮, 点一下);                         // sahou: 第 17 行
  刷新();
})();
```

注意三个生成细节：① 中文标识符原样保留；② 每个函数上方的 `// sahou: 第 N 行` 注释与 `--source-map` 一起保证行号可回溯；
③ 所有取值/赋值都走 `__saho_dict_get/set`，所以"缺键"报的是 卅 的双语消息，而不是 JS 的 `undefined`。

### 3.8 实现注记

- **代码生成器**：新增 `codegen/js.py`，输入 AST、输出 JS 文本；与 `runtime/interpreter.py` 平级，两者都不依赖对方。
  AST 上若需要前端专用信息（如"这个函数是事件处理函数"），一律**不新增 AST 节点**——用生成期的上下文判断即可，保持 AST 是语言事实的唯一表示。
- **运行时前导库** `saho_rt.js`（约 20 个 `__saho_*` 函数，不是语言内置函数、不计入 29 个名额）：

  | 辅助函数 | 对应语义 |
  |---|---|
  | `__saho_truthy` / `__saho_str` / `__saho_typeof` | 真值规则（5.4）、`文本(值)` 转换（5.1）、`类型(值)`（S14） |
  | `__saho_num` / `__saho_div` / `__saho_mod` / `__saho_round` | 15 位有效数字归一、真除法与除零、余数符号、四舍五入 |
  | `__saho_eq` / `__saho_lt` 等 | 深度相等（含循环检测）、大小比较与跨类型报错（S7） |
  | `__saho_index` / `__saho_slice` / `__saho_len` / `__saho_contains` | 索引（禁负、越界报错）、`取`、`长度`、`包含` |
  | `__saho_dict_get` / `__saho_dict_set` / `__saho_dict_remove` | 字典读写与缺键候选建议 |
  | `__saho_append` / `__saho_dedupe` | `列表.添加`、`列表.去重` |
  | `__saho_iter` | `遍历` 列表/文本/字典的统一迭代 |
  | `__saho_throw` / `__saho_error_text` | `抛出` 与 `接住`（屏蔽 JS 原生异常文案） |
  | `__saho_print` / `__saho_json_to` / `__saho_json_from` | `打印`（`console.log`）、`网络.到文本` / `网络.自文本`（`Map`↔对象、循环引用抛错） |
- **前导库的打包**：默认**内联**进输出 JS（单文件、双击 `HTML` 就能跑，最符合教学场景），
  可选 `--runtime 外部` 生成 `<script src="saho_rt.js">` 供多页面复用。
- **浏览器可用性检查**：转译期对 `读取文件`/`写入文件`/`文件存在`/`输入` 给警告级提示（见 3.3 表），
  对 `网络.请求` 给错误级提示（浏览器端不提供，理由见 3.5）。
- **一致性验证（最重要的一条）**：把 v1 的解释器测试语料（04 文档 8.4）同时跑在两个后端上——
  解释器执行 `.saho`，转译器生成 JS 后用 Node.js 执行，逐字节比较输出。两份输出不一致 = 转译器有 bug，
  **不是**"浏览器就是这样"。唯一的例外是 3.4 的精度清单与 3.8 的宿主能力清单，二者必须在测试里显式登记为允许偏差。
- **浏览器的报错出口**：未被接住的错误用 `console.error` 打印 `[卅 第 N 行] + 中文消息 + 英文消息 + 建议`，
  并在页面上（若存在 `id="卅-错误"` 的元素则写入该元素）显示同一句话——让学生不必打开控制台就能看到自己错在哪。

## 4. 与核心设计原则的兼容性自检表（D1–D10）

| 决策 | 扩展是否破坏它 | 具体落点 |
|---|---|---|
| **D1** `end`/`完毕` 收尾，不用缩进与花括号 | 否 | 扩展**不新增块类型**：路由处理函数、事件处理函数都是普通 `函数 … 完毕`。生成器把 `完毕` 一一映射成 `}`。虽然 JS 有箭头函数与花括号，卅 侧仍然只有一种匿名写法 `函数(x) => 表达式`，不引入链式回调 |
| **D2** 双语关键字（18 个） | 否 | 扩展的一切名字都双语：`网络/net`、`服务/server`、`路由/route`、`监听/listen`、`请求/request`、`自文本/json_from`、`到文本/json_to`、`页面/page`、`取元素/el`、`置文本/set_text`、`点击/on_click`、`输入/on_input`。`网络`/`页面` 是**模块名不是关键字**，v1.1/v1.5 关键字总数仍为 **18**；模块引入语句是 v2 的事（1.3） |
| **D3** 只有一种"数" | 否 | 语言层的数不变（整数精确、`10 == 10.0` 为 `真`、`/` 永远真除）；前端映射到 JS `number` 并按 15 位有效数字归一（3.4），超大整数给出可接住的显式错误而**不是**错答案 |
| **D4** 只有 5 种类型 + 空值 | 否 | 服务、请求、响应**全是普通字典**（"服务=字典+函数"）；元素句柄是不透明宿主句柄，**不新增类型名**（`类型(元素)` 返回 `"dict"`），不能索引/成员访问/参与运算。扩展没有引入集合、Promise、类、日期等任何新类型 |
| **D5** 函数是一等公民，定义方式只有一种 | **直接应用** | 路由注册传函数值、事件绑定传函数值，正是 D5 的用途。不引入方法、`this`、绑定、装饰器、重载；匿名函数仍只有 `函数(x) => 表达式`（因此多语句的事件处理必须写成具名函数——这是示例 3.6 展示的写法） |
| **D6** 插值代替拼接 | 否 | 前后端示例继续使用 `"你点了 {数字["值"]} 次"`；生成 JS 模板字符串，插值值经 `__saho_str` 归一，所以 `真` 仍然是"真"而不是 JS 的 `true` |
| **D7** 循环只有两种，无 `async/await` | 否 | 路由分派与待办遍历都用 `遍历`；扩展不加循环语法、不加异步语法、不加回调地狱式的错误链。`服务.监听(端口)` 就是一条普普通通、会阻塞的语句；定时器与 `网络.请求`（浏览器端）因此明确不做（3.5、第 5 节） |
| **D8** 错误处理只有 `尝试/接住` | 否 | 端口占用、JSON 解析失败、处理函数出错、浏览器里调用文件函数——全部走同一条 `抛出`/`接住` 通道，错误对象仍是一段**文本**。没有 Promise rejection、没有错误事件回调、没有 finally |
| **D9** 内置函数 ≤ 30（现 29），v1 无模块系统 | 否 | 第 1.2 节**名额账本**：核心仍 29 个；`网络` 6 个、`页面` 14 个成员全在模块命名空间，**+0**；`__saho_*` 是生成代码的私有实现，不是语言内置函数。模块系统的缺失用"预置模块名"这一临时形态补上，v2 换成 `用 "xxx" 引入` 时用户代码不变 |
| **D10** 报错必须说人话（双语、带行号、给建议） | 否，且要额外守两条 | ① 宿主错误（端口占用、JSON 解析失败、JS 原生 `TypeError`）**一律翻译**成 `第 N 行` + 中英双语 + 建议，禁止泄露 `Traceback`/`undefined`/`Cannot read properties of null`；② 前端靠 `// sahou: 第 N 行` 注释与 source map 保证行号指向 `.saho`，编译期错误沿用 v1 同一套 diagnostics，不新增第二种报错格式 |

## 5. 明确不做的事（及理由）

**1. 不做 SSR（服务端渲染）。**
理由：SSR 需要"在服务端执行一段页面代码、再把它变成 HTML 文本"的第二套渲染语义，还要定义模板、转义、注水（hydration）等概念——
这与"一个程序一种写法"直接冲突，也会让初学者搞不清"这段话到底在服务器跑还是在浏览器跑"。
替代方案：v1.5 只做**构建期转译 + 静态托管 + 客户端渲染**；需要服务端逻辑，就用 v1.1 的 `网络` 模块写一个 API，把数据发给前端。
（顺带：`页面` 模块在服务端不存在，从机制上就堵住了"服务端跑页面代码"这条路。）

**2. 不做虚拟 DOM。**
理由：虚拟 DOM 的核心是"两棵树的 diff 算法"与"状态变化触发重渲染"的隐式调度，这需要组件模型、生命周期、key 约定——
即一整个框架。它与 D1"结构要显式"背道而驰：新手看不到"什么时候、为什么界面变了"。
替代方案：直接用 `页面.创建/加入/移除` 与 `页面.置文本` 显式改界面；列表刷新就写一个 `函数 刷新列表()`，清空后重新逐条加入。
教学场景的页面规模下，这个写法足够快，而且每一步都看得见。

**3. 不做响应式框架。**
理由：响应式（数据变了自动重画）依赖**隐式依赖追踪**——这正是简报砍掉"魔法方法"的同一条理由。
它还会与 v1 的作用域规则打架：v1 里函数内赋值只创建局部变量（规范 5.3），隐式追踪必须绕过这条规则，等于给语言加暗门。
替代方案：显式调用刷新函数（3.6 的 `刷新()`）；需要"数据变了就更新"的场合，就在改完数据的那一行**紧接着**写调用。

**4. 不做 WebSocket（v2 再议）。**
理由：WebSocket 是**双工长连接**，它一次性引入四件 v1 明确没有的东西：连接生命周期管理、断线重连、异步消息回调、服务端并发。
v1.1 的服务端是单线程串行（2.6），v1 没有 `async/await`，"收到消息就执行一段函数"这种回调模型还没有定义过。
替代方案：用 `网络.请求` **轮询**（每几秒问一次服务端）——慢一点，但语义完全落在 v1 已有的能力里，学生能看懂。
将来要做，必须先做 v2 的并发与异步模型（回调形式？事件队列？），再谈 WebSocket；本文不预先设计它。

**5. 附带不做（同类理由，一并写清楚）**

| 不做的事 | 理由 | 替代写法 |
|---|---|---|
| 静态文件托管（`服务.静态(目录)`） | 会往 `网络` 里塞进 MIME 类型、目录遍历、路径安全一整套东西；教学场景用宿主的静态服务器即可 | 用 `sahou build` 产物配任意静态托管（教学场景由老师预先放好 `计数器.html` + `计数器.js`） |
| 路径参数路由（`/待办/{序号}`） | 需要新的词法/模式语法，属于"改语言"而不是"加扩展" | 参数放查询串（2.5 示例的 `?序号=1`） |
| 并发/多线程服务 | 简报 1 节把并发列为非目标；多线程会让共享字典出现看不见的竞态 | 单线程串行（2.6）；要并行先在 v2 定并发模型 |
| 二进制上传/下载、Cookie/会话 | 语言里没有"字节"类型，会话要引入服务端状态存储 | 只收发文本/JSON；会话状态由前端自己保存并每次带上 |
| 浏览器端 `网络.请求`、定时器 | 需要异步语义，而 v1 砍掉 `async/await`（D7） | 数据在构建期渲染进 HTML；或 v2 定义回调式 API 后再做 |
| 直接引用 npm 包、前端打包器 | 依赖生态属于 v2 的 `stones`，且打包器会引入模块解析谜题 | 只用 `sahou build` 产出单文件 JS；第三方库等 `stones` |
| 前端专属的新语法（组件、插槽、指令） | 会破坏"v1.1/v1.5 零关键字增量"这条铁律 | 全部用函数 + 字典 + `页面` 模块的组合表达 |
