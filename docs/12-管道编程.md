# 卅· 管道编程

> **文档定位**：本文描述 卅 **v3 新增的核心结构特色——数据流水线**（通常简称"管道"，pipeline）。
> 管道不是新函数、不是新类型、也不是新关键字，它是**表达式的一种写法**：
> 让数据像石子一样，沿着管道一节一节流过去，每一步都被加工一次。
>
> 与《[02-语言规范](./02-语言规范.md)》《[11-用户手册](./11-用户手册.md)》的关系：
> 关键字、内置函数、数据类型三本账**一个都没变**——仍然是
> **本文写作时（v3）21 个关键字、29 个内置函数；现为 23 个关键字、30 个内置函数**（v4.1 加 格子之后又加 跳出/继续 与 位置/find），5 种数据类型 + 一个空值不变。
> 管道只是把"函数的嵌套调用"换了一种**从左往右读**的写法。**本文是管道示例的唯一事实来源。**
>
> **验证说明**：本文中的代码块（含全部管道示例）均已用 `sahou.exe run` / `sahou.exe ast`
> 实机验证通过。管道符号推荐手打方便的 `->`；全角 `→` 是等价别名。

## 0. 一分钟看懂

同一个任务，两种写法，结果完全相同：

```saho
# 不用管道：从最里面往外读
结果 = 连接(取(排序([95, 58, 72, 88, 60], 降序: 真), 0, 3), "、")

# 用管道：从左往右读，数据一路流过去
结果 = [95, 58, 72, 88, 60] -> 排序(降序: 真) -> 取(0, 3) -> 连接("、")
```

两种写法都得到 `95、88、72`：

1. `[95, 58, 72, 88, 60]` 是**入口**，把一串成绩放进去；
2. `-> 排序(降序: 真)` 把它排成 `[95, 88, 72, 60, 58]`；
3. `-> 取(0, 3)` 取前三个，得到 `[95, 88, 72]`；
4. `-> 连接("、")` 连成一句话 `"95、88、72"`。

一句话：**管道让"数据怎么变"按发生的顺序，从左到右写出来。**

## 1. 为什么要有管道

### 1.1 同一个任务的三种写法

任务：从成绩里挑出及格的（`>= 60`），按从高到低排序，取前三名，用"、"连成一句话。

**写法一：嵌套调用——从里往外读**

```saho
结果 = 连接(取(排序(过滤(分数们, 函数(x) => x >= 60), 降序: 真), 0, 3), "、")
```

这段代码能用，但**读起来很累**：最外层的动作 `连接(...)` 写在最左边，可它是**最后**才执行的；
眼睛必须在四层括号之间来回跳，才能还原事情的先后顺序。括号一多，漏一个、多一个都很难发现。

**写法二：中间变量——一步一步读写**

```saho
合格的 = 过滤(分数们, 函数(x) => x >= 60)
排好的 = 排序(合格的, 降序: 真)
前三 = 取(排好的, 0, 3)
结果 = 连接(前三, "、")
```

这个写法**清楚**：每一行做一件事，从上往下就是执行顺序。但它要起四个名字，
而 `合格的`、`排好的`、`前三` 这三个名字**只出现一次**，用完就再也没人提起。
名字是给读者看的，起得太多反而变成噪音；更麻烦的是，
"这一步的结果到底交给谁"要靠读者自己一行行去接。

**写法三：管道——数据自己流过去**

```saho
结果 = 分数们 -> 过滤(函数(x) => x >= 60) -> 排序(降序: 真) -> 取(0, 3) -> 连接("、")
```

这一行同时拿到了两个好处：

- **像写法二一样清楚**：从左到右，就是执行的先后顺序；
- **像写法一一样紧凑**：不用给只活一行的中间结果起名字。

### 1.2 "数据像石子在管道里流动"

想象你手里有一颗**石子**：

- 最左边的 `分数们` 是**管道入口**，你把石子从这里放进去；
- 每一个 `-> 步骤` 是**一节管道**，石子经过它就被加工一次（排序、截取、拼接）；
- `->` 本身是**两节管道之间的接头**，它不做事，只负责把上一节的出口接到下一节的入口；
- 最右边流出来的，就是整条管道的产物。

石子在管道里**只往前走，不回头**：

```
分数们 ──-> 过滤(及格) ──-> 排序(降序) ──-> 取(0, 3) ──-> 连接("、") ──-> "95、88、72"
  [列表]       [列表]          [列表]         [列表]         [文本]
```

每一步只关心两件事：**我收到什么、我交出什么**。它不需要知道前面是谁，
也不需要知道后面是谁——这正是"管道"最值钱的地方：**每一节都可以单独看懂、单独测试。**

### 1.3 与 JavaScript / Python 的根本差别

JavaScript 和 Python 的基本结构是"**语句 + 赋值**"的命令式结构：

```
读数 -> 存进变量 -> 用 if 判断 -> 用 for 循环 -> 把结果存进另一个变量
```

数据本身不会"动"，是你在语句之间**搬**它。

卅 在这套结构**之上**，多给了一种声明式的结构：**数据沿管道流动**。
你只需说"数据依次经过哪些加工"，而不必说"每一步把结果存进哪个盒子"。

| 维度 | JS / Python 的常规写法 | 卅 管道写法 |
|---|---|---|
| 结构 | 语句 + 赋值（命令式） | 数据沿管道流动（声明式） |
| 读法 | 嵌套时从里往外，或从上往下 | **从左往右，就是执行顺序** |
| 中间结果 | 必须嵌套，或必须起名字 | 隐式流动，不落地 |
| 数据的位置 | 被动地被搬来搬去 | **主动地从左流到右** |
| 加工的顺序 | 藏在括号层次里 | 直接写在纸面上 |

> **注意**：JavaScript 里也有 `xs.filter(f).map(g)` 这样的"链式调用"，但那是
> **对象方法链**——只有"自带这些方法的对象"才能链，链上写的是方法名。
> 卅 的管道对**任何值、任何函数**都成立：列表可以流、文本可以流、字典可以流，
> 全局函数、成员函数、匿名函数都能当一节管道。它不是一个库，而是**语言结构**。

### 1.4 什么时候**不**用管道

管道很好，但不是万金油。遇到下面三种情况，请换回普通写法：

1. **只有一步**：`print(排序(数据))` 比 `print(数据 -> 排序)` 更直接；
2. **中间结果后面还要用**：给它起个名字（`排好的 = 数据 -> 排序`），之后反复使用；
3. **一步里有分支、循环、多句话**：把它抽成一个**具名函数**（匿名函数只能写一句表达式，
   装不下 `如果` / `遍历` / `尝试`），然后 `-> 函数名`。

## 2. 语法细则

以下七条是管道的全部规则，请逐条读完再看例子。

### 2.1 形式与管道符号

形式：

```
表达式 -> 步骤 -> 步骤 -> ...
```

- 管道符号是**半角箭头 `->`**（减号 + 大于号，键盘直接可打，**推荐写法**）；
- 全角箭头 `→` 是**完全等价的别名**，词法阶段就归为同一个记号（早于 `->` 存在，仍支持）；
- 一条管道至少要有**一个步骤**（只有一个 `->`）。

```saho
print([3, 1, 2] -> 排序)      # [1, 2, 3]
print([3, 1, 2] → 排序)     # 同上：全角别名 →，完全等价
```

三个必须记住的区分：

| 写法 | 名字 | 含义 |
|---|---|---|
| `->`（别名 `→`） | **管道** | 把左边的值流进右边的步骤 |
| `=>` | 匿名函数 | `函数(x) => x * 2`，箭头右边是函数体 |
| `- >` | 不是任何东西 | `-` 是减号、`>` 是比较符；中间隔了空格就拼不成管道 |

> **为什么推荐 `->`**：`→` 要靠输入法特殊面板或复制粘贴才能打出来，`->` 在任何键盘上直接可打。
> 全角箭头 `→` 是"全角标点"里**唯一被正式承认为语法符号**的字符（其余全角标点自动按半角处理）；
> 但不要写成全角减号夹着的 `－>`、也不要写成中文破折号 `—>`。

### 2.2 步骤的形态

一个步骤必须是下面**四种合法形态**之一（详细对照表见第 3 节）：

**(a) 裸函数名**：`-> 排序`。流经的值自动作为这个函数的**第一个参数**。
因为是单参数调用，所以 `-> 排序` 等价于 `排序(流经值)`。

```saho
print([3, 1, 2] -> 排序)          # [1, 2, 3]
print([1, 2, 3] -> 反转)          # [3, 2, 1]
print("你好世界" -> 长度)          # 4
```

**(b) 成员函数**：`-> 列表.去重()`。流经的值自动作为这个成员调用的**接收者**，
`-> 列表.去重()` 等价于 `流经值.去重()`。
（`列表` 是规范 6.4 里成员函数的书写方式，表示"对当前流过的那个列表调用"。）

```saho
数字们 = [3, 1, 3, 2]
数字们 -> 列表.去重()             # 就地去掉重复；这一步返回 空值
print(数字们)                    # [3, 1, 2]——原变量已经被就地改好了

小猫 = { "名字": "咪咪", "饥饿": 0 }
小猫 -> 字典.删除("饥饿")          # 就地删除键；这一步返回 空值
print(小猫)                      # {"名字": "咪咪"}
```

> **成员函数步骤的返回值提醒**：规范规定"成员函数一律原地修改、返回 `空值`"。
> 所以 `去重()`、`删除(...)` 作为管道步骤时，**它交出的值是 `空值`**，
> 而它要修改的那个对象是**流经值本身**（已经被就地改好了）。
> 因此成员函数步骤通常放在管道的**最后一步**，或者只当一条表达式语句来用；
> 如果你还想继续用这个值，请继续使用**原来那个变量**。

**(c) 带参数的调用，且调用里不含 `它`**：`-> 取(0, 2)`。
流经的值自动**插入为第一个实参**，于是 `-> 取(0, 2)` 等价于 `取(流经值, 0, 2)`。

```saho
print([1, 2, 3, 4] -> 取(0, 2))          # [1, 2]
print([3, 1, 2] -> 排序(降序: 真))        # [3, 2, 1]——命名实参照常写在后面
print(["小", "石", "头"] -> 连接("·"))    # 小·石·头
```

规则只有一条：**流经值插到最前面**。所以你写 `-> 取(0, 2)`，而不是 `-> 取(它, 0, 2)`；
后者虽然也能跑（见形态 d），但多写了 `它`，没有必要。

**(d) 含有 `它` 的表达式**：在这一步里，`它` 就是**此刻流经的那个值**。

```saho
print("95" -> 数(它))                # 95——它 = "95"
print(3 -> 它 * 2)                   # 6
print([1, 2, 3] -> 它 * 2)           # [1, 2, 3, 1, 2, 3]——列表重复
print(3 -> 函数(x) => x * 2)         # 6——匿名函数步骤
```

其中**匿名函数步骤**要单独说明：`-> 函数(x) => x * 2` 里，
**管道流经的值作为这个匿名函数的唯一实参传入**，所以 `x` 就是流经值。
它和 `-> 它 * 2` 算出来一样，区别是：

- 想给流经值起个更清楚的名字（尤其是参数不止一次出现时），用匿名函数步骤；
- 只在一处用到流经值，用 `它` 更短。

> **小提示**：规范 4.3 第 7 条规定"匿名函数体延伸到最右"。
> 所以匿名函数步骤后面**还有别的步骤**时，建议给函数体加括号：
> `-> 函数(x) => (x * 2 + 1)`。这样"函数体到哪里结束"一眼可见，不会和后面的 `->` 打架。

**(e) 其他裸值：报错。** 步骤既不是函数调用、又不含 `它`，就会被明确报错，并给出改法：

```text
第 5 行：管道步骤不能是一个裸值 5。步骤要么是函数调用，要么是含有 它 的表达式。
line 5: a pipeline step cannot be a bare value 5. Use a function call, or an expression containing 它.
  提示：想打印它，写 -> 打印；想把它原样传过去，写 -> 它；想改成别的值，写 -> 数(它)。
```

### 2.3 管道是表达式

管道不是语句，它和 `1 + 2`、`"你好"` 一样是**表达式**，因此可以用在任何能放表达式的地方。

**赋给变量**：

```saho
x = [1, 2] -> 长度
print(x)                     # 2
```

**当作实参**：

```saho
print([1, 2, 3] -> 反转)       # [3, 2, 1]
print(排序([5, 3, 1] -> 反转))  # [1, 3, 5]
```

**放进插值**：

```saho
print("长度是 {[1, 2, 3] -> 长度}")          # 长度是 3
print("最大是 {[3, 9, 2] -> 最大值}")        # 最大是 9
```

**当作返回值**：

```saho
函数 分数行(分数们)
    返回 分数们 -> 排序(降序: 真) -> 连接("、")
完毕

print(分数行([88, 95, 72]))     # 95、88、72
```

因为管道是表达式，它**不会**引入新的块结构：管道里没有 `完毕`、也没有花括号，
它就是**一行表达式**（把整条管道包在一对括号里，还可以折成几行写，见 7.4）。

### 2.4 优先级：管道最低

**管道是优先级最低的运算符**，低于所有算术、比较、逻辑运算。这带来两条结论：

**结论一：管道左边的算术先算完，再整块流进管道。**

```saho
x = 1 + 2 -> 文本
print(x)          # 3——x 是文本 "3"：先把 1 + 2 算成 3，再流进 文本
print(x + "!")    # 3!——x 是文本，所以能和 "!" 拼接
```

**结论二：想把管道的产物再拿去做算术，必须给管道加括号。**

```saho
print([1, 2, 3] -> 求和)          # 6
print(([1, 2, 3] -> 求和) + 1)    # 7——括号把管道和 +1 分开了

# 不推荐、也容易看错的写法：
# [1, 2, 3] -> 求和 + 1     # 这一步的内容是 求和 + 1，不是合法步骤，会报错
```

第二条也可以换个写法，让管道自己多走一步：

```saho
print([1, 2, 3] -> 求和 -> 它 + 1)   # 7——最后一步是含 它 的表达式
```

**步骤内部是普通表达式**，优先级照规范 3.2 走：

```saho
print([1, 2, 3, 4] -> 取(1, 1 + 2))     # [2, 3]——步骤内部先算 1 + 2
```

**为什么要把管道定成最低？** 为了让"数据从哪来"一眼看清：
`1 + 2 -> 文本` 里的入口是整个 `1 + 2`，而不是孤零零的 `2`。
拿不准的时候，**加括号永远不会错**。

### 2.5 作用域：`它` 只管当前这一步

- `它` 在**当前步骤内部**指"此刻流经的值"；
- 出了这一步，`它` 就失去这个含义，**不会影响管道外面**；
- 每一步都有自己的 `它`，同一个符号在不同步骤里指的值**不同**。

```saho
结果 = [1, 2, 3] -> 它 * 2 -> 长度
print(结果)      # 6
# 第一步的 它 是 [1, 2, 3]，算出 [1, 2, 3, 1, 2, 3]
# 第二步的 它 是 [1, 2, 3, 1, 2, 3]，算出长度 6
```

`它` **不是关键字**（所以关键字账本仍然是 20 个），只是"管道步骤里一个有特殊含义的名字"。
把它当普通变量名使用是合法的，但会让人误会，**强烈不建议**：

```saho
它 = "外层的它"        # 合法，但请别这么写

结果 = [1, 2, 3] -> 长度
print(它)              # 外层的它——管道步骤里的 它 与它毫无关系
print(结果)            # 3
```

> 记住一句话：**`它` 是"这一节管道里流过的东西"，出了这一节就不认识你。**

### 2.6 从左到右流动，错误可被接住

一条管道严格**从左到右**依次执行，前一步的产物就是后一步的输入：

```
值 -> f -> g -> h     等价于     h(g(f(值)))
```

任何**一步**抛出的错误，都和普通函数调用出错完全一样，
会被最近的 `尝试/接住` 接住（D8），错误信息里也带着出错的行号：

```saho
尝试
    总数 = ["95", "不是数"] -> 变换(函数(x) => 数(x)) -> 求和
    print(总数)
接住 错误信息
    print("出问题了：{错误信息}")
完毕
```

输出会类似：

```text
出问题了：文本 "不是数" 不是数字。
```

> 管道**没有**"短路"这一说：从左到右每一步都要真的跑一遍。
> 想跳过某一步，请在步骤函数里自己用 `如果` 判断（把逻辑写进具名函数）。

### 2.7 与字典、函数结合的推荐模式

管道最常用的搭档是**高阶函数**——"接收一个函数当参数"的函数。
规范推荐把这类帮助函数写成 `变换(列表, 函数)`、`过滤(列表, 函数)` 这样的形式，
放在 **stones 包**里复用。它们的约定是：

| 帮助函数 | 签名 | 作用 |
|---|---|---|
| `变换` | `变换(列表, 函数)` | 对每个元素调用一次函数，返回**新列表** |
| `过滤` | `过滤(列表, 函数)` | 只留下"函数返回真"的元素，返回**新列表** |
| `归约` | `归约(列表, 初始, 函数)` | 从头到尾把元素"合"成一个值 |

它们的共同点：**数据放第一个参数**。这样写，正是为了配合管道——
流经值会自动插到第一个参数的位置，于是 `-> 过滤(函数(x) => x >= 60)`
就自然读成"把流过的列表按这个条件过滤一遍"。

**自己写一个 `过滤`，配合管道使用**（这就是 stones 包里的标准写法）：

```saho
# 文件 stones/列表工具.saho —— 顶层只放定义
函数 过滤(数据, 判断)
    保留 = []
    for 元素 于 数据
        如果 判断(元素)
            保留.添加(元素)
        完毕
    完毕
    返回 保留
完毕

函数 变换(数据, 映射)
    结果 = []
    for 元素 于 数据
        结果.添加(映射(元素))
    完毕
    返回 结果
完毕
```

装好之后，主程序这样用：

```saho
用 "列表工具" 引入

分数们 = [95, 58, 72, 88, 60]

及格排行 = 分数们 -> 列表工具.过滤(函数(x) => x >= 60) -> 排序(降序: 真)
print(及格排行)     # [95, 88, 72, 60]

加五分 = 分数们 -> 列表工具.变换(函数(x) => x + 5) -> 列表工具.过滤(函数(x) => x >= 90)
print(加五分)       # [100, 93]
```

字典同样可以流。字典流进 `列表(...)` 会得到**键的列表**：

```saho
用户 = { "名字": "小明", "年龄": 12, "城市": "杭州" }

一句话 = 用户 -> 列表 -> 排序 -> 连接("、")
print(一句话)     # 名字、城市、年龄（文本按 Unicode 码位排序）
print(用户 -> 列表 -> 长度)     # 3
```

## 3. 步骤四种形态对照表

| # | 形态 | 写法示例 | 流经值去哪里 | 等价于 | 说明 |
|---|---|---|---|---|---|
| 1 | 裸函数名 | `-> 排序` | 作为函数的第一个（唯一）实参 | `排序(流经值)` | 最常用；函数得是单参数，或其余参数都有默认值 |
| 2 | 成员函数 | `-> 列表.去重()` | 作为成员调用的接收者 | `流经值.去重()` | 原地修改，返回 `空值`；适合放管道末尾 |
| 3 | 带参数的调用（不含 `它`） | `-> 取(0, 2)` | 插入为**第一个实参** | `取(流经值, 0, 2)` | 命名实参照常写在位置实参之后 |
| 4 | 含 `它` 的表达式 | `-> 数(它)` / `-> 它 * 2` / `-> 函数(x) => x * 2` | 就是 `它` 本身 | `数(流经值)` 等 | 匿名函数步骤里，流经值是**唯一实参** |
| — | 其他裸值 | `-> 5` | — | **报错** | 提示你改用函数调用或含 `它` 的表达式 |

**怎么选形态？** 一张对照思路：

| 你想做的事 | 用哪种形态 | 例子 |
|---|---|---|
| 调用一个现成的单参数函数 | 形态 1 | `[3, 1, 2] -> 排序` |
| 就地改一个列表 / 字典 | 形态 2 | `数字们 -> 列表.去重()` |
| 调用一个还需要别的参数的函数 | 形态 3 | `[1, 2, 3, 4] -> 取(0, 2)` |
| 临时算一个小表达式 | 形态 4（`它`） | `3 -> 它 * 2` |
| 一个小动作只想写一次、不想起名字 | 形态 4（匿名函数） | `[1, 2] -> 函数(x) => x + 1` |

**形态 3 与形态 4 的边界**：调用里**只要写了 `它`**，流经值就由 `它` 决定，
**不再自动插到最前面**。所以 `-> 取(0, 2)` 和 `-> 取(它, 0, 2)` 结果相同但写法不同；
规范推荐**不含 `它` 时不写 `它`**，让 `-> 取(0, 2)` 保持干净。

## 4. 与函数组合的关系

管道**没有**发明新的调用语义，它只是**自动帮你穿针引线**：

```
值 -> f -> g -> h      就是      h(g(f(值)))
```

把它和数学里的复合函数 `h(g(f(x)))` 对照着看，会立刻明白：
**管道从外往里读，就是函数从里往外算。** 管道的全部工作，就是把这层嵌套"摊平"成一条直线。

由此可以推出三条实用结论：

**结论一：管道里流的每一步，都是一个普通的函数调用。**
所以规范里关于函数的一切规则，在管道里原样成立——参数个数要对、类型要匹配、
错误可以被接住、函数可以来自内置、来自 stones、也可以是自己写的。

**结论二：管道里能当步骤的东西，本质都是"函数值"。**
函数是值（D5），所以你可以先把步骤存起来：

```saho
翻倍 = 函数(x) => x * 2
加一 = 函数(x) => x + 1

print([1, 2, 3] -> 变换(翻倍) -> 变换(加一))     # [3, 5, 7]
```

也可以把一整条管道包成一个函数，随时复用：

```saho
函数 清洗(数据)
    结果 = 数据 -> 过滤(函数(x) => x != "") -> 变换(函数(x) => 修剪(x))
    结果 -> 列表.去重()      # 成员函数单独走一条管道：就地去重，返回 空值，所以不接在赋值里
    返回 结果
完毕
```

**结论三：管道是"数据的顺序"，函数是"加工的单元"，两者分工明确。**
把加工写成函数，把顺序写成管道——这正是"函数是值的直接应用"（D5）最自然的用法：
管道不生产新能力，它只是**把已有的函数按顺序接起来**。

> 换个角度说：中间变量写法是"手工穿针引线"，嵌套写法是"线绕成一团"，
> 管道写法是"让针自己走"。三种写法的**语义完全相同**，管道只是最省心的那一种。

## 5. 在后端与前端都能用

管道是**语言结构**，不是某个宿主的特性。所以它在两侧**行为一致**：

| 运行方式 | 宿主 | 管道支持 |
|---|---|---|
| `sahou run 程序.saho` | Go 解释器（后端） | ✅ 支持 |
| `sahou build 页面.saho -o 页面.js` | 卅 → JS 转译器（前端） | ✅ 支持 |
| REPL（`卅`） | Go 解释器 | ✅ 支持 |
| VS Code 扩展（`Alt+S`） | 调 Go 解释器 | ✅ 支持 |

**为什么两侧一定一致？** 因为管道在**语法树这一层**就被展开成普通函数调用，
解释器和转译器复用**同一套**词法分析与语法分析。
换句话说，走到"求值/生成代码"那一步时，管道已经不存在了——
它变成的正是你手写嵌套调用会得到的同一棵树。因此：

- **不新增内置函数**：管道不占名额（写作时 29 个；现 30 个，增量与管道无关）；
- **不新增关键字**：20 个一个不多；
- **不新增运行时**：`sahou build` 的产物里没有"管道运行时"这种东西。

**后端示例（`sahou run`）**：

```saho
用 "随机" 引入

函数 掷三次()
    结果 = []
    for i 于 从a到b(1, 4)
        结果.添加(随机.数(1, 6))
    完毕
    返回 结果 -> 连接("、")
完毕

print(掷三次())     # 例如 4、6、6
```

**前端示例（`sahou build` 之后在浏览器里跑）**：

```saho
函数 刷新(事件)
    条目们 = 页面.取全部(".条目")
    数目 = 条目们 -> 长度
    页面.置文本(计数, "{数目} 条")
完毕
```

也可以直接把管道写进插值：

```saho
函数 刷新(事件)
    页面.置文本(计数, "{页面.取全部(".条目") -> 长度} 条")
完毕
```

两种写法在浏览器里都能跑，因为转译器把管道展开时，用的就是页面模块的普通调用。

## 6. 常见管道配方

下面六个配方覆盖日常八成场景，可以直接抄。

### 配方一：打印调试——看一眼，但别打断流动

`打印` 会打印并返回 `空值`，直接把 `-> 打印` 放进管道会把后面的值变成 `空值`。
所以调试时写一个"看一眼就原样放行"的小函数：

```saho
函数 看看(值)
    打印(值)
    返回 值
完毕

结果 = 从a到b(1, 6) -> 变换(函数(x) => x * x) -> 看看 -> 求和
print(结果)
```

输出：

```text
[1, 4, 9, 16, 25]
55
```

### 配方二：数长度

```saho
print([3, 1, 2] -> 长度)               # 3
print("你好世界" -> 长度)               # 4
print({"名字": "咪咪", "饥饿": 0} -> 长度)   # 2
```

### 配方三：取一段

`取(序列, 起, 止)` 是**含起点、不含终点**（半开区间）。流经值自动插到最前面：

```saho
print([10, 20, 30, 40, 50] -> 取(1, 4))    # [20, 30, 40]
print("上海自来水" -> 取(0, 2))             # 上海
```

### 配方四：连接成一句话

```saho
print(["小", "石", "头"] -> 连接("·"))       # 小·石·头
print([1, 2, 3] -> 连接("-"))                # 1-2-3
```

### 配方五：变换每个元素

```saho
分数们 = [95, 58, 72]

加五分 = 分数们 -> 变换(函数(x) => x + 5)
print(加五分)     # [100, 63, 77]

平方 = 分数们 -> 变换(函数(x) => x * x)
print(平方)       # [9025, 3364, 5184]
```

### 配方六：过滤 + 排序 + 截取 + 连接（一条龙）

```saho
分数们 = [95, 58, 72, 88, 60, 45, 100]

光荣榜 = 分数们 -> 过滤(函数(x) => x >= 60) -> 排序(降序: 真) -> 取(0, 3) -> 连接("、")
print("前三名：{光荣榜}")     # 前三名：100、95、88
```

> **配方组合的诀窍**：把 `变换(函数)` 想成"每个元素都过一遍机器"，
> 把 `过滤(函数)` 想成"门口的筛子"，把 `排序` / `取` / `连接` 想成"整理和打包"。
> 一条好的管道，读起来应该像一句在描述流程的普通话。

## 7. 常见错误

### 7.1 步骤不是函数

最典型的是往管道里塞一个裸值：

```saho
print([1, 2, 3] -> 5)     # 错了
```

报错会直接告诉你怎么改：

```text
第 1 行：管道步骤不能是一个裸值 5。步骤要么是函数调用，要么是含有 它 的表达式。
line 1: a pipeline step cannot be a bare value 5. Use a function call, or an expression containing 它.
  提示：想打印它，写 -> 打印；想把它原样传过去，写 -> 它；想改成别的值，写 -> 数(它)。
```

一个不那么明显的情况：**步骤里写了运算，但那不是合法步骤**。

```saho
print([1, 2, 3] -> 求和 + 1)     # 错了：这一步的内容是 求和 + 1
```

正确写法二选一：

```saho
print([1, 2, 3] -> 求和 -> 它 + 1)      # 7
print(([1, 2, 3] -> 求和) + 1)          # 7
```

### 7.2 忘了 `它`

管道里"此刻流过的值"只有一个名字：`它`。写成别的名字，轻则报错，重则用错值：

```saho
print(3 -> x * 2)     # 错了：x 没有定义
```

```text
第 1 行：变量 "x" 还没有定义。你是不是想写 "它"？
line 1: name "x" is not defined. Did you mean "它"?
  提示：管道步骤里，"此刻流过的值"叫 它；也可以写 函数(x) => ...，此时 x 就是流经值。
```

正确写法：

```saho
print(3 -> 它 * 2)                # 6
print(3 -> 函数(x) => x * 2)      # 6
```

> **最危险的情况**：外面**正好**有一个叫 `x` 的变量。
> 这时 `3 -> x * 2` 不会报错，它会悄悄用外面那个 `x`，结果完全不是你想的。
> 所以请养成习惯：**步骤里要引用流经值，永远写 `它`，或者用匿名函数自己的参数名。**

### 7.3 步骤内写多语句——应该改用函数

匿名函数**只能写一句表达式**，所以下面这种写法不成立：

```text
# 错：步骤里塞不下 如果 / 遍历 / 多句话
结果 = 数据 -> 函数(x) => 如果 x > 0 ... 完毕
```

正确做法：把那段逻辑写成**具名函数**，再用裸函数名当步骤：

```saho
函数 规范化(原文)
    干净的 = 修剪(原文)
    如果 长度(干净的) == 0
        返回 "（空）"
    完毕
    返回 转小写(干净的)
完毕

结果 = [" 苹果 ", "", " 香蕉"] -> 变换(规范化)
print(结果)     # ["苹果", "（空）", "香蕉"]
```

### 7.4 其他容易踩的点

| 现象 | 原因 | 改法 |
|---|---|---|
| `a - > b` 报错 | `-` 和 `>` 之间不能有空格 | 写成 `a -> b` 或 `a -> b` |
| 把 `->` 当成了 `=>` | 两者含义不同 | `=>` 只属于匿名函数；管道用 `->` |
| `[1,2,3] -> 求和 + 1` 报错 | 步骤被解析成 `求和 + 1` | 加括号，或写成 `-> 求和 -> 它 + 1` |
| `-> 取(它, 0, 2)` 看着别扭 | 写了 `它` 后流经值**不再自动插入**，`它` 就是第一个实参——结果和 `-> 取(0, 2)` 一样，只是多写了 | 直接写 `-> 取(0, 2)`，让流经值自动插入 |
| 成员函数步骤之后再流，后面步骤报"空值 没有成员" | `去重()` / `删除(...)` 返回 `空值` | 把成员函数步骤放在末尾，或继续用原变量 |
| 管道太长一行放不下 | 换行是语句分隔符 | 用一对括号把整条管道包起来再折行，或者改用中间变量 |
| 跨行时忘了括号 | 换行把管道切成了两条语句 | 折行的管道必须整体在 `(` `)` 里 |

**一条总口诀**：**入口在左，步骤在右；步骤四形态，流经值叫 `它`；拿不准就加括号。**

## 8. 与设计原则自检

管道必须放进 卅 既有的十条设计决策里自检，`->` 才算"加得值"。

| 决策 | 管道是否破坏它 | 具体落点 |
|---|---|---|
| **D5 函数是一等公民，但定义方式只有一种** | **否，而且是它的直接应用** | 管道里没有新的"可调用物"：每一步都是普通函数调用。匿名函数仍然只有 `函数(x) => 表达式` 一种写法；管道不做 `lambda`、不做方法链、不做管道运算符重载。它就是"把函数按顺序接起来"——**函数是值，管道是值的直接应用**。 |
| **D2 双语关键字 / 关键字账本** | 否 | `->`（全角别名 `→`）是**运算符/标点**，不是关键字；`它` 也**不是关键字**，只是**管道步骤里的一个特殊名字**。所以关键字仍然是 **20 个**，中英对照表一行都不用改。 |
| **D1 `end`/`完毕` 收尾，块结构显式** | 否 | 管道是**表达式**，不是块：它没有块头、没有收尾词、里面也不能写多语句。折叠长管道时用括号 `(` `)`，而不是花括号 `{ }`——不会与"两种块风格不要混用"的规矩打架。 |
| **D9 标准库极小且全是函数（≤30）** | 否 | 管道不新增任何内置函数（写作时 29 个；现为 30 个，增量来自 v4.1 位置/find，与管道无关）。`变换` / `过滤` 这类帮助函数是**普通用户函数**，住在 stones 包里，不占内置名额。 |
| **D8 错误处理极简：尝试/接住** | 否 | 管道任何一步的报错都走同一条错误通道，可被 `尝试/接住` 接住；没有为管道新增错误类型、没有 `finally`。 |
| **D10 报错信息必须说人话** | 是**加分项** | 裸值步骤、忘记 `它` 都能给出**针对性**的中文提示与改法，而不是一句笼统的"语法错误"。 |
| **更少的概念，更早的成就感** | 是**加分项** | 管道让"筛选、变换、排序、取一段、拼成句子"这个新手最常做的组合，从四行中间变量变成一行；概念只增加"`->` 和 `它`"两个名字。 |
| **结构要显式，不要靠排版** | 是**加分项** | 执行顺序不再藏在括号嵌套里，而是**写在纸面上从左到右**——没有隐式求值、没有惰性、没有魔法。 |

**最后强调两条边界**：

1. **管道不会改变任何东西的语义。** `值 -> f -> g` 和 `g(f(值))` 是同一个意思、
   同一棵语法树、同一套错误行为。管道是"另一种写法"，不是"另一种运行方式"。
2. **`它` 不是关键字，`->` 也不是。** 它们都不进 21 个关键字的账本；
   `它` 只在**步骤内部**才是"流经值"这个名字，出了那一步就什么都不是。
   这正是 卅 一贯的态度：**能用已有结构表达的，就绝不新造一个词。**

## 附：管道速记卡

```text

符号       ->（全角）  ≡  ->（ASCII）

           ② 成员函数        -> 列表.去重()      ≈ 流经值.去重()（原地改，返回空值）
           ③ 调用（不含它）  -> 取(0, 2)        ≈ 取(流经值, 0, 2)
           ④ 含 它 的表达式  -> 数(它) / -> 它*2 / -> 函数(x) => x*2
           ⑤ 其他裸值        -> 5               -> 报错并给改法
本质       值 -> f -> g -> h   ≡   h(g(f(值)))
优先级     最低（低于算术/比较/逻辑）；想参与运算请加括号
作用域     它 只管当前这一步，不影响外面
性质       表达式：可赋值、可当实参、可放进插值、可当返回值
错误       任何一步出错，都能被 尝试/接住 接住
账本       关键字 20 个不变、内置函数 29 个不变、类型 5 种 + 空值不变
```
