## 1. 语言定位

### 1.1 名字

语言名为中文 **卅**，英文名 **卅**，源文件后缀 **`.saho`**。这个名字本身就是设计态度的宣言：Python 是一条蟒蛇，庞大、有力、能吞下整个工程；"卅"是"三十"的古体字，三横一竖，四画写完，小、直、一眼就能写完。它不打算长得比蟒蛇更大，只想**更小、更简单**。第三方库生态与包管理器留待 v2 再命名，v1 不引入任何安装概念。

### 1.2 一句话定位

> **卅 是"比 Python 更简单一点的入门语言"——保留 Python 的动态、灵活、可读，砍掉新手最容易踩坑的部分。**

这句话有三个关键词，缺一不可：

- **动态**：变量不需要声明类型，随时可以放任何值，学习时不必先理解类型系统。
- **灵活**：想写三行的程序就写三行，不必为了"正规"而包裹在类或函数里。
- **可读**：代码首先是给人看的，其次才是给机器执行的。

而"砍掉"同样是定位的一部分。卅 不是 Python 的超集，也不是 Python 的方言，它是**一条更窄的路**：窄路上没有悬崖，新手可以放心往前走。

### 1.3 目标用户

- **零基础初学者**：第一次接触编程，还不知道"变量""函数"是什么的人。
- **中小学编程教育**：课堂时间有限，老师不能把一半课时花在解释缩进和浮点误差上。
- **从自然语言过渡到代码的人**：习惯用中文思考和表达，希望先建立编程思维，再逐步接触英文关键字。

这三类用户有一个共同点：**他们的挫败感阈值很低，而挫败感的主要来源不是"逻辑难"，而是"环境与语法在跟我作对"**。卅 的全部设计决策，都是围绕这一点展开的。

### 1.4 非目标

卅 **明确不追求**以下方向，这些方向留到后续版本或交给别的语言：

- **高性能计算**：v1 是树遍历解释器，速度不是指标。
- **大型工程**：没有模块系统（v1）、没有包管理、没有类型检查。
- **并发编程**：没有线程、没有协程、没有 async/await。

这不是"暂时做不到"，而是**主动的边界**。一门想让新手安心的语言，必须敢于说"这不是我现在要解决的问题"。

### 1.5 实现路线

- **v1：树遍历解释器**。先保证简单、正确、报错清楚，性能放在最后。
- **v2：考虑字节码 VM**。当语言形态稳定、有真实用户之后，再换发动机。

## 2. 设计哲学

十条设计决策（D1–D10）不是零散的点子，它们服务于六条一以贯之的原则。

### 原则一：更少的概念，更早的成就感

新手最大的敌人是"概念总量"。卅 反复做减法：一种数、五种类型、两种循环、一种错误处理、一种函数定义。目标是在第一节课结束时，学生能写出一个**完整可运行**的小程序，而不是还在背诵语法名词。

### 原则二：结构要显式，不要靠排版

程序的块结构应该由**明确的词**标记，而不是由**空白字符**暗示。看一段代码，应该一眼看出"这里结束了"，而不是靠数空格。

### 原则三：语言不该因为格式问题惩罚学习者

混用空格和 Tab、多缩进一格、少缩进一格——这些都是编辑器的问题，不是学习者的问题。卅 不允许这类问题升级为"程序无法运行"。

### 原则四：母语友好，但不是母语独占

关键字提供中英双份。全中文能写，全英文能写，混着写也能写。学习者可以用中文建立概念，再平滑迁移到英文——**而不是先过一道英语关，才能开始学编程**。

### 原则五：报错即教学

一条报错信息应该同时回答三个问题：**哪里错、为什么错、怎么改**。报错信息是语言和用户之间最重要的一次对话，不能浪费在 `SyntaxError: invalid syntax` 这样的冷冰冰的短语上。

### 原则六：渐进披露

语言要能"只用一小部分就写出有用的东西"。不需要先懂类、不需要先懂异常继承树、不需要先懂模块。随着需要，再逐步发现更多能力。

## 3. 十条设计决策逐条展开

### D1 用 `end` 关键字收尾，不用缩进和花括号

**决策**：块结构由 `end`（或 `完毕`）收尾，参考 Lua/Ruby。

**动机**：Python 的缩进块是新手最大的错误来源——混用空格与 Tab、缩进层级错位、复制粘贴后缩进错乱。这类错误的共同特点是：**它跟程序逻辑毫无关系，却会让程序完全无法运行**。对于初学者，这会造成一种致命的误解——"编程很难，我连格式都搞不对"。

**规则**：任意缩进、空格 Tab 混用都不报错。缩进在 卅 中**只是给人类看的排版**，不参与语法。

```
if x > 3
    print("大")
else
    print("小")
end
```

上面这段代码即使把 `print("大")` 顶格写，语义也完全不变。

**代价与取舍**：`end` 会让代码比 Python 多出一行一行的收尾词，深层嵌套时收尾会比较密集。我们认为这个代价是值得的：多打一个词是**键盘成本**，缩进错误是**认知成本**，而对新手来说，认知成本远比键盘成本昂贵。同时 `end` 让"块从哪里开始、到哪里结束"变成一个可以被指针指着的具体位置，讲解和调试都更容易。

### D2 双语关键字：中文英文都能写

**决策**：每条语句提供等价的中文关键字，程序可以全中文书写，也可以全英文，或混用。

| 英文 | 中文 | | 英文 | 中文 |
|---|---|---|---|---|
| `if` | `如果` | | `fn` | `函数` |
| `elif` | `又如` | | `return` | `返回` |
| `else` | `否则` | | `for` | `遍历` |
| `while` | `当` | | `in` | `于` |
| `end` | `完毕` | | `and` | `并且` |
| `true` | `真` | | `or` | `或者` |
| `false` | `假` | | `not` | `非` |
| `null` | `空值` | | `let` | `设` |
| `try` | `尝试` | | `catch` | `接住` |

（`let/设` 是可选的变量赋值前缀，写不写都可以。）

这是 v1 的**全部 18 个关键字**，与《02-语言规范.md》2.6 节逐行一致。
刻意不在清单里的：`break`/`continue`（用布尔标志提前结束循环）、`class`、
`import`、`raise`（用内置函数 `抛出("消息")`）、`finally`——少一个关键字，就少一节课。

**动机**：语言不该成为一道额外的门槛。中文关键字让学习者把注意力放在**逻辑**上；同时保留英文关键字，让学到的东西可以无缝迁移到 Python、JavaScript 等真实世界的语言。混用也是允许的，因为真实的中文编程者本来就习惯"中文思路 + 英文术语"。

**示例**（中英混用是合法的，也是被鼓励的过渡形态）：

```
设 计数 = 0
while 计数 < 3
    计数 = 计数 + 1
完毕

for i 于 从a到b(1, 4)
    print(i)
完毕
```

**注意**：双语关键字是**同一套语法的两种拼写**，不是两套语言。`if` 与 `如果` 功能完全等价，编译器在词法阶段就把它们归为同一个记号（token）。

### D3 用户只看到一个"数"类型

**决策**：卅 只有一种**数**（number）。内部自动按需用整数或小数表示。

**动机**：Python 里 `int` / `float` / `10` / `10.0` / 精度问题，是新手噩梦的经典组合。最典型的困惑是：

- `10 / 3` 在 Python 2 里得 `3`，在 Python 3 里得 `3.333...`，为什么？
- `0.1 + 0.2` 为什么不等于 `0.3`？
- `10` 和 `10.0` 是同一个东西吗？为什么要写两种？

这些问题对**第一周的学习者**来说毫无价值，却会消耗大量课堂时间。卅 的答案是：**让用户根本看不到这个区分**。

**规则**：

- 用户永远只写 `10`、`3.5`。
- `10 == 10.0` 成立——因为根本不存在两个类型，只有一种数。
- `10 / 3` 得 `3.3333...`：**除法永远是真除法**，不做整除特例。
- 整数精确运算在内部仍然保证（计数、索引不出错）。也就是说，"只有一个类型"是**给用户看的表象**，实现层面依然会区分表示形式，以保证 `列表[2]` 这样的索引和循环计数永远精确。

```
print(10)          # 10
print(3.5)         # 3.5
print(10 == 10.0)  # 真
print(10 / 3)      # 3.3333...
```

### D4 只有 5 种数据类型

**决策**：数（number）、文本（string）、列表（list）、字典（dict）、布尔（bool），外加一个空值（null/空值）。

**动机**：数据类型的选择题是新手入门的第二大障碍。"我该用列表还是元组？""集合和列表有什么区别？""什么时候用字节？"——这些问题在初学者写不出十行程序时毫无意义。

**规则**：

- 没有元组、集合、字节、复数。
- 需要集合语义时用列表 + `列表.去重()`。
- 没有类（class）——v1 用字典 + 函数组合表达结构化数据。

```
小猫 = { "名字": "咪咪", "饥饿": 0 }
```

**代价与取舍**：砍掉元组意味着某些"不可变数据"的表达要退化；砍掉集合意味着去重需要显式调用。但我们判断，这些损失远小于"少背四个类型名词"带来的收益。而砍掉类是最重要的一条：**面向对象是强大的抽象工具，但它不是编程的起点**。用字典存数据、用函数操作字典，足以表达绝大多数入门阶段的程序，而且没有 `self`、没有继承、没有构造函数的语法负担。

### D5 函数是一等公民，但定义方式只有一种

**决策**：函数是一等公民（可以赋值、传参、返回），但定义方式只有一种。

```
函数 加(a, b)
    返回 a + b
完毕
```

**规则**：

- 没有 lambda（多种写法）、没有装饰器、没有方法重载。
- 匿名函数只有一个语法：`函数(参数) => 表达式`。

**动机**：一等公民让函数可以像数据一样被传递，这是编程思维的重要一步；而"定义方式只有一种"保证了阅读代码时不需要先做语法识别。Python 提供了 `def`、`lambda`、装饰器语法 `@`、默认参数、`*args`/`**kwargs` 等一整套工具，对初学者而言这是一片需要记忆的沼泽。卅 只保留 **`fn`/`函数`** 一个入口，加上一个箭头形式的匿名函数作为补充。

**代价与取舍**：没有装饰器意味着无法用优雅的语法做横切关注点（如缓存、日志）。在入门语言的语境下，这些能力用普通函数包装即可实现，不值得为它引入一个 `@` 符号和一套元编程心智。

### D6 字符串插值代替拼接的心智负担

**决策**：用花括号插值，替代字符串拼接。

```
设 名字 = "卅"
print("你好, {名字}!")
```

**规则**：花括号内可以是**任意表达式**。`+` 也能拼接文本，但推荐插值。

**动机**：拼接写法 `"你好, " + 名字 + "!"` 有三个问题：引号与加号交替出现，容易漏写；数字必须手动转换；句子被切碎，读起来不像一句话。插值让"文本"和"模板"统一起来，读代码时能直接读出中文句子的语序。

**示例**：

```
设 单价 = 3.5
设 数量 = 4
print("总价是 {单价 * 数量} 元")   # 总价是 14 元
print("多买一件就是 {单价 * (数量 + 1)} 元")
```

### D7 循环只有两种

**决策**：只有 `for x 于 列表`（`遍历 x 于 列表`）和 `while 条件`（`当 条件`）。

**规则**：

- 没有 `range` 的三参数形式——提供内置函数 `从a到b(步长)` 返回列表，或直接遍历列表。
- 没有列表推导式（这是 Python 语法中最难教的部分之一），需要新列表就写显式循环。

**动机**：Python 的 `range(1, 10, 2)`、`range(len(xs))`、`enumerate`、`zip`、推导式嵌套，构成了初学者最容易混淆的一组用法。卅 把"生成一个序列"变成一个**看得见结果的函数调用**：`从a到b(1, 10)` 就是你可以在屏幕上打印出来的那个列表。而"筛选/变换一个列表"则退回到最朴素的显式循环——写得长一点，但每一步都清楚。

```
# 显式循环构建新列表（替代列表推导式）
设 平方数 = []
for i 于 从a到b(1, 6)
    平方数 = 平方数 + [i * i]
完毕
print(平方数)
```

**代价与取舍**：显式循环比推导式啰嗦，性能也更朴素。我们接受这一点：**推导式省下的是打字时间，付出的是理解时间**，而在入门阶段，理解时间的汇率高得多。

### D8 错误处理极简：尝试/接住

**决策**：只有一种错误处理机制。

```
尝试
    危险操作()
接住 错误信息
    print("出错了: {错误信息}")
完毕
```

**规则**：

- 错误对象就是一个文本（或含 `.消息` 字段的简单字典）。
- 没有 `finally`、没有 `raise` 层级、没有异常类继承树。
- 抛错用内置函数 `抛出("消息")`。

**动机**：Python 的异常体系是一棵需要记忆的树：`Exception`、`ValueError`、`TypeError`、`KeyError`、`IndexError`……新手常常不知道该接住哪一个，于是干脆不处理，或者写一个 `except:` 吞掉一切。卅 只提供"**尝试做一件事，出了问题就接住**"这一个模式，把错误信息当成一句话，而不是一个对象类型。

**为什么不用 `finally`**：`finally` 在入门代码里几乎总是和"文件必须关闭""资源必须释放"绑定，而这些属于后续版本的能力。保留 `尝试/接住` 两段式，结构更短、更易教。

### D9 标准库极小且全是函数

**决策**：不超过 30 个内置函数，全部小写蛇形命名，中英双名。

**规则**：

- 例如 `打印/print`、`读取文件/read_file`、`文本转数/str_to_num`。
- 不引入模块系统——v1 所有内置函数全局可见；v2 再考虑 `用 "xxx" 引入`。

**动机**：一个巨大的标准库对初学者来说不是能力，而是噪音。"我要读一个文件，应该 import 什么？"这个问题本身就该被消除。v1 的做法是：**常用能力全部内置、全局可见、名字一眼能懂**。同时"不超过 30 个"是一条硬性的自我约束——每增加一个内置函数，都要问一句"能不能不加"。

**命名规则**：小写蛇形（`read_file`）保证不出现大小写记忆负担；每个函数同时提供中文名，与 D2 的双语关键字策略一致。简报示例中出现的 `数(文本)` 即为数值转换内置函数，具体命名与完整清单在《02-语言规范.md》中统一固化。

### D10 报错信息必须说人话

**决策**：所有错误消息双语（中文优先），带行号和"你可能是想……"的修复建议。

```
第 3 行：变量 "nmae" 还没有定义。你是不是想写 "name"？
```

**动机**：报错信息是语言与用户之间最频繁的对话。Python 的报错对新手极不友好：`NameError: name 'nmae' is not defined` 只说了"哪里错"，没有说"怎么改"。而**拼写错误**恰恰是新手最高频的错误类型。

**规则**：

1. **中文优先**，英文附后，照顾不同背景的学习者。
2. **必须带行号**，让用户能立刻定位。
3. **必须给建议**：拼写错误给最接近的候选名，类型错误说明期望类型与实际类型，括号缺失说明在第几个字符处不匹配。
4. 报错文本本身使用简单词汇，不出现"未绑定的标识符""词法错误"这类术语。

**示例风格**（示意，具体文案由实现统一）：

```
第 7 行：函数 "从a到c" 还没有定义。你是不是想写 "从a到b"？
第 12 行：不能把 文本 和 数 相加。你可能是想把数字转换成文本，试试 文本(数量)？
```

## 4. 与 Python 的逐项对照表

| 维度 | Python | 卅 | 差异的理由 |
|---|---|---|---|
| 块结构 | 缩进 | `end` / `完毕` | 缩进错误是新手最大错误来源；块边界应显式可见 |
| 关键字 | 仅英文 | 中英双语，可混用 | 降低语言门槛，同时保留向英文生态迁移的路径 |
| 数字类型 | `int` / `float`（还有 `complex`、`Decimal`） | 只有一种**数** | 消除 `int/float` 与精度问题带来的入门困惑 |
| 除法 | `/` 真除，`//` 整除 | `/` 永远是真除法 | 少一个运算符、少一条规则 |
| 数据类型 | 数、文本、列表、元组、字典、集合、布尔、字节、复数…… | 只有 5 种：数、文本、列表、字典、布尔（+ 空值） | 概念数量直接决定入门坡度 |
| 字符串构建 | `+` 拼接、`f"..."`、`.format()` | `"{表达式}"` 插值（`+` 也可用） | 插值读起来就是一句中文 |
| 函数定义 | `def`、`lambda`、装饰器、默认参数、`*args` | 只有 `fn`/`函数`，匿名用 `函数(x) => 表达式` | 定义方式唯一，阅读时无需辨认语法变体 |
| 面向对象 | `class`、继承、多继承、魔法方法 | 无类；字典 + 函数 | 面向对象不是编程的起点 |
| 循环 | `for`、`while`、推导式、`range` 三参数 | `for x 于 列表`、`while 条件` | 循环形态收敛为两种 |
| 序列生成 | `range(起, 止, 步长)` | `从a到b(起, 止, 步长)` 返回列表 | 生成结果可以直接看见、可以打印 |
| 列表变换 | 列表推导式、`map`/`filter` | 显式循环 | 推导式难教难读 |
| 索引取值 | 切片 `xs[1:3]`、负索引 | `取(列表, 起, 止)` | 切片语法符号密集，函数调用更直白 |
| 错误处理 | `try/except/else/finally` + 异常类型树 | `尝试 / 接住 错误信息 / 完毕` | 一种机制，错误信息就是一句话 |
| 主动抛错 | `raise ValueError("...")` | `抛出("消息")` | 不需要构造异常对象 |
| 报错信息 | 英文、术语化、多数无修复建议 | 双语（中文优先）、带行号、带修复建议 | 报错即教学 |
| 标准库 | 庞大、需要 `import` | ≤30 个内置函数、全局可见、中英双名 | 消除"该 import 什么"的噪音 |
| 模块系统 | `import` / `from ... import` | v1 无；v2 才考虑 `用 "xxx" 引入` | 单文件程序是入门的主场景 |
| 类型注解 | 支持 `x: int`、`typing` | 不支持 | 动态语言的入门阶段不需要类型负担 |
| 异步/并发 | `async/await`、`threading`、GIL | 不支持 | 并发不在 v1 目标内 |
| 真值判断 | 空列表、`0`、`""`、`None` 均为假 | 由规范统一定义（见《02-语言规范.md》） | 避免"什么算假"变成记忆题 |
| 执行方式 | 编译成字节码后由 CPython 执行 | v1 树遍历解释器 | 先简单正确，v2 再考虑字节码 VM |
| 性能定位 | 通用、工业级 | 教学、入门 | 目标不同，取舍不同 |

## 5. 砍掉的 Python 特性清单及理由

下面是简报第 4 节列出的**明确砍掉**的特性，逐条给出理由与替代方案。

| 砍掉的特性 | 砍掉的理由 | 在 卅 中的替代 |
|---|---|---|
| **缩进块** | 空格/Tab 混用与层级错位是新手最高频、最无意义的失败来源 | `end` / `完毕` 显式收尾，缩进仅作排版 |
| **类与继承** | `class`、`self`、`__init__`、继承、`super()` 一整套语法与概念，远超入门所需 | 字典 + 函数组合表达结构化数据 |
| **元组 / 集合** | 与列表的差别（可变性、顺序、唯一性）是记忆题，不是思维题 | 统一用列表；去重写 `列表.去重()` |
| **列表推导式** | 嵌套推导式是 Python 语法中最难教、最难读的部分之一 | 显式 `for` 循环逐个构建新列表 |
| **切片语法** | `xs[1:3]`、`xs[:]`、`xs[::-1]` 符号密集、语义多样 | `取(列表, 起, 止)` 函数调用，参数含义写在位置上 |
| **lambda 多种写法** | 与 `def` 并存的第二套函数定义语法，增加识别成本 | 唯一匿名语法 `函数(参数) => 表达式` |
| **装饰器** | `@` 语法与"函数包装函数"的元编程思维，入门阶段无法自解释 | 用普通函数显式包装 |
| **生成器** | `yield`、惰性求值、迭代器协议是抽象概念的叠加 | 直接返回一个列表 |
| **async / await** | 并发不是 v1 的目标；异步语义对初学者是纯负担 | 无（顺序执行） |
| **类型注解** | 动态语言的价值就在于不写类型，注解会引入"必须标注"的误解 | 无，变量直接赋值 |
| **模块系统（v1）** | `import` 会让第一个程序变成"三行代码 + 两行导入"，且涉及文件路径 | 内置函数全局可见；v2 再考虑 `用 "xxx" 引入` |
| **多重继承** | 连有经验的工程师都难以推理，对新手完全是黑魔法 | 无类，自然无继承 |
| **魔法方法** | `__str__`、`__eq__`、`__len__` 等双下划线协议需要理解解释器内部约定 | 用普通函数代替（如 `文本(x)`、`长度(x)`） |
| **可变默认参数陷阱** | "默认值在定义时求值一次"是反直觉语义，会制造难以定位的 bug | 不暴露这种可被误用的默认值语义 |
| **GIL 相关讨论** | 属于实现层的并发话题，与"写出第一个小程序"无关 | 语言文档不涉及；并发能力留待后续版本 |

**没有被砍掉的东西**同样值得说明：动态类型、函数是一等公民、字典与列表、真值判断、字符串插值、`while` 循环、`尝试/接住`——这些是"写出有用程序"的最小必要集合，也是从 卅 迁移到 Python 时可以直接复用的部分。

## 6. 示例速查（与简报第 3 节完全一致）

以下三段程序是本项目其余文档引用示例时的基准写法，**必须逐字一致**。

**示例一：打印九九乘法表**（注意嵌套 `for`、`完毕` 收尾、命名参数 `结尾:`）

```
# 打印九九乘法表
函数 乘法表()
    for i 于 从a到b(1, 10)
        for j 于 从a到b(1, i + 1)
            print("{j}×{i}={i * j}", 结尾: "  ")
        完毕
        print("")
    完毕
完毕

乘法表()
```

**示例二：用字典代替"对象"，用函数操作字典**

```
# 用字典代替"对象"，用函数操作字典
小猫 = { "名字": "咪咪", "饥饿": 0 }

函数 喂食(动物)
    动物["饥饿"] = 动物["饥饿"] - 10
    返回 "{动物["名字"]} 吃饱啦，饥饿度 {动物["饥饿"]}"
完毕

print(喂食(小猫))
```

**示例三：尝试/接住 与 抛出**

```
# 尝试/接住 与 抛出
函数 文本转成绩(文本)
    尝试
        返回 数(文本)
    接住 错误信息
        抛出("成绩必须是数字，收到: {文本}")
```

## 7. 这份设计意味着什么

把 D1–D10 放在一起看，卅 的形象是清晰的：

- 它**故意不完整**。没有类、没有模块、没有并发、没有类型系统，因为完整不是它的目标。
- 它**把语法成本的预算几乎全部花在容错上**：可以为多打一个 `end` 付费，不肯为缩进对齐付费；可以为多写一个循环付费，不肯为读懂一个推导式付费。
- 它**把报错当作产品功能**，而不是失败提示。
- 它**为迁移留了门**：英文关键字、蛇形命名的内置函数、真假值、列表与字典，都是通往 Python 的同一套词汇。

接下来，《02-语言规范.md》会把这里的原则固化为可实现的词法、语法与语义；《03-入门教程.md》会带着零基础读者从安装走到第一个完整程序；《04-编译器技术设计.md》会说明 v1 树遍历解释器的架构与报错机制如何落地。三份文档与本文一样，均以《00-设计决策简报.md》为唯一事实来源。
