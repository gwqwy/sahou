## 1. 浏览器与 JavaScript：为什么需要转译

### 1.1 你写的程序，第一次"长"在屏幕上

在网络模块教程里，你写的程序已经能被别人"用"了：程序一直开着，别人发请求，它回一句文本。
但那还是**一行行文字**。前端要改变的是这件事：

> 你写的程序变成**一个看得见、点得动的页面**：有按钮、有输入框、有会变化的文字。

浏览器是全世界唯一一个"到处都装好了"的图形界面。所以"我写的程序有界面了"这件事，
在 卅 里就等于"我写的程序能在浏览器里跑"。

### 1.2 麻烦在于：浏览器只认一门"外语"

浏览器很能干，但它有一个死规矩：

> **浏览器只会执行 JavaScript，别的什么都不会。**

你写的 `.saho` 文件，浏览器打开来只会当成乱码或者直接下载。这不是 卅 的缺陷，
所有语言都面对同一堵墙——这是浏览器的现实，不由我们决定。

那怎么办？只有两条路。

**路 A：带一个"现场口译员"进浏览器。**
把整个 卅 解释器（连同报错系统与全部内置函数）一起打包发给浏览器，
让它在页面里现场读 `.saho`、现场解释。

**路 B：提前把 `.saho` 整本"翻译"成 JavaScript。**
翻译一次，得到一个普通的 `.js` 文件，浏览器任何时候都能直接跑。

### 1.3 翻译官的比喻

把浏览器想象成一个**只读英文书的读者**，你手里这本书是中文的。你有两种办法：

| 办法 | 对应实现 | 代价 |
|---|---|---|
| 每次都请一个**现场口译员**坐在读者旁边，你读一句他翻一句 | 路 A：浏览器里的 卅 解释器 | 每读一本书都要多带一个人（体积和启动都变慢）；口译员本人也可能翻错，于是"两套语义"开始漂移 |
| **提前请翻译官把整本书译成英文**，读者拿到就是一本英文书 | 路 B：`sahou build` 转译器 | 需要一次"翻译"的工序；但产物是普通英文书，谁都能读、什么时候都能读 |

卅 选择**路 B（提前翻译）**。理由有三条，都很好记：

1. **产物是普通 JavaScript**：任何浏览器、任何静态托管都能跑，除了一个很小的前导库之外**零运行时依赖**。
2. **同一个翻译官，只有一套规则**：转译器复用 v1 的**同一套** 词法分析 → 语法分析 → AST，
   只多接了一个"输出 JavaScript"的后端。所以两台后端的行为被压到最接近，不会各说各话。
3. **报错还是说人话**：生成的文件里每条语句上方都有 `// sahou: 第 N 行` 注释，
   加上 `--source-map`，浏览器控制台里的报错仍然能指回你 `.saho` 的那一行（D10）。

一句话记住：

> **浏览器只认 JavaScript，所以 `sahou build` 就是那个翻译官：
> 它把 `.saho` 译成 `.js`，翻译一次，以后随便跑。**

顺便对照一下：你在网络模块教程第 5.2 节认识的 `网络.自文本` / `网络.到文本`，
是"**JSON 文本 ↔ 卅 值**"之间的两个翻译官；本文的 `sahou build`，
是"**卅 源码 → JavaScript 源码**"之间的翻译官。一个是运行期翻译数据，一个是构建期翻译程序。

### 1.4 翻译官遵守的规则（转译速览）

"翻译"最怕的是**走样**：中文里一句"这个问题我们回头再说"，译成英文不能变成"我们现在就办"。
`sahou build` 的翻译规则是一份公开的契约，下面这张表是最常用的几条
（完整 18 条关键字逐一对应的表格见《05》第 3.3 节）：

| 卅 | 译成 JavaScript | 为什么这么译 |
|---|---|---|
| `完毕` / `end` | `}` | 块收尾一一对应，翻译官**不产生任何额外的块** |
| `如果 条件` | `if (__saho_truthy(条件))` | JavaScript 里 `[]`、`{}`、`"0"` 都算真，而 卅 规定 `[]`、`{}`、`0`、`""` 为假，必须过一层真值包装 |
| `遍历 x 于 列表` | `for (const x of __saho_iter(列表))` | 列表→数组、文本→按字符、字典→按键，统一迭代 |
| `函数 名字(参数)` | `function 名字(参数) { … }` | **中文标识符原样保留**，方便你对照着读 |
| `函数(x) => 表达式` | `(x) => 表达式` | 唯一的匿名写法，两边都是单表达式 |
| `真` / `假` / `空值` | `true` / `false` / `null` | 直接对应 |
| `{ "名字": "咪咪" }` | `new Map([["名字", "咪咪"]])` | **字典译成 `Map` 而不是普通对象**：`Map` 保持插入顺序、允许数作键、没有原型链干扰 |
| `"{x}"` | `` `${__saho_str(x)}` `` | 插值值先归一成文本，所以 `真` 还是"真"，不会变成 JavaScript 的 `true` |
| `a == b` | `__saho_eq(a, b)` | 卅 的列表/字典是**深度相等**，JavaScript 的 `===` 只是引用比较 |
| `%` | `__saho_mod(a, b)` | 余数符号跟随被除数：`-7 % 3` 得 `2`，JavaScript 原生 `%` 得 `-1` |
| 顶层 `返回` | 整个程序包进 `(function () { … })();` | JavaScript 脚本顶层不允许 `return`，包一层就合法了 |

翻译官**明确不做的四件事**（与"砍掉清单"对齐）：不生成 `async`/`await`、不生成 `Promise`、
不生成 `class`、不生成生成器与装饰器。因为这些词在 卅 里**根本没有对应语法**，
翻译的时候永远不需要面对它们。

### 1.5 你要学的新东西只有一样

读到这儿你可能会紧张："前端是不是要学一堆新语法？"

**不是。** 前端给你的是：

- 一条命令：`sahou build`；
- 一个模块：`页面`（14 个成员）。

本文写作时（v1.5）关键字 18 个、内置函数 29 个；此后 v2/v4/v4.1 按路线图新增（现分别为 23 个、30 个），页面模块的语义未变。
你在入门教程里学的每一个字，在浏览器里都照样管用。

## 2. 第一个页面：点击按钮计数器

这一节用的是《05》第 3.6 节的标准示例。它只有 17 行，但把前端要讲的东西全都讲到了。
我们分三步：先写 HTML，再写 `.saho`，然后一行一行解释。

### 2.1 准备

1. 新建一个文件夹，比如 `E:\卅练习\前端`。
2. 在里面新建 `计数器.html`。
3. 在同一个文件夹里新建 `计数器.saho`。
4. 打开终端，用 `sahou build` 把 `.saho` 译成 `.js`（下一节细讲，这里先照抄）。

### 2.2 页面 HTML（`计数器.html`）

HTML 不是 卅，它是"页面的骨架"：哪里放一段文字，哪里放一个按钮，给它们各起一个 `id`。
下面这 13 行**逐字来自《05》第 3.6 节**：

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <title>计数器</title>
</head>
<body>
  <p id="显示">还没开始</p>
  <button id="按钮">点我 +1</button>
  <script src="计数器.js"></script>
</body>
</html>
```

三个要点，先记住，后面的排错全靠它们：

- `<p id="显示">` 和 `<button id="按钮">` 各有一个 `id`。这两个 `id` 就是 卅 里
  `页面.取元素("#显示")`、`页面.取元素("#按钮")` 的**门牌号**——`#` 就是"按 id 找"的意思。
- `<script src="计数器.js">` 引进的是 `sahou build` **翻译出来的那个 `.js`**，不是 `.saho`。
  引错文件是新手第一个空白页的原因。
- `<script>` 写在 `</body>` 前面，也就是写在两个元素的**后面**。这样脚本运行时元素已经存在了。
  （原因见第 7.1 节：取不到的元素会返回 `空值`。）

### 2.3 卅 源文件（`计数器.saho`）

```saho
# 计数器页面（v1.5 页面模块）—— 事件处理就是传函数值（D5）
#   v2 落地后，第一行改为：用 "页面" 引入
数字 = { "值": 0 }
显示 = 页面.取元素("#显示")
按钮 = 页面.取元素("#按钮")

函数 刷新()
    页面.置文本(显示, "你点了 {数字["值"]} 次")
完毕

函数 点一下(事件)
    数字["值"] = 数字["值"] + 1
    刷新()
完毕

页面.点击(按钮, 点一下)
刷新()
```

### 2.4 逐行解释

| 行 | 代码 | 说明 |
|---|---|---|
| 1 | `# 计数器页面…` | 注释。`#` 之后到行尾全部被忽略。 |
| 2 | `#   v2 落地后…` | 注释。`页面` 现在是**预置模块名**，不需要引入；v2 有模块系统后写法改成 `用 "页面" 引入`，模块成员的写法与语义不变。 |
| 3 | `数字 = { "值": 0 }` | **计数状态**。为什么不直接写 `数字 = 0`？因为事件处理函数里给它赋值只会建**局部变量**，外面的 `数字` 一动不动（规范 5.3，第 7.2 节详述）。放进字典，改的是**共享对象的字段**，才真的生效。这就是入门教程第 5.3 节"用字典代替对象"。 |
| 4 | `显示 = 页面.取元素("#显示")` | 按 CSS 选择器取元素，`"#显示"` 表示"id 是 `显示` 的那个元素"。返回的是一个**元素句柄**。取不到会返回 `空值`，**不报错**——这是刻意的，方便你写 `如果 元素 == 空值` 判断。 |
| 5 | `按钮 = 页面.取元素("#按钮")` | 同上，这次取的是按钮。两个句柄取出来就存着，后面反复用，不用每次重取。 |
| 6 | （空行） | 排版用，不影响语法。 |
| 7 | `函数 刷新()` | 定义"把界面重画一遍"的函数。名字随便起，这里叫 `刷新` 最直白。 |
| 8 | `页面.置文本(显示, "你点了 {数字["值"]} 次")` | 把 `<p>` 里的文字换掉。`{数字["值"]}` 是**插值**（D6），运行时取出 `数字` 字典里 `"值"` 字段的当前值填进去。注意里面的嵌套引号：卅 能正确分辨哪对引号包着整个文本、哪对在花括号里（入门教程 5.2）。 |
| 9 | `完毕` | 结束 `函数 刷新`。 |
| 10 | （空行） | 排版。 |
| 11 | `函数 点一下(事件)` | **事件处理函数**：一个普普通通的 卅 函数，收一个参数（事件字典）。参数叫 `事件` 只是习惯，你也可以叫 `e`、`忽略`。 |
| 12 | `数字["值"] = 数字["值"] + 1` | **改容器里的字段**：取出旧值加 1，再写回去。这一行是整个页面的核心，见第 7.2 节。 |
| 13 | `刷新()` | 显式调用刷新函数。**没有响应式、没有虚拟 DOM**——你改完数据，必须自己说一句"现在重画"。这是刻意的：新手能一眼看出"我改了什么"和"我什么时候要求它重画"。 |
| 14 | `完毕` | 结束 `函数 点一下`。 |
| 15 | （空行） | 排版。 |
| 16 | `页面.点击(按钮, 点一下)` | 绑定点击事件：**把函数 `点一下` 当作值传给 `页面.点击`**。注意 `点一下` 后面**没有括号**——传的是"怎么处理"这件事本身，不是"现在就执行一遍"。写成 `点一下()` 就会立刻执行、并把返回值（`空值`）当成处理函数，是新手最常见的错误。 |
| 17 | `刷新()` | 页面刚打开时先画一次，让 `<p>` 一开始显示"你点了 0 次"，而不是 HTML 里写的"还没开始"。 |

### 2.5 构建与打开

```bash
sahou build 计数器.saho -o 计数器.js
# 然后用浏览器打开 计数器.html（或放在任何静态托管上）
```

双击 `计数器.html`，页面上应该出现"你点了 0 次"和一个按钮；每点一次，数字加一。

### 2.6 这个示例要说明的三件事

1. **`函数 点一下(事件)` 是普通 卅 函数，被当作值传进去。**
   没有事件接口、没有实现类、没有注册类型、没有 `this`，全靠 D5"函数是一等公民"。
   想加一个"清零"按钮？再写一个 `函数 清零(事件)`，再传一次 `页面.点击(清零按钮, 清零)`，仅此而已。
2. **计数状态必须放在字典里。** 处理函数里写 `数字["值"] = …` 改的是共享对象；
   若写成 `数字 = 数字 + 1`，因为函数内赋值只创建局部变量，计数会永远停在 1。
3. **更新界面靠显式调用 `刷新()`。** 没有"数据变了自己变"的魔法，每一步都看得见。

### 2.7 看一眼翻译出来的 JavaScript（节选）

构建之后打开 `计数器.js`，你会看到类似这样的内容（节选，见《05》第 3.7 节）：

```javascript
// 由 sahou build 生成 —— 请勿手改
(function () {
  "use strict";
  const 数字 = new Map([["值", 0]]);
  const 显示 = page.el("#显示");
  const 按钮 = page.el("#按钮");

  function 刷新() {                                    // sahou: 第 7 行
    page.set_text(显示, `你点了 ${__saho_str(__saho_dict_get(数字, "值"))} 次`);
  }
  function 点一下(事件) {                              // sahou: 第 12 行
    __saho_dict_set(数字, "值", __saho_num(__saho_dict_get(数字, "值") + 1));
    刷新();
  }
  page.on_click(按钮, 点一下);                         // sahou: 第 17 行
  刷新();
})();
```

注意三个生成细节：

1. **中文标识符原样保留**（`数字`、`显示`、`刷新`），你可以对照着 `.saho` 读懂产物；
2. 每个函数上方有 `// sahou: 第 N 行` 注释，配合 `--source-map` 保证行号可回溯；
3. 所有字典读写都走 `__saho_dict_get/set`，所以"缺键"报的是 卅 的中英双语消息，
   而不是 JavaScript 那句冷冰冰的 `undefined`。

`__saho_*` 这些名字是**运行时前导库**里的私有辅助函数（约 20 个），
它们**不是**语言的内置函数、**不占**内置函数名额，你写 卅 代码时永远不需要直接写它们。

## 3. 构建命令 `sahou build` 怎么用

### 3.1 最基本的用法

```bash
sahou build 计数器.saho -o 计数器.js
```

- `build` 是子命令，意思是"把源码转译成 JavaScript"，**它不会运行页面**；
- `-o` 指定输出的 `.js` 文件名。**这一步是既定决策**，也是你最常见的一条命令；
- 默认情况下，运行时前导库（`saho_rt.js`）会**内联**进输出文件，
  于是产物是**单文件**——双击 `HTML` 就能跑，最符合教学场景。

### 3.2 常用选项

```bash
sahou build 页面.saho -o 页面.js      # 基本用法：生成可直接 <script src> 的 JS
sahou build 页面.saho --watch          # 改 .saho 就自动重新生成（建议）
sahou build 页面.saho --source-map     # 生成 页面.js.map，控制台定位回 .saho 行（建议）
sahou build 页面.saho --runtime 外部   # 生成 <script src="saho_rt.js">，多页面复用（建议）
```

| 选项 | 作用 | 什么时候用 |
|---|---|---|
| `-o 文件名` | 指定输出文件 | 总是写，最清楚 |
| `--watch` | 监视源文件，保存就重新生成 | 边改边看的时候，省得每次手动敲 |
| `--source-map` | 生成 `.js.map` | 页面报错看不懂时，让控制台指回 `.saho` 行 |
| `--runtime 外部` | 前导库不内联，单独出 `saho_rt.js` | 有多个页面共用同一份运行时的时候 |

> 除 `sahou build 页面.saho -o 页面.js` 之外的选项，属于**建议选项**（《05》的【扩展补充 E4】），
> 工具链将来可能增删，但基本形态这一条不会变。

### 3.3 构建时你会看到的输出

构建成功后，终端会打印一行**精度提示**——这是唯一一处允许的语义偏差，必须让你知道：

```text
提示：浏览器端小数按 15 位有效数字对齐，超大整数（> 2^53）不保证精确。
```

翻译成大白话：

- 日常的加减乘除、计数、金额、成绩，在浏览器里和解释器里结果一致；
- `0.1 + 0.2 == 0.3` 在两边都是 `真`；
- 但**绝对值超过 9007199254740992 的整数可能不再精确**。真到了那一步，
  运行时不会给你一个错答案，而是抛一个**可接住**的错误：
  `数太大了，浏览器里的数最多精确到 9007199254740992，这个数已经超出。`
- 需要大整数或高精度计算（比如算阶乘）的程序，请放在**服务端**（用 v1 解释器跑）。

### 3.4 编译期：警告和错误

**编译期错误**与你写命令行程序时**完全一样**：同一个语法分析器、同一套诊断格式
（第 N 行、中文优先、英文其次、`你是不是想写…`）。前端**不会新增第二种报错格式**。

```
第 9 行：第 9 行的 "函数" 块没有收尾，缺少 "完毕"。
line 9: the "函数" block starting on line 9 is not closed; missing "完毕" (end).
  提示：这个块从第 9 行开始，一直开到文件结束。补一个 "完毕"，或删掉多余的开头。
```

**编译期警告**只有一种：用了浏览器里没有的东西。这时给的是**警告不是错误**，
因为同一份 `.saho` 也可能在服务端跑：

| 你用了 | 构建时的态度 | 浏览器里调用时 |
|---|---|---|
| `读取文件` | 警告 | 抛可接住错误：`浏览器里没有文件系统，读取文件 用不了。试试让服务端把内容发过来。` |
| `写入文件` | 警告 | 同上 |
| `文件存在` | 警告 | 同上 |
| `输入` | 警告 | 同上（浏览器里请用 `页面.值(输入框)` 读输入框） |
| `网络.请求` | **错误级提示** | 浏览器端**不提供**（理由见第 7.3 节） |

### 3.5 运行期：浏览器里怎么看报错

页面出错了，卅 有**两个出口**，你不用猜：

1. **控制台**：按 `F12`（或右键 → 检查）打开控制台，会看到
   `[卅 第 N 行]` + 中文消息 + 英文消息 + 建议；
2. **页面上**：如果你的 HTML 里有一个 `id="卅-错误"` 的元素，同一句话会**写进那个元素**，
   不打开控制台也能看到自己错在哪。教学场景强烈建议加上：

```html
<p id="卅-错误" style="color: red"></p>
```

另外，浏览器里的 `打印(...)` 走 `console.log`——**它不会画在页面上**。
想看到东西，要么打开控制台，要么用 `页面.置文本` 写到页面上。
这一点和命令行程序差别很大，是新手最容易困惑的地方。

## 4. 页面模块 API 逐个演示

### 4.1 API 总表（14 个成员，全部中英双名）

一句话原则先摆在这里：

> **事件处理就是传函数值。** 没有 `addEventListener` 这个名字、没有事件对象类型、
> 没有 `this`、没有 `async/await`、没有响应式绑定。

| 双语名 | 签名 | 一行说明 |
|---|---|---|
| `页面.取元素(选择器)` / `page.el(selector)` | `-> 元素` | 按 CSS 选择器取一个元素；找不到返回**空值**，不报错 |
| `页面.取全部(选择器)` / `page.el_all(selector)` | `-> 列表` | 取所有匹配元素，返回元素列表（可为空列表） |
| `页面.置文本(元素, 文本)` / `page.set_text(el, text)` | `-> 空值` | 设置元素文字内容；非文本值自动按 `文本(...)` 规则转换 |
| `页面.取文本(元素)` / `page.get_text(el)` | `-> 文本` | 读取元素文字内容 |
| `页面.值(元素)` / `page.value(el)` | `-> 文本` | 读取输入框当前值（`<input>`/`<textarea>`/`<select>`） |
| `页面.置值(元素, 文本)` / `page.set_value(el, text)` | `-> 空值` | 设置输入框的值 |
| `页面.置样式(元素, 属性, 值)` / `page.set_style(el, name, value)` | `-> 空值` | 设置内联样式 |
| `页面.置属性(元素, 名称, 值)` / `page.set_attr(el, name, value)` | `-> 空值` | 设置 HTML 属性（如 `"href"`、`"title"`） |
| `页面.点击(元素, 函数)` / `page.on_click(el, fn)` | `-> 空值` | 点击事件；`函数` 接收一个参数（事件字典） |
| `页面.输入(元素, 函数)` / `page.on_input(el, fn)` | `-> 空值` | 输入事件，每敲一下就触发一次 |
| `页面.提交(元素, 函数)` / `page.on_submit(el, fn)` | `-> 空值` | 表单提交事件，宿主自动阻止默认跳转 |
| `页面.创建(标签)` / `page.create(tag)` | `-> 元素` | 新建元素，如 `页面.创建("li")` |
| `页面.加入(父元素, 子元素)` / `page.append(parent, child)` | `-> 空值` | 把子元素追加到父元素末尾 |
| `页面.移除(元素)` / `page.remove(el)` | `-> 空值` | 从页面中移除元素 |

下面把最常用的十个**一个一个演示**。所有片段都假设 HTML 里有对应的 `id`，
并且已经用 `页面.取元素("#id")` 把句柄取好、存进了变量（元素名与 `id` 一一对应）。

### 4.2 取元素：`页面.取元素`（`page.el`）

```saho
显示 = 页面.取元素("#显示")
如果 显示 == 空值
    打印("页面上没有 #显示 这个元素，检查一下 HTML 里的 id。")
否则
    打印("找到了，它现在写着：{页面.取文本(显示)}")
完毕
```

- 参数是 **CSS 选择器**：`"#显示"` 按 id 找，`".条目"` 按 class 找，`"li"` 按标签名找。
- **找不到返回 `空值`，不报错。** 这是刻意的设计：新手最常犯的错就是"id 打错了"，
  返回空值让你能用一句 `如果 元素 == 空值` 把话说清楚，而不是拿到一个莫名其妙的崩溃。
- 取到的元素建议**存进变量**反复用，不要每次都重新取。

### 4.3 取全部：`页面.取全部`（`page.el_all`）

```saho
条目们 = 页面.取全部("li")
打印("页面上共有 {长度(条目们)} 个条目")
for 条目 于 条目们
    页面.置样式(条目, "color", "#333")
完毕
```

- 返回的是**元素列表**，可能为空列表；空列表在条件位置算**假**（真值规则），
  所以 `如果 条目们` 就能判断"有没有"。
- `长度(元素列表)` 用的是你熟悉的 `长度`，元素列表和普通列表一样能遍历。

### 4.4 置文本：`页面.置文本`（`page.set_text`）

```saho
页面.置文本(显示, "你好，卅！")
页面.置文本(显示, 42)                     # 非文本值自动按 文本(...) 规则转换
页面.置文本(提示, "格式是 \{键: 值\}")     # ← 想显示花括号，要写 \{ \}
```

- **第三个例子请特别注意**：花括号在 卅 文本里是"插值"的开始信号。
  如果你想显示的**就是**一对花括号，必须写成 `\{` 和 `\}`。
  忘了转义，卅 会以为你要插值，然后报"括号不配对"。
  这条规矩在网络模块教程第 5.3 节也出现过（写 JSON 例子的时候）。
- 非文本值（数、布尔、列表、字典）会自动转换，规则和插值、`文本(...)` 完全一致。

### 4.5 取文本：`页面.取文本`（`page.get_text`）

```saho
文字 = 页面.取文本(显示)
打印("页面上现在写着：{文字}")
如果 包含(文字, "卅")
    打印("它提到了卅。")
完毕
```

- 返回的是**文本**。可以拼接、可以 `包含`、可以 `长度`，就是普通文本。
- 它读的是**元素里的文字**；要读**输入框里的内容**，请用下一个 `页面.值`。

### 4.6 值：`页面.值`（`page.value`）

```saho
输入框 = 页面.取元素("#名字")
名字 = 页面.值(输入框)
如果 名字 == ""
    页面.置文本(提示, "你还没写名字")
否则
    页面.置文本(提示, "你好，{名字}！")
完毕
```

- **`页面.值` 拿到的永远是文本**，和 `输入()`、和请求里的查询参数是同一条规矩。
  想当数用要自己 `数(...)`：

```saho
年龄框 = 页面.取元素("#年龄")
尝试
    年龄 = 数(页面.值(年龄框))
    页面.置文本(提示, "明年你就 {年龄 + 1} 岁了")
接住 错误信息
    页面.置文本(提示, "年龄要填数字哦")
完毕
```

- 注意"空文本 `""` 在条件位置算假"，所以 `如果 页面.值(输入框)` 就能判断"空不空"。

### 4.7 置值：`页面.置值`（`page.set_value`）

```saho
页面.置值(输入框, "小明")     # 填上
页面.置值(输入框, "")         # 清空（提交成功后最常用）
```

- 和 `页面.值` 是一对：一个读、一个写。
- 清空输入框是表单页面最常见的动作，写 `页面.置值(输入框, "")` 就行。

### 4.8 点击：`页面.点击`（`page.on_click`）

```saho
函数 打招呼(事件)
    页面.置文本(提示, "有人点了按钮，事件类型是 {事件["类型"]}")
完毕

按钮 = 页面.取元素("#按钮")
页面.点击(按钮, 打招呼)
```

- **第二个参数是函数值**：写 `打招呼`，不写 `打招呼()`。
- 处理函数收一个参数，是**事件字典**。v1.5 只保证两个键：
  `"类型"`（如 `"点击"`）与 `"目标"`（元素句柄）。刻意不把整套浏览器事件对象暴露出来——
  那等于把浏览器 API 塞进语言。需要更多信息，就用 `页面.取元素` 再取一次。
- 逻辑只有一句时，可以顺手用匿名函数（唯一的匿名写法）：

```saho
页面.点击(按钮, 函数(事件) => 页面.置文本(提示, "点了一下"))
```

### 4.9 输入：`页面.输入`（`page.on_input`）

```saho
输入框 = 页面.取元素("#名字")
预览 = 页面.取元素("#预览")

函数 边打边看(事件)
    页面.置文本(预览, "你正在输入：{页面.值(输入框)}")
完毕

页面.输入(输入框, 边打边看)
```

- **每敲一下就触发一次**。所以别在里面写很重的循环，页面会卡。
- 它和"点击后再读一次值"是两种风格：`页面.输入` 更即时，`页面.点击` 更省事。

### 4.10 提交：`页面.提交`（`page.on_submit`）

```saho
表单 = 页面.取元素("#表单")

函数 提交了(事件)
    页面.置文本(结果, "收到：{页面.值(输入框)}")
完毕

页面.提交(表单, 提交了)
```

- 绑在 `<form>` 上。**宿主会自动阻止默认跳转**，你不需要自己写任何"阻止跳转"的代码，
  页面不会因为提交而整页刷新。
- 它和点击按钮的区别只是"触发时机"：按回车、点提交按钮都会走它。

### 4.11 创建：`页面.创建`（`page.create`）

```saho
新条目 = 页面.创建("li")
页面.置文本(新条目, "买牛奶")
```

- 参数是标签名，返回一个**刚创建、还没挂到页面上**的元素。
  也就是说：只 `创建` 不 `加入`，页面上**什么都不会出现**。这两步是分开的，别忘第二步。

### 4.12 加入：`页面.加入`（`page.append`）

```saho
列表 = 页面.取元素("#列表")
页面.加入(列表, 新条目)          # 追加到 #列表 的末尾
```

- 父元素在前，子元素在后。v1.5 **只提供"追加到末尾"**这一种插入方式，
  够用就好——想插到最前面，就先把列表清空、再按新顺序逐条加入（每一步都看得见）。

### 4.13 移除：`页面.移除`（`page.remove`）

```saho
页面.移除(新条目)                 # 从页面里拿掉
```

- 移掉之后，这个元素句柄还在你手上，但已经不在页面里了。
- 想清空一个列表，就配合 `页面.取全部` 逐条移除（第 6 节的例子这么做）。

### 4.14 置样式：`页面.置样式`（`page.set_style`）

```saho
页面.置样式(显示, "color", "red")
页面.置样式(显示, "font-size", "20px")
```

设置的是**内联样式**，属性名用 CSS 的写法（`"font-size"` 带连字符）。

### 4.15 置属性：`页面.置属性`（`page.set_attr`）

```saho
链接 = 页面.取元素("#链接")
页面.置属性(链接, "href", "https://example.com")
页面.置属性(链接, "title", "点我去看看")
```

设置 HTML 属性，值通常写成文本。想改"文字内容"用 `页面.置文本`，
想改"样式"用 `页面.置样式`，想改"属性"才用 `页面.置属性`——三者分工清楚。

### 4.16 元素是什么：一个"不透明的句柄"

这是前端最重要的一条边界，请读两遍：

- **元素不是第六种类型。** `类型(元素)` 返回 `"dict"`——它在实现里是一个由**宿主掌控**、
  语言不能直接读写的句柄。所以：
  - 元素**不能**索引（`元素["文字"]` 不行）；
  - 元素**不能**成员访问（`元素.文字` 不行）；
  - 元素**不能**参与算术、比较大小；
  - 元素只能交给 `页面` 模块的函数。
- 误用时报的是说人话的双语错误：

```
第 6 行：元素不能这样用。它只能交给 页面 模块的函数，例如 页面.置文本(元素, "你好")。
line 6: an element cannot be used like this. Pass it to a 页面 (page) function, e.g. 页面.置文本(元素, "你好").
```

- 两个句柄之间用 `==` 比较，判断的是"**是不是同一个元素**"；元素和别的值比较一律为 `假`。

## 5. 事件处理就是传函数值

### 5.1 一件事，两种写法

前端没有发明新概念，它用的就是入门教程第 8.4 节那个你已经会的东西：

```saho
设 翻倍 = 函数(x) => x * 2
print(翻倍(21))                        # 42

函数 应用(操作, 值)
    返回 操作(值)
完毕

print(应用(函数(x) => x + 100, 5))     # 105
```

`应用` 收到一个**函数值**，然后调用它。事件绑定完全一样：
`页面.点击(按钮, 点一下)` 就是"把一个函数值交给页面模块，**将来**有人点按钮时替我调用它"。

对照一下你已经见过的两个地方，会发现**它们是同一件事**：

| 场景 | 谁在传函数值 | 什么时候被调用 |
|---|---|---|
| 入门教程 | `应用(函数(x) => x + 100, 5)` | 函数体里的 `操作(值)` 那一行 |
| 网络模块 | `服务.路由("GET", "/", 问好)` | 有人访问 `GET /` 的时候 |
| 前端模块 | `页面.点击(按钮, 点一下)` | 有人点那个按钮的时候 |

**"传函数值 = 把一段将来要做的事交给别人保管"**——三次都是这句话。

### 5.2 什么时候用匿名函数，什么时候用具名函数

| 写法 | 能装多少逻辑 | 适合 |
|---|---|---|
| `函数(事件) => 表达式` | **只有一句表达式** | 一行就能说完的响应，比如 `页面.置文本(提示, "点了")` |
| `函数 名字(事件) … 完毕` | 任意多行，可以用 `如果`、`遍历`、`尝试` | 真实的事件处理 |

写多语句的处理函数，**必须**用具名函数——这是语言里唯一的匿名写法只有单表达式决定的，
不是前端额外的限制。

### 5.3 两个必须记住的坑

1. **不要带括号。**

```saho
页面.点击(按钮, 点一下)      # 对：把函数交出去
页面.点击(按钮, 点一下())    # 错：立刻执行了一遍，把返回值（空值）当成处理函数
```

2. **处理函数要收一个参数。** 宿主调用它时会传一个事件字典，
所以签名写成 `函数 名字(事件)`。参数在函数体里用不上也没关系，名字起 `事件` 就行，
但**不能不写**——参数个数不符会按规范报错。

### 5.4 加一个功能 = 再写一个函数，再传一次

这就是前端最舒服的地方。想给计数器加"清零"：

```saho
函数 清零(事件)
    数字["值"] = 0
    刷新()
完毕

清零按钮 = 页面.取元素("#清零")
页面.点击(清零按钮, 清零)
```

没有插件、没有配置对象、没有生命周期钩子。**函数 + 字典 + 页面模块的组合**，
就是全部的表达方式（D5 的直接收益）。

## 6. 综合小例子：待办清单页面

现在把前面所有东西合起来，写一个真的有用的小页面：
**输入框 + 添加按钮 + 列表展示**，一共 28 行（含注释与空行）。

### 6.1 HTML（`待办.html`）

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <title>待办清单</title>
</head>
<body>
  <h1>待办清单</h1>
  <input id="输入框" placeholder="写点什么">
  <button id="添加">添加</button>
  <button id="清空">清空</button>
  <ul id="列表"></ul>
  <script src="待办.js"></script>
</body>
</html>
```

### 6.2 卅 源码（`待办.saho`，28 行）

```saho
# 待办清单页面（v1.5 页面模块）—— 输入框 + 添加按钮 + 列表展示
输入框 = 页面.取元素("#输入框")
添加按钮 = 页面.取元素("#添加")
清空按钮 = 页面.取元素("#清空")
列表 = 页面.取元素("#列表")

函数 添加一条(事件)
    内容 = 页面.值(输入框)
    如果 内容 == ""
        打印("先写点内容，再点添加。")
        返回 空值
    完毕
    条目 = 页面.创建("li")
    页面.置文本(条目, 内容)
    页面.加入(列表, 条目)
    页面.置值(输入框, "")
    打印("已添加：{内容}")
完毕

函数 清空列表(事件)
    所有条目 = 页面.取全部("#列表 li")
    for 条目 于 所有条目
        页面.移除(条目)
    完毕
完毕

页面.点击(添加按钮, 添加一条)
页面.点击(清空按钮, 清空列表)
```

构建并打开：

```bash
sahou build 待办.saho -o 待办.js
# 然后双击 待办.html
```

### 6.3 逐段解释

**第一段：取好四个句柄（第 2–5 行）**

```saho
输入框 = 页面.取元素("#输入框")
添加按钮 = 页面.取元素("#添加")
清空按钮 = 页面.取元素("#清空")
列表 = 页面.取元素("#列表")
```

一次性把要用的元素都取出来存好。这一段必须写在 `</body>` 前面的脚本里效果才稳
（第 7.1 节解释原因）。

**第二段：添加一条（第 7–18 行）**

| 行 | 代码 | 说明 |
|---|---|---|
| 8 | `内容 = 页面.值(输入框)` | 读输入框当前内容，拿到的是**文本**。 |
| 9–12 | `如果 内容 == ""` … `返回 空值` | **空内容不添加**。`返回 空值` 会立刻结束这个处理函数，后面几行全部跳过。`如果` 块里的 `返回` 是提前退出的标准写法（入门教程 10.4 节用过同样的手法）。 |
| 13 | `条目 = 页面.创建("li")` | 新建一个列表项元素。此刻它还不在页面上。 |
| 14 | `页面.置文本(条目, 内容)` | 把用户写的内容填进去。 |
| 15 | `页面.加入(列表, 条目)` | **挂到页面上**。少了这一行，页面上什么都不会变——这是"创建/加入分两步"最典型的坑。 |
| 16 | `页面.置值(输入框, "")` | 清空输入框，方便接着写下一条。 |
| 17 | `打印("已添加：{内容}")` | 走 `console.log`，纯粹给自己调试看。想显示在页面上，改成 `页面.置文本`。 |

**第三段：清空列表（第 20–25 行）**

```saho
所有条目 = 页面.取全部("#列表 li")
for 条目 于 所有条目
    页面.移除(条目)
完毕
```

- 选择器 `"#列表 li"` 读作"`#列表` **里面的**所有 `li`"；
- `所有条目` 是**新列表**，`页面.移除` 改的是页面，不会动这个列表，
  所以这个 `for` 是安全的（规范 S19 只禁止修改**正在被遍历的那个列表**）；
- 如果页面本来就是空的，`所有条目` 是空列表，`for` 一次都不执行，不会出错。

**第四段：绑定（第 27–28 行）**

```saho
页面.点击(添加按钮, 添加一条)
页面.点击(清空按钮, 清空列表)
```

一行一个事件，读起来就是"点添加按钮，就执行添加一条；点清空按钮，就执行清空列表"。

### 6.4 可以自己加的功能

1. **回车也能添加**：把输入框包进 `<form id="表单">`，用 `页面.提交(表单, 添加一条)`。
2. **显示条数**：加一个 `<p id="计数">`，在 `添加一条` 和 `清空列表` 里各更新一次。
3. **实时预览**：加 `页面.输入(输入框, 预览函数)`，每敲一下就更新一个 `<p>`。
4. **点条目划掉**：给每个新 `li` 也绑一个 `页面.点击`，用 `页面.置样式(条目, "text-decoration", "line-through")`。

## 7. 常见问题与排错

### 7.1 元素取不到：`页面.取元素` 返回空值

**症状**：页面上什么都没有变，控制台也没有报错；或者在页面上写了
"页面上没有 #显示 这个元素"。

**原因**：`页面.取元素` 找不到元素时**不报错**，它返回 `空值`。
于是后面 `页面.置文本(空值, "…")` 才会报错，或者干脆什么都不做。

**四个常见原因，按出现频率排序**：

| 原因 | 怎么发现 | 改法 |
|---|---|---|
| **`<script>` 写在元素前面**（比如放进了 `<head>`） | 脚本运行时元素还不存在 | 把 `<script src="…">` 挪到 `</body>` **前面**，也就是所有元素之后。v1.5 只保证 `点击/输入/提交` 三种事件，**没有**"页面加载完成"事件可用，所以位置很重要 |
| **id 打错或用错了选择器** | 卡片上写着 `id="显示"`，代码里写 `"#显示框"` | 一个字母一个字母对；`#` 表示 id，`.` 表示 class，别混 |
| **忘了 `#`** | 写成 `页面.取元素("显示")` | 那是"标签名叫 显示"，当然找不到；改成 `"#显示"` |
| **改完 `.saho` 没重新构建** | 浏览器跑的还是旧的 `.js` | 再执行一次 `sahou build`，或干脆用 `--watch` |

**标准防御姿势**——每个取元素的地方都可以顺手写一句：

```saho
显示 = 页面.取元素("#显示")
如果 显示 == 空值
    抛出("HTML 里没有 id 是 显示 的元素")
完毕
```

**还有一条容易忘的**：元素是**不透明句柄**，不能这样用——
`页面.置文本(元素["文字"], "…")` 或 `元素.文字`。要用 `页面.取文本(元素)`。

### 7.2 事件里改共享状态：要改容器，不能重新赋值

这是整个前端模块里**最容易错、也最值得花时间理解**的一条，
和网络模块教程第 8.3 节是**同一条规则**。

**规则回顾（规范 5.3）**：函数内给一个名字赋值，是在**当前函数作用域新建一个局部变量**，
**不会**修改外层的同名变量。但列表和字典是**可变对象**：
通过 `容器["键"] = 值`、`容器.添加(...)`、`容器.删除(...)` 修改的是**共享的那个对象本身**，
调用者看得见。

先看**错误的写法**：

```saho
# 错误示范：计数永远停在 1
计数 = 0
显示 = 页面.取元素("#显示")
按钮 = 页面.取元素("#按钮")

函数 点一下(事件)
    计数 = 计数 + 1        # ← 错！这只是新建了一个局部变量，函数一结束就没了
    页面.置文本(显示, "你点了 {计数} 次")
完毕

页面.点击(按钮, 点一下)
```

每点一次，页面都显示"你点了 1 次"。`计数 = 计数 + 1` 这行看起来完全正确，
但它改的是**局部变量**，外面的 `计数` 一个字节都没动。

**正确的写法**：改容器里的字段。

```saho
状态 = { "计数": 0 }                  # 第 3 行：共享状态放进字典
显示 = 页面.取元素("#显示")
按钮 = 页面.取元素("#按钮")

函数 点一下(事件)
    状态["计数"] = 状态["计数"] + 1     # 改的是共享字典的字段
    页面.置文本(显示, "你点了 {状态["计数"]} 次")
完毕

页面.点击(按钮, 点一下)
```

**为什么这个坑在前端特别隐蔽？**
因为页面**不会报错**——它只是安安静静地不按你想的变。
在命令行程序里，变量没生效往往马上就露馅；在页面上，现象只是"数字卡住了"，
新手很容易怀疑是浏览器坏了。

所以写事件处理函数时，请养成和网络模块里一样的自问：

> **"我这个赋值，是要改外面那个容器，还是只想建个本地变量？"**

**反过来，什么样的情况用普通变量是对的？** 只在本函数里用、函数结束就不需要的数据：

```saho
函数 添加一条(事件)
    内容 = 页面.值(输入框)      # 这次请求自己的数据，用局部变量完全正确
    条目 = 页面.创建("li")
    页面.置文本(条目, 内容)
    页面.加入(列表, 条目)
完毕
```

判断标准还是那一句：**这个数据要不要活过这一次事件？**

### 7.3 服务端模块在浏览器里不可用

前端和后端用的是**两种宿主**，有些能力只在其中一边存在。
这不是缺陷，而是刻意的边界（《05》第 3.5、5 节）。

**（1）`页面` 模块只在浏览器里存在。**
在服务端解释器里跑一份用了 `页面` 的 `.saho`，会抛错并提示：

```text
页面 模块只能在浏览器里用；服务端程序请用 网络 模块。
page module is only available in the browser; for a server program use the 网络 (net) module.
```

所以"同一份代码既能当服务端又能画页面"这件事，v1.5 是**不成立**的。
想同时有前后端，就写两个 `.saho` 文件：一个用 `网络` 起服务，一个用 `页面` 做界面。

**（2）浏览器里没有文件系统。**
`读取文件`、`写入文件`、`文件存在` 在浏览器里**用不了**（构建时会给你警告，因为同一份源码
也可能在服务端跑）；真在浏览器里调用会抛一个**可接住**的错误：

```text
浏览器里没有文件系统，读取文件 用不了。试试让服务端把内容发过来。
```

`输入` 也一样不可用——浏览器里的"输入"就是输入框，请用 `页面.值(输入框)`。

**（3）`网络.请求` 在浏览器端不提供。**
原因是：浏览器主线程不允许**同步阻塞**地发网络请求，而 v1 又砍掉了 `async/await`（D7），
没有异步语法可以表达"等结果回来再继续"。所以这一能力留到 v2 与并发模型一起定义。

那前端怎么拿数据？三条路，都不用异步：

| 做法 | 思路 | 适合 |
|---|---|---|
| **构建期渲染进 HTML** | 服务端把数据写进 HTML（比如 `<li>买菜</li>` 直接写死），前端只负责交互 | 内容变化不频繁的页面，最省事 |
| **普通表单提交** | `<form>` 提交到服务端，服务端返回一个新页面 | "提交后换一页"的传统做法 |
| **服务端程序 + 前端页面分开** | 服务端用 `网络` 模块提供 JSON，前端页面先显示静态内容；要取新数据就整页刷新 | 教学演示 |

**（4）错误处理在两边是同一条通道。**
浏览器里的 `抛出("消息")` 仍然走 `尝试/接住`，错误信息仍然是**一段文本**（D8）。
没有被接住的错误，会走第 3.5 节说的两个出口（控制台 + `id="卅-错误"` 的元素）。
另外，JavaScript 原生的异常**不会**漏给你看——宿主会把它替换成
"程序内部出错，请把下面这段报给作者"这类文本，D10"不泄露实现语言"在浏览器里同样成立。

### 7.4 其他常见坑（速查）

| 现象 | 原因 | 改法 |
|---|---|---|
| 页面一片空白，什么都不显示 | `<script src>` 引进的是 `.saho`，或者文件名写错 | 引进 `sahou build` 产出的 `.js`；核对文件名大小写 |
| 控制台报"页面 模块只能在浏览器里用" | 用服务端解释器跑了页面代码 | 用 `sahou build` 生成 `.js`，再用浏览器打开 HTML |
| 按钮点了没反应 | `页面.点击(按钮, 点一下())` 多写了括号 | 去掉括号，传函数值本身 |
| 按钮点了报参数个数不符 | 处理函数没写参数：`函数 点一下()` | 写成 `函数 点一下(事件)` |
| 页面上的花括号没显示出来，反而报插值错 | 文本里的 `{` `}` 没转义 | 写成 `\{` 与 `\}` |
| `打印(...)` 看不到任何输出 | 浏览器的 `打印` 走 `console.log` | 按 `F12` 看控制台，或用 `页面.置文本` 写到页面上 |
| 数字卡住不变 | 事件里用了普通变量的 `x = x + 1` | 改成容器字段：`状态["计数"] = 状态["计数"] + 1`（第 7.2 节） |
| 新建的元素不出现 | 只 `页面.创建` 没 `页面.加入` | 补上 `页面.加入(父元素, 子元素)` |
| 改了 `.saho` 刷新页面却没变 | 没重新构建 | 再跑一次 `sahou build`，或用 `--watch` |
| 报错只有一行 `[卅 第 N 行]` 看不懂 | 产物是转译后的 JS | 用 `--source-map` 重新构建，让控制台指回 `.saho` 行 |
| 元素报"不能这样用" | 对元素做了索引、成员访问或运算 | 元素只能交给 `页面` 模块的函数，用 `页面.取文本/置文本` |
| 输入框里拿到的是文本，做加法出错 | `页面.值` 永远返回文本 | 先 `数(页面.值(输入框))`，并用 `尝试/接住` 兜底 |
| 少了一个 `完毕` | 块没收尾 | 报错会告诉你是**从第几行开始的块**没关上，照着补 |

## 8. 速查表、自检与练习

### 8.1 一页速查

**两步走完前端**

```bash
sahou build 页面.saho -o 页面.js      # 第一步：翻译
# 第二步：写 HTML，用 <script src="页面.js"> 引进，浏览器打开
```

**最常用的一页速查**

```saho
元素 = 页面.取元素("#id")               # 取一个元素（找不到返回 空值）
元素们 = 页面.取全部("li")               # 取一批元素（列表）
页面.置文本(元素, "文字")                # 改文字
文字 = 页面.取文本(元素)                 # 读文字
值 = 页面.值(输入框)                     # 读输入框（永远是文本）
页面.置值(输入框, "")                    # 写输入框（清空）
页面.点击(按钮, 处理函数)                # 点击事件（传函数值，不带括号）
页面.输入(输入框, 处理函数)              # 每次敲键盘都触发
条目 = 页面.创建("li")                   # 新建元素
页面.加入(父元素, 条目)                  # 挂到页面上
页面.移除(条目)                          # 从页面拿掉
```

**三条铁律**

1. **事件处理就是传函数值**——写 `点一下`，不写 `点一下()`；处理函数要收一个参数。
2. **共享状态放容器里改**——`状态["计数"] = 状态["计数"] + 1`，不要 `计数 = 计数 + 1`。
3. **界面靠显式刷新**——改完数据，自己调用刷新函数；没有响应式，没有"自动变"。

### 8.2 语言纯度的自检（你应该没有学到任何新语法）

| 检查项 | 本模块是否破坏 |
|---|---|
| 关键字总数 | 仍是 **18 个**，`页面` 是模块名不是关键字，**+0** |
| 内置函数总数 | 本文写作时 **29 个**（现为 30 个：v4.1 加 位置/find，与 页面 无关），`页面` 的 14 个成员不占名额，**+0** |
| 数据类型 | 仍是 **数/文本/列表/字典/布尔 + 空值**；元素是**不透明宿主句柄**，`类型(元素)` 返回 `"dict"`，**+0** |
| 块收尾 | 全部用 `完毕`/`end`，没有花括号、没有缩进规则 |
| 双语 | 模块成员全部中英双名（`页面/page`、`取元素/el`、`置文本/set_text`、`点击/on_click`…） |
| 错误处理 | 只有 `尝试/接住` + `抛出`，错误对象就是一段文本 |
| 函数 | 定义只有一种写法；匿名仍只有 `函数(x) => 表达式` |

如果你发现自己想用 `class`、`async`、`await`、`import`、组件、指令、装饰器——
**它们都不存在**，而且你也不需要用：**函数 + 字典 + `页面` 模块**就够了。

```saho
页面.点击(清空按钮, 清空列表)
更新计数()
```

要点：抽出一个 `更新计数()`，在每个改数据的地方**紧接着**调用它——
这正是"显式刷新"的实践方式；`长度(条目们)` 直接数页面上的 `li`，
不用另外维护一个计数器，就不会出现"数据和界面不一致"的 bug。

</details>

**练习 4（动脑子）**：把第 2 节计数器里的 `数字["值"] = 数字["值"] + 1` 改成
`数字 = 数字 + 1`，然后点几下按钮，猜猜页面会显示什么？再亲手验证。

<details>
<summary>参考答案</summary>

页面会**报错**（`数 + 字典` 类型不匹配），因为 `数字` 是字典、`1` 是数，不能相加。
如果你把状态换成一个普通变量（`计数 = 0`，事件里写 `计数 = 计数 + 1`），
页面**不会报错**，但会一直显示"你点了 1 次"——函数内赋值只创建局部变量，外层没被修改（第 7.2 节）。
两种现象都说明同一件事：**要改的是共享容器里的字段。**

</details>

### 8.4 接下来

你已经会用 卅 写一个能在浏览器里跑的页面了。往下可以试：

1. **把前后端串起来**：服务端用 `网络` 模块（网络模块教程第 6 节）提供待办清单，
   前端页面用第 6 节的写法做界面。注意浏览器端没有 `网络.请求`，
   v1.5 的做法是把数据在构建期渲染进 HTML，或者用普通表单提交。
2. **读设计文档**：《[05-前端后端扩展设计](./05-前端后端扩展设计.md)》第 3 节讲了这些 API
   为什么长成这样，第 5 节还明确列出了"**不做的事**"（不做 SSR、不做虚拟 DOM、
   不做响应式、不做 WebSocket、不做打包器），每一条都有理由——
   知道"为什么不做什么"，比知道"能做什么"更重要。
3. **读一读生成的 JavaScript**：`计数器.js` 不长，对照第 2.7 节的片段读一遍，
   你会对"翻译官到底做了什么"有具体的印象。

> **一句话收尾**：前端不是另一门语言，它只是"**同一棵语法树的第二个出口**"。
> 你写的还是 `如果`/`函数`/`完毕`，浏览器拿到的却是能直接跑的 JavaScript——
> 中间的差别，全部由 `sahou build` 这个翻译官替你处理掉了。
