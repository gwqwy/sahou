## 1. 动机：为什么 v1 故意没有 import

### 1.1 三行代码不该配两行导入

简报 D9 写得很直接：**"不引入模块系统——v1 所有内置函数全局可见；v2 再考虑 `用 "xxx" 引入`。"**
第 4 节的"明确砍掉的 Python 特性"里，`模块系统（v1）` 与类、装饰器、生成器并列。

这不是"还没来得及做"，而是一个刻意的取舍。看一份初学者真正会写的程序：

```
小猫 = { "名字": "咪咪", "饥饿": 0 }
print("你好, {小猫["名字"]}!")
print("饥饿度 {小猫["饥饿"]}")
```

三行代码，教的是"字典代替对象"（D4）和"插值代替拼接"（D6）两件正事。
如果语言要求每份文件开头写 `import`，这三行就要配上两行：

```
import math
import random
```

初学者的第一个疑问立刻从"什么是字典"变成"**什么叫导入？为什么有些东西要导入、`print` 却不用？**"
——一个与程序逻辑完全无关的问题。卅 的定位是"比 Python 更简单一点"，
所以 v1 的选择是：**29 个内置函数全局可见，一个 import 都不要**（D9 的原文：全局可见、无需引入）。

### 1.2 那什么时候开始需要 import

答案不是"程序变长"，而是**三件事同时出现**的时候：

| 信号 | v1 怎么办 | 为什么 v1 的替代法不够了 |
|---|---|---|
| **能力边界**：想写前后端，能力却不在 29 个内置函数里 | 用**预置模块名** `网络` / `页面`（《05》的 E1） | 预置模块名只有这两个，第 3 个能力没地方放 |
| **代码规模**：一个文件放不下，想拆成几个文件 | 只能把整段复制过来 | 复制出来的两份会各自演化，改一处漏一处 |
| **复用**：想把"工具函数"分给第二个程序用 | 没有共享机制 | 每次都要重新粘贴，且没有版本概念 |

《05》用"预置模块名"这个临时形态顶住了第一件事，让 v1.1 的 `网络` 与 v1.5 的 `页面`
**零关键字增量**地跑了两个版本。第二、第三件事就必须靠真正的模块系统来解了——
而一旦要写"从哪个文件加载"，就需要一门语法，这就是 v2 唯一的关键字增量。

### 1.3 v2 的关键字增量：18 → 20

| 英文 | 中文 | 类别 | 用途 | 示例 |
|---|---|---|---|---|
| `use` | `用` | 模块 | 模块引入语句的开头 | `用 "工具" 引入` |
| `import` | `引入` | 模块 | 模块引入语句的结束词（**可省略**） | `用 "工具"` |

这两条与既有 18 个关键字合并，v2 关键字总数为 **20 个**（中文 20 个、英文 20 个，一一对应）。
`import` 进入关键字表，正好补上了简报 D2 里"`import` 均不在其中"那句话留下的 v2 缺口；
而 `用/use` 是为了让中英文两种拼写都读得通：

```
用 "工具" 引入          # 全中文
use "工具" import       # 全英文
用 "工具"               # 省略 引入/import，等价
use "工具"              # 等价
```

### 1.4 为什么这件事必须做成语法，而不是内置函数

v1 有一条隐形纪律：**凡是函数和字典能表达的，绝不做成语法**（《05》第 1.2 节的"约束一"）。
所以先问一句：能不能加一个内置函数 `引入("工具")`？

不能，有两个硬理由：

1. **名额不够，而且开了一个不该开的头。** D9 的 29 个内置函数是"全局可见、不需要引入"的，
   现在要加一个"本身就在做引入这件事"的内置函数，等于把模块系统塞进标准库，
   30 个名额既被占了，语义上还自相矛盾。
2. **"引入"要改变**名字绑定与加载顺序**，函数做不到。** `引入("工具")` 返回一个字典，
   那就还得写 `工具 = 引入("工具")`——初学者必须理解"绑定"这个抽象，反而更难；
   而且 `如果 条件 引入(...)` 这种写法一旦合法，模块加载时机就变成了运行期表达式，
   "循环引入"就没法在加载期干净地报错（M4）。

结论：引入语句是**语句**，与 `如果`/`遍历`/`函数` 同级——它靠 `完毕` 收尾（D1），
它不做抽象，它只做一件事：**把一个模块绑定到一个名字上。**

## 2. 引入语句：语法与名字绑定

### 2.1 语法（M1）

```ebnf
引入语句    ::= ( "use" | "用" ) 文本 [ ( "import" | "引入" ) ] ;
```

三条说明：

- 模块名是**文本字面量**，必须用半角引号：`用 "工具" 引入`。
  写成 `用 工具 引入`（不带引号）会报错，提示"模块名要用引号括起来，如 用 "工具" 引入"。
- `引入` / `import` **可省略**：`用 "工具" 引入` 与 `用 "工具"` 完全等价，同一条语句、同一个记号序列。
  之所以留一个可选收尾词，是因为"用 X 引入"读起来更完整，而"用 X"更短——
  两种都要能用，让写代码的人按自己顺口来。**（这就是 E2 的定案。）**
- 引入语句**只能写在程序顶层**（函数定义之外）。写在函数体里报错：

```
第 9 行：引入语句要写在最外层，不能写在函数里。
line 9: a use/import statement must be at the top level, not inside a function.
  提示：把 用 "工具" 引入 挪到这个文件的最上面。
```

- **不支持别名**（v2.0 保持最小）。`用 "工具" 引入 当 我的工具` 这类写法**没有语法**，
  解析到 `当` 就会报错，并给出明确提示：

```
第 1 行：引入语句不支持起别名，"当" 这个词这里不认识。
line 1: use/import does not support aliases; "当" is not expected here.
  提示：v2 只支持 用 "工具" 引入（可省略 引入）。名字冲突时请直接改名，别起别名。
```

### 2.2 名字绑定（M2）

`用 "网络" 引入` 把模块绑定到**默认名字**，而且**中文与英文两个拼写都绑定**：

| 写法 | 绑定出来的名字 | 说明 |
|---|---|---|
| `用 "网络" 引入` | `网络` **和** `net` | 两个名字指向同一个模块对象 |
| `用 "net" 引入` | `网络` **和** `net` | 与上一行完全等价（模块 id 归一化，见 4.2） |
| `用 "工具" 引入` | `工具` | 用户模块：绑定名 = 文件名去后缀 |
| `用 "待办" 引入`（`stones/待办/main.saho`） | `待办` | 目录包：绑定名 = 包名 |

```
用 "网络" 引入

服务1 = 网络.服务()      # 中文名能用
服务2 = net.服务()       # 英文名也能用，指向同一个模块
print(网络 == net)       # 真——同一个模块对象
```

两条规矩：

1. **两个拼写指向同一个模块对象**，所以 `网络 == net` 为 `真`，
   改其中一个的顶层变量（不建议这么做，见 3.2）另一个也看得见。
   这与内置函数的中英双名（`打印`/`print`）是同一套约定。
2. **用户模块的英文名来自文件名本身**；文件名是中文（`工具.saho`）时，
   并不凭空发明一个英文词，只绑定中文名 `工具`。
   要让英文名也有意义，就把文件名写成英文：`tools.saho` 绑定 `tools`，
   而 `用 "tools" 引入` 与 `用 "工具" 引入` 是两个不同的模块（不同文件），这一点必须说清楚。

**引入的名字是普通变量**（这条很重要，它保证了"没有魔法"）：

```
用 "工具" 引入

工具 = { "加": 函数(a, b) => a * b }    # 普通赋值，遮蔽了模块名
print(工具.加(2, 3))                     # 6——现在它是个字典，不是模块了

工具 = 空值                               # 再用一次普通赋值，模块就找不回来了
```

- 遮蔽就是 v1 规范 5.3 第 5 条的普通遮蔽，**不产生任何特殊错误**，也不影响别的文件。
- 想恢复就是把 `用 "工具" 引入` 再写一次（重新绑定），或者换个变量名。

### 2.3 名字冲突：直接报错，建议改名

不支持别名（M1），所以冲突必须有话直说。冲突只发生在**两个模块想占用同一个名字**时：

```
用 "工具" 引入
用 "工具" 引入
```

```
第 2 行：名字 "工具" 已经有一个模块了（第 1 行引入的）。
line 2: the name "工具" already refers to a module (imported on line 1).
  提示：一个名字只能绑一个模块。要同时用两个，请把其中一个模块文件改个名，
        例如 工具2.saho，然后写成 用 "工具2" 引入。
```

同理，`用 "工具" 引入` 之后再 `用 "tools" 引入`（假设 `tools.saho` 与 `工具.saho`
都绑定了 `工具`，比如同名的目录包）也按上表报错。

> **设计意图**：别名是"两个名字指一个东西"，它会让"这个名字到底是哪来的"变成需要顺藤摸瓜的问题。
> v2.0 的取舍是**宁可让你改文件名**——文件名就在目录里，一眼看得见；别名只活在代码里，看不见。

## 3. 模块编写规范

### 3.1 模块文件就是一个普通 `.saho` 文件

用户模块不引入任何新写法：没有 `export`、没有 `module`、没有花括号包裹、
没有"公开/私有"标注（D1、D4）。`工具.saho` 就是一个用 v1 语法写出来的普通文件。

```
# 工具.saho —— 一个用户模块
函数 加(a, b)
    返回 a + b
完毕

函数 打招呼(名字)
    返回 "你好, {名字}!"
完毕

版本 = "1.0.0"
```

主程序：

```
# 主程序.saho
用 "工具" 引入

print(工具.加(1, 2))            # 3
print(工具.打招呼("卅"))        # 你好, 卅!
print(工具.版本)                # 1.0.0
```

### 3.2 导出即"顶层名字"（M4）

**规则一句话**：模块的**全部顶层名字**（顶层的 `函数` 定义与顶层变量）构成**导出字典**，
成员访问就是字典访问（规范 5.7），所以 `工具.加(1, 2)` 能用，`工具.版本` 也能读。
不需要任何"导出声明"——**顶层写了什么，就导出什么。**

模块能看到的东西，与它的导出范围，是两条不同的线：

| 问题 | 答案 |
|---|---|
| 模块能用 29 个内置函数吗？ | **能**，全部可见（`打印`、`长度`、`尝试/接住`、`抛出` 都能用，D9） |
| 模块能看到引入者（主程序）的变量吗？ | **不能**。模块有自己的模块作用域，看不见任何引入者的名字 |
| 模块能看见它自己引入的模块吗？ | 能，但那个名字**不进入**本模块的导出字典 |

把最后一条写清楚：模块顶层下面这些名字**不会**出现在导出字典里——

- 引入语句产生的绑定（写 `用 "网络" 引入`），
- 模块内部为了临时计算放在顶层的中间变量（没有"私有"语法，只有"别放顶层"这条约定）。

如果模块真的需要"只给自己用的东西"，就把它写在函数里（函数内的局部变量天然不外泄）：

```
# 工具.saho
函数 内部格式化(值)          # 它也在导出字典里（凡是顶层名字都导出）
    返回 "[{值}]"
完毕

函数 打招呼(名字)
    内部 = 内部格式化(名字)   # 函数内的局部变量，外面看不到
    返回 "你好, {内部}!"
完毕
```

> **v2 刻意不做"私有/公开"标注**。名字前缀 `_` 之类的约定也不做——
> 一旦有了"部分不导出"，就必须先回答"谁有权看见"，那就离开"初学者语言"了（见第 8 节）。

**顶层名字撞上内置函数时怎么办**（这一条必须写死，否则导出字典会出现两种解释）：
内置函数**不能被重新定义**（规范 6.1），所以模块顶层**不允许**定义与内置函数同名的 `函数`。
若模块顶层出现一个与内置函数同名的**变量**（例如 `文本 = "版本"`），则：

- 在本模块内部，这个名字**遮蔽**该内置函数（就是普通的遮蔽，规范 5.3 第 5 条）；
- 在导出字典里，键 `"文本"` 仍然指向**内置函数本身**，被遮蔽的那个变量以 `文本_` 为键导出
  （尾随下划线是转译器为避免撞名自动加的，会在生成代码里留一行 `// sahou: 原名 文本` 注释）。

**实践建议：别给顶层名字起内置函数的名字**——两个名字长得一样，读者永远猜不到 `工具.文本` 是哪一个。

### 3.3 避免副作用：模块顶层的代码只该"定义东西"

模块文件在**自己的模块作用域**里**执行一次**（按绝对路径缓存，M4），
所以模块顶层的每一行都会真的运行。推荐写法只有一句：

> **顶层放定义，动作放函数。**

```
# 推荐：顶层只有定义
用 "网络" 引入              # 引入也要写在顶层
默认端口 = 8080

函数 起个服务()
    返回 网络.服务()
完毕
```

```
# 不推荐：顶层直接起服务——"引入即开服务器"，引入者完全没得选
用 "网络" 引入
服务 = 网络.服务()          # 顶层副作用：一引入就跑
服务.监听(8080)             # 顶层副作用：整个程序卡在这里
```

副作用**只在首次引入时执行一次**（模块按绝对路径缓存，M4）。也就是说：

```
用 "工具" 引入
用 "工具" 引入     # 这一行会报名字冲突（2.3）；即使换个名字重新引入，也不会再执行一次
print(工具.版本)   # 模块对象是缓存下来的那一个
```

所以顶层的 `打印` 只会打印一次。这是好事（不必担心重复执行），
但也意味着"我想每次引入都重置状态"做不到——**模块是单例**，状态要显式重置就导出个 `重置()` 函数。

### 3.4 循环引入：立即报错（M4）

A 引入 B、B 又引入 A，这种"互相等对方先加载完"的局面没有正确答案，v2 的规定是**立即报错**，
并把整条引用链列出来（包括"自己引入自己"这种最简单的循环）：

```
第 1 行：模块之间循环引入了：甲.saho -> 乙.saho -> 甲.saho。
line 1: circular import detected: 甲.saho -> 乙.saho -> 甲.saho.
  提示：模块只能自上而下引入。请把两个模块都要用的东西抽出来，
        放进第三个模块（例如 公共.saho），让 甲 和 乙 都引入它。
```

报错时机有两处，两处都会报：

1. **解释执行时**（`sahou 主程序.saho`）：加载到成环的那一步立即中断程序。
2. **转译时**（`sahou build`）：**转译期**就能检测到（M6），所以在浏览器里不可能出现
   "转到一半才炸"的情况——这与 D10"编译错误在本地就报清楚"完全一致。

### 3.5 模块顶层写 `返回` 报错（M4）

v1 规范 5.8 规定：顶层（函数外）写 `返回` 表示结束整个程序（S12）。
**模块文件不是程序**，所以这条不适用，必须报错：

```
第 4 行：模块文件里不能写 返回。模块不是程序，它只负责定义东西。
line 4: a module file cannot use 返回 (return); a module is not a program.
  提示：把这句话放进一个函数里，让主程序去调用那个函数；
        模块的 返回 只在函数内部有意义。
```

理由：如果允许模块顶层 `返回`，就会出现"引入一个模块，结果把引入者自己的程序结束了"这种
完全无法调试的行为——模块的加载是**引入者**的决定，结束程序不该是它的权力。

## 4. 解析顺序表

### 4.1 顺序表（M3）

`用 "名字" 引入` 按下面的顺序**从上到下**查找，找到第一个就停：

| 优先级 | 位置 | 具体路径（以引入者文件所在目录为基准） | 说明 |
|---|---|---|---|
| 1 | 内置模块 | `网络/net`、`页面/page` | 写在运行时不进文件系统，直接绑定（M6） |
| 2 | 同目录单个文件 | `名字.saho` | 最常见的用户模块 |
| 3 | 同目录目录包 | `名字/main.saho` | 比它多一个"包"的外壳，便于放附件 |
| 4 | stones 单个文件 | `stones/名字.saho` | 装进来的包 |
| 5 | stones 目录包 | `stones/名字/main.saho` | 装进来的包（目录形态） |
| — | 都没有 | 报错（4.3） | 列出搜过的位置 |

**"同目录"指引入者文件所在的目录**，不是进程的当前工作目录。
这样可以保证"从哪个目录运行程序"不会改变解析结果——`卅 项目/主程序.saho`
无论在项目里还是在项目外执行，结果都一样。

**`网絡` 的英文拼写归一化**：内置模块的 id 有两个拼写（`网络` 与 `net`），
它们不是两个模块——`用 "网络" 引入` 与 `用 "net" 引入` 找到的是同一个对象，
绑定出的名字也都是 `网络` + `net`（2.2）。

**一个模块一个身份**：解析结果一律归一成**绝对路径**作为模块 id（目录包归一成 `名字/main.saho` 的绝对路径），
所以"从同目录找到"和"从 stones 找到同一个文件"不会加载两次（M4 的缓存规则）。

### 4.2 找到时的行为

| 找到的位置 | 它是什么 | 绑定名 |
|---|---|---|
| `网络` / `net` | 内置模块（运行时对象） | `网络` 与 `net` |
| `工具.saho` | 用户模块 | `工具` |
| `工具/main.saho` | 目录包 | `工具` |
| `stones/工具.saho` | 用户模块 | `工具` |
| `stones/工具/main.saho` | 目录包 | `工具` |

### 4.3 找不到：双语错误 + 搜索位置清单 + stones 提示

这是初学者最常撞的墙，所以报错必须一次性说全（D10）：

```
第 1 行：找不到模块 "工具"。
line 1: module "工具" was not found.
  找过这些地方 / searched:
    1. 内置模块 网络/net、页面/page（没有 "工具"）
    2. 与本文件同目录：E:\代码\工具.saho
    3. 与本文件同目录：E:\代码\工具\main.saho
    4. stones 目录：E:\代码\stones\工具.saho
    5. stones 目录：E:\代码\stones\工具\main.saho
  提示：检查文件名是不是拼错了（区分大小写）；想从别处拿包，先写 stones.yml 再运行 sahou 装。
```

如果 `stones.yml` **已经登记了**这个包、但本地确实没有对应文件，报错要**再补一句**，
直接告诉用户下一步该敲什么命令：

```
第 1 行：找不到模块 "工具"，但 stones.yml 里登记了它（版本 1.0.0）。
line 1: module "工具" was not found, but stones.yml lists it (version 1.0.0).
  提示：运行 sahou 装 把它补齐。
```

## 5. stones 工作流

### 5.1 包是什么

**包（package）就是 `.saho` 文件目录，或者单个 `.saho` 文件**，放在项目的 `stones/` 目录下。
没有压缩包、没有清单里的文件列表、没有构建步骤——复制即安装，删除即卸载。

```
我的项目/
├── 主程序.saho
├── stones.yml
└── stones/
    ├── 工具.saho                 # 单文件包
    └── 待办/                     # 目录包
        ├── main.saho             # 包入口（必须叫 main.saho）
        └── 说明.md               # 可以是任何附件
```

- 目录包的入口**必须**是 `main.saho`；缺了它，解析表（4.1）第 5 条就命中不了，
  等于包没装（报错会列出搜过的位置）。
- `stones/` 里的包**互相之间**也用同一套解析顺序，所以"包 A 引入包 B"是合法的，
  但**不能成环**（3.4）。
- 不写 `stones/` 前缀：引入语句里永远只写**包名**，`stones` 这个位置由解析器负责（4.1）。

### 5.2 清单文件 `stones.yml`

`stones.yml` 与 `stones/` 目录**同级**，记录每个包的**名字与版本**：

```yaml
# stones.yml —— 这个项目的包清单
# 格式：包名: 版本
工具: 1.0.0
待办: 0.2.1
返回码: 2.0.0
```

- 一行一个包，`包名: 版本`。
- `#` 开头是注释（与 卅 的注释符一致）。
- 包名与文件名/目录名一致（不含 `.saho`）；版本是**文本**，v2 只做"记录 + 校验"，不做范围解析。
- 手工编辑这个文件是允许的；`sahou 装` 是把它变简单的工具，不是唯一入口。

### 5.3 命令：`sahou 装`

| 命令 | 英文别名 | 行为 |
|---|---|---|
| `sahou 装 <本地路径>` | `卅 install <本地路径>` | 把 `<本地路径>` 指向的 `.saho` 文件或目录**复制**进 `stones/`，并把 `包名: 版本` 登记进 `stones.yml` |
| `sahou 装` | `卅 install` | **无参数**：校验 `stones.yml` 里登记的每一个包都已在本地 |
| `sahou 装 <远程来源>` | `卅 install <远程来源>` | v1.8 起支持直接安装远程 zip 包（5.4）；索引/版本解析式仓库仍未来 |
| `sahou 装 <包名>` | `卅 install <包名>` | v4.2：按名字取出 **exe 自带**的标准库包（`sahou stones` 可列出），离线可用 |
| `sahou stones` | `卅 stones` | v4.2：列出 exe 自带的标准库包（`用 "包名" 引入` 免安装即用；本地同名包优先） |

用法示例（命令行，不是 卅 代码）：

```bash
# 把隔壁目录的 工具.saho 装进来 -> stones/工具.saho，并登记 stones.yml
sahou 装 ../共享/工具.saho

# 把一个目录包装进来 -> stones/待办/，并登记 stones.yml
sahou 装 ./待办

# 校验清单：每个登记的包都在本地吗？
sahou 装
#   ✓ 工具 1.0.0（stones/工具.saho）
#   ✓ 待办 0.2.1（stones/待办/main.saho）
#   ✓ 返回码 2.0.0（stones/返回码.saho）
#   3 个包全部就位。all 3 packages are present.

# 少了一个时：
#   ✗ 返回码 2.0.0：stones.yml 里登记了，但 stones/ 里没有。
#   提示：重新运行 sahou 装 <这个包的本地路径>，或者从 stones.yml 里删掉这一行。
```

三条规矩：

1. **不静默覆盖。** 目标已存在时**默认报错**并提示（`stones/工具.saho` 已存在），
   不自动覆盖用户已经改过的包——这与 D10"给出建议、不要猜"一致。带 `--覆盖` 时才覆盖。
2. **版本来自包自己。** 单文件包读取顶层变量 `版本 = "1.0.0"`；
   目录包读取 `main.saho` 的顶层 `版本`。读不到就登记为 `0.0.0`，并给一句**警告级**提示
   （不中断）：`没找到 版本，stones.yml 里先记为 0.0.0。`（这也是 3.3"顶层放定义"的一个实际好处。）
3. **`装` 只做复制与登记，不做任何编译或改名。** 包名就是原文件名/目录名；
   想改名请先改本地文件的名字——v2 没有别名（第 8 节）。

### 5.4 远程包：v1.8 起支持远程 zip，索引式仓库仍未来

**已支持（v1.8）**：`sahou 装 https://example.com/包名.zip` —— 下载 zip、自动剥掉顶层目录、解压进 `stones/包名/` 并登记 stones.yml。

下面的旧提示保留作历史记录——v1.8 起直接的 zip 网址已经能装（见上），
但**索引式仓库**（能搜索、能解析版本、能信任校验的"stones 集市"）仍然未提供：

```
（v2 时期的提示，现仅对非 zip 的远程来源出现）
装：暂时还不能从远程仓库装包。
```

理由贯穿全篇：**先把"本地能装、能校验、能复现"这条链路做扎实**，
再谈分发。索引式仓库一旦出现，就必须同时回答"版本冲突怎么办""下载来的包怎么信任"
"离线怎么办"三个大问题，那是另一份设计文档的事。

## 6. 转译器行为

### 6.1 内置模块：直接绑定运行时对象

`sahou build`（v1.5 已交付）对 `网络` / `页面` 两个内置模块**不做任何打包**——
它们不是 卅 源码，而是运行时的成员（`net` 对象、`page` 对象），
所以引入它们只生成一次绑定：

```javascript
// 由 sahou build 生成 —— 请勿手改
// 用 "网络" 引入
const 网络 = __saho_net, net = __saho_net;
// 用 "页面" 引入
const 页面 = __saho_page, page = __saho_page;
```

这也解释了 M5 为什么可以**保持预置**：不写引入语句时，这两个名字本来就已经在场；
写了引入语句，只是**多一次"显式声明依赖"的动作**，绑定到的是同一个对象。
两条路径的产物**完全一致**。

### 6.2 用户模块：每个模块一个 IIFE，按模块 id 缓存（M6）

用户模块会转译成**一个 IIFE（立即执行函数），返回导出字典**；
每个模块 id 只执行一次，结果缓存起来：

```javascript
// 由 sahou build 生成 —— 请勿手改
// ==== 模块：工具.saho ====   模块 id 是它的绝对路径
__saho_modules["<工具.saho 的绝对路径>"] = (function () {
  const __导出 = new Map();                       // 导出字典，就是 卅 的字典（D4）
  function 加(a, b) {                             // sahou: 第 2 行
    return __saho_num(a + b);
  }
  function 打招呼(名字) {                          // sahou: 第 6 行
    return `你好, ${__saho_str(名字)}!`;
  }
  __saho_dict_set(__导出, "加", 加);
  __saho_dict_set(__导出, "打招呼", 打招呼);
  return __导出;                                  // IIFE 的返回值就是导出字典
})();

// ==== 主程序 ====
const 工具 = __saho_require("<工具.saho 的绝对路径>");
__saho_print(__saho_dict_get(工具, "加")(1, 2), "\n");
```

四个要点：

1. **导出字典是 卅 的字典**（生成 JS 里的 `Map`），不是 JS 普通对象——
   与《05》3.3（2）表里"字典用 `Map`"的理由逐条一致（插入顺序、数的键、原型链）。
   因此模块成员访问走 `__saho_dict_get`，缺键时给出的是 卅 的双语建议（D10）。
2. **按模块 id 缓存**：`__saho_require` 先查缓存，命中就直接返回上次的导出字典。
   所以"模块顶层副作用只执行一次"（3.3）在浏览器里同样成立。
3. **转译期检测循环引入**：打包前先做一次依赖图遍历，发现环就**在 `sahou build` 时报错**
   （报错文本与 3.4 逐字一致），不会生成一份"跑起来才发现成环"的 JS。
4. **产物仍是单文件 JS**：所有被引入的用户模块都并进同一个输出文件，
   顺序按依赖拓扑排序；`--runtime 外部` 的选项只影响 `saho_rt.js` 前导库是否内联，
   不影响模块打包（《05》的 E4）。

### 6.3 与解释器的一致性

同一份源码有两个后端（解释器 / 转译器），模块语义必须**逐字节一致**：
模块加载顺序、副作用次数、导出字典的成员与顺序、循环引入报错文本、找不到模块的报错文本，
全部登记进一致性语料库（《05》3.8 与 04 文档 8.4）做双向验证。
两份输出不一致 = 转译器有 bug，**不是"浏览器就是这样"**——这条铁律在模块系统里同样有效。

## 7. 与设计原则的兼容自检（D1–D10）

| 决策 | 是否破坏 | 具体落点 |
|---|---|---|
| **D1** `end`/`完毕` 收尾，不用缩进与花括号 | 否 | 引入语句是**单行语句**，不引入块，所以它没有 `完毕`；模块文件里的每个 `函数` 仍用 `完毕` 收尾。生成 JS 的 IIFE 花括号是转译产物，卅 侧看不见 |
| **D2** 双语关键字 | 否 | 新增 `用/use`、`引入/import` 一对双语关键字，中文 20 个、英文 20 个一一对应；模块名本身不是关键字，它由**文件名**决定（`工具.saho` 绑 `工具`，`tools.saho` 绑 `tools`），模块成员名照旧双语（`网络/net`、`页面/page`） |
| **D3** 只有一种"数" | 否 | 模块系统完全不碰数值语义；`版本 = "1.0.0"` 是文本不是版本号类型（v2 不新增类型） |
| **D4** 只有 5 种类型 + 空值 | 否 | 模块对象**就是字典**（导出字典），模块名**就是普通变量**，导出成员**就是字典成员**。没有 module 类型、没有 namespace 类型、没有包对象类型 |
| **D5** 函数是一等公民，定义方式只有一种 | 否 | 导出的是函数值；`工具.加` 与 `小猫.名字` 是同一种成员访问。没有 `export function`、没有默认导出、没有 `as` 重命名函数 |
| **D6** 插值代替拼接 | 否 | 模块示例继续用 `"你好, {名字}!"`；模块名本身是文本字面量，插值不参与解析（`用 "{名字}" 引入` **不是**合法的动态引入，模块名必须是写死的文本） |
| **D7** 循环只有两种，无 `async/await` | 否 | 模块加载是**同步**的（与 v1 顺序语义一致）。没有动态 `import()`、没有异步加载、没有懒加载。引入会让程序停一下去读文件，这与 `读取文件` 一样是普通同步操作 |
| **D8** 错误处理只有 `尝试/接住` | 否 | 找不到模块、成环、名字冲突、版本读不到——统统是**双语、带行号、给建议**的错误。其中"找不到模块"可被 `尝试/接住` 接住吗？**不可以**：引入语句在最外层、加载期同步失败，按 v1 规范 5.9"没被接住的错误终止程序"处理（这是一处必须写明的边界） |
| **D9** 内置函数 ≤ 30，v1 无模块系统 | 否（这正是 v2 的账本） | 见下方"名额账本"：**关键字 20**（+2），**内置函数仍 29**（+0），**类型仍 5**（+0）。模块成员住在模块命名空间，不进全局表 |
| **D10** 报错必须说人话 | 否，且额外守两条 | ① 找不到模块的报错**列出全部搜索位置**，并提示 `sahou 装`；② 转译期检测循环引入，把编译错误留在本地（不在浏览器里炸） |

### 7.1 名额账本（v2）

| 名额 | v1/v1.5 | v2 | 变化 |
|---|---|---|---|
| 关键字 | 18 | **20**（`用/use`、`引入/import`） | **+2**（唯一变化） |
| 内置函数（D9，上限 30） | 29 | **29** | **+0** |
| 数据类型 | 5 种 + 空值 | **5 种 + 空值** | **+0** |
| 模块成员（不占内置名额） | `网络` 6 + `页面` 14 | 不变 | **+0** |
| 语法形式 | 赋值、表达式、`如果`、`当`、`遍历`、`函数`、`返回`、`尝试` | 再加 **引入语句** | **+1** |

v2 之后，**任何新能力都必须做成模块成员或 stones 包**，绝不能是第 30 个内置函数、
第 21 个关键字、第 6 种类型。这条纪律与《05》1.2 节的"约束二"是同一句话。

### 7.2 兼容性：v1.1/v1.5 的代码一行不用改（M5）

```
# v1.1 的写法（《06-网络模块教程》）：预置，直接可用
服务 = 网络.服务()
```

```
# v2 的写法：显式声明依赖，行为完全相同
用 "网络" 引入
服务 = 网络.服务()
```

**`网络` 与 `页面` 仍保持预置**（不写引入语句也能用）——这是**有意的兼容选择**：
v1.1/v1.5 的示例、教程、博客、学生作业都不用改一个字。
`用 "网络" 引入` 是给**想显式声明依赖**的用户准备的：一眼能看出这个文件依赖什么，
也让"同一个程序同时用网络和页面"这件事在源码第一屏就写得明白。**两种写法完全等价。**

> 一句话记住 M5：**预置是"默认开着"，引入是"我可以把它写出来"。**

## 8. 明确不做的事（及理由）

### 8.1 不做别名（`as` / `当`）

**理由**：别名让"这个名字指哪个模块"从**目录里的一眼可见**变成**代码里的顺藤摸瓜**（2.3）。
v2.0 的模块数量在教学场景个位数，冲突概率极低；真冲突了就改文件名——
文件名是实体，改名是好事（会同步改掉别人的引用），别名是幻影。
另外，别名会给"解析顺序表"加一列（别名 → 真实模块 id），
而这列的唯一用途就是绕开冲突，得不偿失。

**替代写法**：改文件名；或用 `工具2 = 工具` 做一次普通赋值（那是普通变量，不是别名机制）。

### 8.2 不做索引式远程仓库（直连 zip 除外）

**理由**（5.4）：远程分发一出现，"版本冲突、包信任、离线可用"三个大问题必须同时回答；
而 v2 的第一目标是让**本地**这条链路（装 → 登记 → 解析 → 校验 → 复现）跑通且报错清楚。
现在给远程来源会得到明确的双语提示，**不会静默失败**。

**替代写法**：本地路径安装（`sahou 装 ../共享/工具.saho`）+ `stones.yml` 记录版本，
把包目录直接放进版本控制共享给同事/同学。

### 8.3 不做命名空间再导出（`用 "工具" 引入` 后再 `导出 工具`）

**理由**：模块的导出字典**就是顶层名字的字典**（3.2），一旦允许"把引入的模块再导出"，
导出字典里就会出现"属于别的模块的名字"，于是"这个成员是谁定义的、谁有权改它"
立刻变成必须回答的问题——这就是 v1 明确砍掉的"继承与可见性"那一类复杂度（D4、D5）。
不做它，模块依赖图**永远是树**（成环即报错，3.4），一眼能看完。

**替代写法**：需要"汇总多个模块"就写一个普通函数逐个转发：

```
# 汇总.saho
用 "工具" 引入
用 "文本工具" 引入

函数 加(a, b)
    返回 工具.加(a, b)
完毕

函数 大写(内容)
    返回 文本工具.大写(内容)
完毕
```

### 8.4 不做 from 式部分引入（`从 "工具" 引入 加`）

**理由**三条：
① 它让"`加` 这个名字是谁的"无法从调用处看出来，读者被迫去翻文件头，与 D10"报错/阅读都要清楚"的精神相反；
② 它会引出**新的词法形式**（`从`、`引入` 后面跟标识符列表，而不是文本字面量），
等于为了一点点输入便利再加关键字，与"v2 只加 2 个关键字"的克制冲突；
③ 部分引入会遮蔽全局内置函数的判断（`从` 一个模块引入名叫 `文本` 的东西怎么办），
凭空造出一类需要解释的冲突。

**替代写法**：整模块引入，然后在需要的地方写全名 `工具.加(1, 2)`——
多打几个字，换来"一眼看得见来自哪里"。

### 8.5 顺带不做（同类理由）

| 不做的事 | 理由 | 替代写法 |
|---|---|---|
| 动态引入（`用 变量 引入`） | 模块名写死才能在转译期打包与查环（D7、D10） | 写死的文本模块名 |
| 条件引入（`如果 调试 用 "调试" 引入`） | 加载时机变成运行期，循环引入无法干净报错（1.4） | 写成两个模块，在函数里判断；或用顶部顶层引入并在函数内分支 |
| 模块版本的语义化约束（`工具: ^1.0.0`） | 需要版本求解算法与冲突报告，v2 只有"记录 + 校验" | `stones.yml` 写精确版本文本 |
| 私有/公开标注 | 见 3.2 的说明：会引出可见性模型 | 顶层只放定义；内部细节放进函数 |
| 包内附件资源（图片/数据文件） | 语言里没有"字节"类型（D4），资源不是语言的事 | 目录包里的附件由宿主/构建工具处理，`.saho` 只读文本 |

## 9. 速查表与自检清单

### 9.1 一页速查

```
用 "工具" 引入          # 引入并在顶层绑定 工具（= 文件名去后缀）
用 "工具"               # 等价写法，引入/import 可省略
用 "网络" 引入          # 内置模块：绑定 网络 和 net，两个名字同一对象
工具.加(1, 2)           # 导出成员 = 顶层名字，成员访问即字典访问
用 "工具" 引入          # 同一个名字只能绑一次；第二次报错并建议改名
```

| 想做的事 | 写什么 |
|---|---|
| 引入同目录的 `工具.saho` | `用 "工具" 引入` |
| 引入同目录的 `工具/main.saho` | `用 "工具" 引入`（解析顺序自动找到） |
| 引入 stones 里的包 | `用 "工具" 引入`（不写 `stones/` 前缀） |
| 引入内置模块 | `用 "网络" 引入` / `用 "页面" 引入`（也可不写，M5） |
| 查看/补齐本地包 | `sahou 装` / `sahou 装 ../共享/工具.saho` |
| 记录版本 | 在 `stones.yml` 写 `工具: 1.0.0` |

### 9.2 自检清单（写模块前逐条核对）

1. 模块文件里**没有**顶层 `返回`（3.5）。
2. 模块顶层**只放定义**，动作都在函数里（3.3）。
3. 所有块都用 `完毕`/`end` 收尾，一个不少（D1）。
4. 模块名是**文本字面量**，`用 "工具" 引入`，不是 `用 工具 引入`（2.1）。
5. 引入语句写在**最外层**，不在函数里（2.1）。
6. 模块之间**没有环**；两个模块都要用的东西抽到第三个模块（3.4）。
7. 没有起别名、没有 `从 … 引入`、没有动态模块名（第 8 节）。
8. 模块顶层**没有**与 29 个内置函数同名的 `函数` 定义（内置函数不能被重新定义，规范 6.1）。
9. 版本用文本写：`版本 = "1.0.0"`，不是 `版本 = 1.0.0`（D3：只有一种数，没有版本类型）。
10. 用 `sahou 装` 校验一遍：清单里的每个包都在本地（5.3）。

### 9.3 完整小例子：三个文件的项目

```
记账/
├── 主程序.saho
├── stones.yml
└── stones/
    └── 工具.saho
```

**stones/工具.saho**

```
# 工具.saho —— 一个用户模块：顶层名字就是导出的东西
版本 = "1.0.0"

函数 加(a, b)
    返回 a + b
完毕

函数 打招呼(名字)
    返回 "你好, {名字}!"
完毕

函数 显示条目(条目)
    返回 "{条目["事项"]}：{条目["金额"]}"
完毕
```

**stones.yml**

```yaml
工具: 1.0.0
```

**主程序.saho**

```
# 主程序.saho —— 把 工具 装进来，然后像用字典一样用它
用 "工具" 引入

次数 = 0
函数 记一笔(事项, 金额)
    次数 = 次数 + 1          # 注意：函数内的赋值会新建局部变量（规范 5.3）
    一条 = { "事项": 事项, "金额": 金额 }
    print("{次数}. {工具.显示条目(一条)}")
完毕

记一笔("买菜", 12)
记一笔("书", 35)
print("合计 {工具.加(12, 35)} 元")
print("工具模块版本 {工具.版本}")
```

参考输出：

```
1. 买菜：12
2. 书：35
合计 47 元
工具模块版本 1.0.0
```

> 最后那句"注意"是故意留在示例里的：模块系统再新，**v1 的作用域规则一个字都没改**——
> 想让 `次数` 真的累加，得用字典（`次数 = { "值": 0 }` 然后 `次数["值"] = 次数["值"] + 1`），
> 这正是《03-入门教程》与《06-网络模块教程》反复强调的同一件事。
