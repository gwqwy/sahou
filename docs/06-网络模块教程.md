## 1. 后端是什么：一个餐厅服务员的比喻

### 1.1 你写的程序，第一次能被别人"打开"

到现在为止，你写的所有程序都有一个共同点：**只有你自己能看见**。
运行 `sahou 记账本.saho`，屏幕上出现一行行字，程序结束，屏幕清空，什么都没留下。

**后端**（也叫"服务端"）要改变的就是这件事：

> 你写的程序**一直开着**，别人通过网络来"用它"，它每次都回一句话。

浏览器、手机 App、别人的程序，都可以来问你。这就是"后端"的全部含义——
不是某种高深的技术，而是"**一个一直开着、等着别人来提问的程序**"。

### 1.2 餐厅的比喻

把服务想象成一家餐厅。这个比喻里的每个东西，在 卅 里都有对应的一行代码：

| 餐厅里的东西 | 卅 里的东西 | 代码 |
|---|---|---|
| 盘下一家店、拿到一块空招牌 | 创建一个服务对象 | `服务 = 网络.服务()` |
| 在菜单上写："点这道菜，就这么做" | 注册一条路由 | `服务.路由("GET", "/待办", 列出)` |
| 开门营业，站在门口等客人 | 监听端口（**一直等**） | `服务.监听(8080)` |
| 店的门牌号 | 端口号 | `8080` |
| 后厨的一道工序：拿到订单，端出菜 | 处理函数 | `函数 列出(请求) … 完毕` |
| 顾客点单的那张纸条 | 请求字典 | `请求["方法"]`、`请求["路径"]`… |
| 端出去的那个盘子 | 响应字典 | `{ "状态": 200, "体": "…" }` |

把这个比喻再讲细一点，因为它能解释后面所有的规则：

**（1）`网络.服务()` 就是"盘下一家店"。**
它给你的不是一间装修好的房子，而是**一张空菜单**。这张菜单在 卅 里就是一个**普通字典**——
`服务["路由"]` 和 `服务["监听"]` 是放在字典里的两个**函数值**。
这正是入门教程第 5.3 节讲过的"**用字典代替对象，用函数操作字典**"（设计决策 D4）。
服务不是什么新类型，就是一个字典。所以你能对它做字典能做的一切：打印它、把它传给别的函数、放进列表里。

**（2）`服务.路由(方法, 路径, 函数)` 就是"在菜单上加一道菜"。**
"方法"是你想干什么（看？加？删？），"路径"是你要点哪道菜（`/待办`），"函数"是这道菜的做法。
菜做好之前，谁也不知道配料是什么；**做法本身就是一个函数值**，可以被传来传去。
这是 D5"函数是一等公民"的直接应用——和入门教程里 `应用(函数(x) => x + 100, 5)` 是同一件事。

**（3）`服务.监听(端口)` 就是"开门营业"。**
这一行**不会返回**。程序会停在这里，一直到你按 `Ctrl + C` 把它关掉。
在入门教程里，你写的程序都是从第一行跑到最后一行就结束；`服务.监听` 是第一个"**停在那里不走**"的语句。
这不是新语法，它就是一条普普通通、但会阻塞的语句。

**（4）处理函数就是后厨的一道工序。**
它收进一个**请求**（订单），端出一个**响应**（菜）。没有 `self`、没有类、没有"上下文对象"，
就是一个普通的 卅 函数：

```
函数 做法(请求)
    返回 { "体": "端出去的菜" }
完毕
```

**（5）端口就是门牌号。**
一台电脑上可以开很多家店，`8080`、`8081`、`3000` 是不同的门牌号。
同一个门牌号不能挂两家店——这就是后面第 8.1 节要讲的"端口被占用"。

### 1.3 一句话记住

> **服务 = 字典 + 函数。**

起一个服务永远只有三步，不多不少：

```
服务 = 网络.服务()                 # 第一步：开店
服务.路由("GET", "/你好", 处理)     # 第二步：写菜单（可以写很多条）
服务.监听(8080)                    # 第三步：开门营业（卡在这里）
```

### 1.4 关于 `网络` 这个名字

- `网络` 是**预置模块名**（英文名 `net`），**不是关键字**。所以你的关键字总数仍然是 **18 个**，
  一个都没多。你甚至可以在函数里给 `网络` 赋值把它遮蔽掉——但那样你就用不了这个模块了，不推荐。
- v1.1 用"预置模块名"这个临时形态提供网络能力，**不需要任何引入语句**，直接写 `网络.服务()` 就能用。
- 将来 v2 的模块系统落地后，写法会变成 `用 "网络" 引入`，但**模块成员的写法与语义完全不变**：
  你今天写的代码，将来一行都不用改。
- 模块一共 6 个成员，全部中英双名，与内置函数同一套命名约定：

| 中文 | 英文 | 干什么 | 属于谁 |
|---|---|---|---|
| `网络.服务()` | `net.server()` | 创建一个服务（得到字典） | 服务端 |
| `服务.路由(方法, 路径, 函数)` | `server.route(method, path, fn)` | 注册一条路由 | 服务端 |
| `服务.监听(端口, 主机: "127.0.0.1")` | `server.listen(port, host)` | 开门营业（阻塞） | 服务端 |
| `网络.请求(网址, 方法: "GET", 头: 空值, 体: "")` | `net.request(url, …)` | 当客户端去访问别人 | 客户端 |
| `网络.自文本(文本)` | `net.json_from(text)` | JSON 文本 → 卅 值 | 两边都用 |
| `网络.到文本(值)` | `net.json_to(value)` | 卅 值 → JSON 文本 | 两边都用 |

请再读一遍最后两行：**`网络.自文本` 和 `网络.到文本` 是同一个翻译官的两种方向**。
一个把"JSON 文本"翻译成 卅 的字典/列表，一个把 卅 的字典/列表翻译回 JSON 文本。
后面第 5、6 节会反复用到它们。

## 2. 第一个服务：5 行写出 Hello World

### 2.1 准备

1. 新建一个文件夹，比如 `E:\卅练习\网络`。
2. 在里面新建文件 `你好服务.saho`。

### 2.2 完整代码（5 行）

```
服务 = 网络.服务()
问好 = 函数(请求) => { "体": "你好，世界！" }
服务.路由("GET", "/", 问好)
打印("服务已启动：http://localhost:8080")
服务.监听(8080)
```

**5 行，一个后端服务。** 运行：

```bash
sahou 你好服务.saho
# 服务已启动：http://localhost:8080
```

然后**不要关掉这个终端**（程序会一直停在第 5 行）。另开一个终端，用 `curl` 访问：

```bash
curl http://localhost:8080/
# 你好，世界！
```

或者干脆打开浏览器，在地址栏输入 `http://localhost:8080` —— 页面上会显示 `你好，世界！`。
按 `Ctrl + C` 可以关掉服务。

### 2.3 逐行解释

**第 1 行 `服务 = 网络.服务()`**
调用模块成员 `服务()`，得到一个**普通字典**。它现在是一张空菜单，一条路由都没有。

**第 2 行 `问好 = 函数(请求) => { "体": "你好，世界！" }`**
`函数(请求) => 表达式` 是 卅 **唯一**的匿名函数写法（你在入门教程第 8.4 节见过）。
这里的函数体是一个**字典字面量** `{ "体": "你好，世界！" }`，也就是一个响应字典。
这个响应字典只写了 `"体"`，没写 `"状态"` 和 `"头"` —— 没关系，
**宿主会自动补齐缺省值**：状态补成 `200`（成功），头补成 `{}`。

**第 3 行 `服务.路由("GET", "/", 问好)`**
在菜单上加一道菜：**方法**是 `"GET"`（"我想看看"），**路径**是 `"/"`（首页），**做法**是 `问好` 这个函数值。
注意 `问好` 后面**没有括号**：我们传的是"这道菜的做法"这件事本身，不是"现在就做一遍"。
写成 `服务.路由("GET", "/", 问好())` 就错了——那会先执行一遍函数，把响应字典交给路由，
而路由要的是函数。这是新手最常见的错误之一。

**第 4 行 `打印("服务已启动：http://localhost:8080")`**
一句普通的打印，纯粹为了提醒你自己。它和网络没有任何关系。

**第 5 行 `服务.监听(8080)`**
开门营业。**程序卡在这里**，直到你按 `Ctrl + C`。
`8080` 是端口号，可以换成 `8081`、`3000`、`9000` 等等（1024 以下通常需要管理员权限）。
默认只绑定本机地址 `127.0.0.1`，也就是**只有你自己这台电脑能访问**，
同学在隔壁机器上打开是打不开的——这是刻意的安全默认值。

### 2.4 换成你熟悉的具名函数写法

5 行版本为了短，用了匿名函数。真实项目里更常见的写法是具名函数，因为处理逻辑通常不止一句话：

```
服务 = 网络.服务()

函数 问好(请求)
    返回 { "状态": 200, "头": { "Content-Type": "text/plain; charset=utf-8" }, "体": "你好，世界！" }
完毕

服务.路由("GET", "/", 问好)
打印("服务已启动：http://localhost:8080")
服务.监听(8080)
```

两个版本的语义完全一样。区别只有：

- 匿名写法 `函数(请求) => 表达式` **只能有一句表达式**，所以只适合"一句话就能算完"的处理；
- 具名写法 `函数 … 完毕` 可以有任意多行，还能用 `如果`、`遍历`、`尝试`。

**记住一条：路由的处理函数就是普通 卅 函数**，不接收 `self`、不需要注册类型、没有装饰器。
你能对普通函数做的一切（递归、被别的函数调用、传进传出的），处理函数都能做。

### 2.5 关于 `localhost` 和"阻塞"

- `localhost` 就是"本机"的意思，等价于 `127.0.0.1`。
- `服务.监听` 之后程序**不会往下走**，所以你把它写在程序的最后一行——后面的代码永远不会执行到。
- 因为 v1 没有并发（设计决策 D7），服务是**一次只处理一个请求**的：
  第一个请求还没处理完，第二个请求就在门口排队。这让 `待办` 这类共享字典不会出现
  "两个请求同时改同一个字典"的怪问题，对初学者非常友好。代价是慢一点，但教学阶段完全够用。

## 3. 请求字典与响应字典：逐字段讲解

### 3.1 请求字典：顾客递进来的那张订单

每次有请求进来，宿主都会构造一个**普通字典**交给你的处理函数。
它有 5 个固定的键，**键名固定用中文**，你只需要读，不需要写：

| 键 | 类型 | 说明 | 例子 |
|---|---|---|---|
| `请求["方法"]` | 文本 | 想干什么，统一大写 | `"GET"`、`"POST"`、`"PUT"`、`"DELETE"` |
| `请求["路径"]` | 文本 | 不含查询串的路径 | `"/待办"` |
| `请求["查询"]` | 字典 | 查询串的解析结果，键和值**都是文本** | `{ "序号": "1" }` |
| `请求["头"]` | 字典 | 请求头，键名按 HTTP 惯例原样 | `{ "Content-Type": "application/json" }` |
| `请求["体"]` | 文本 | 请求体**原文**，一个字都没解析过 | `"{\"事项\":\"买菜\"}"` |

三个必须记住的细节：

**（1）`请求["查询"]` 里的值永远是文本。**
哪怕网址写的是 `?序号=1`，你拿到的也是文本 `"1"`，不是数 `1`。
想当数用，要自己 `数("1")`。这和入门教程里"`输入()` 拿到的永远是文本"是同一条规矩。

**（2）`请求["体"]` 是原文。**
宿主**不帮你解析 JSON**。想把它变成字典，你得自己显式写 `网络.自文本(请求["体"])`。
设计上是刻意的：你永远清楚"我什么时候在解析、解析出来的到底是什么格式"。

**（3）语言里没有"字节"类型，所以只能收发文本。**
上传图片、下载文件这类二进制内容不在 v1.1 的能力范围内。

来看一个"把请求原样打印出来"的调试路由，它能把上面 5 个字段一网打尽：

```
服务 = 网络.服务()

函数 看请求(请求)
    打印("方法：{请求["方法"]}")
    打印("路径：{请求["路径"]}")
    打印("查询：{文本(请求["查询"])}")
    打印("头：{文本(请求["头"])}")
    打印("体：{请求["体"]}")
    返回 { "体": "已经打印到终端了，去看看那边。" }
完毕

服务.路由("GET", "/查看", 看请求)
服务.监听(8080)
```

访问 `http://localhost:8080/查看?名字=小明&城市=杭州`，终端里会出现类似这样的内容：

```text
方法：GET
路径：/查看
查询：{"名字": "小明", "城市": "杭州"}
头：{"User-Agent": "...", "Accept": "..."}
体：
```

> 小提示：插值里可以再写带引号的文本，比如 `{请求["方法"]}`，
> 这是入门教程第 5.2 节讲过的"嵌套引号"，卅 能正确分辨哪对引号包着整个文本、哪对在花括号里面。

### 3.2 响应字典：你端出去的那个盘子

处理函数必须**返回一个字典**。它最多有 3 个键，**全都可以不写**，缺的由宿主补齐：

| 键 | 类型 | 缺省值 | 说明 |
|---|---|---|---|
| `响应["状态"]` | 数 | `200` | HTTP 状态码：`200` 成功、`201` 已创建、`400` 请求有问题、`404` 找不到、`500` 服务内部出错 |
| `响应["头"]` | 字典 | `{}` | 响应头，比如 `{ "Content-Type": "application/json" }` |
| `响应["体"]` | 文本 | `""` | 响应体，**必须是文本** |

于是这三种写法都合法：

```
返回 { "体": "最简单的" }                                  # 状态自动 200，头自动 {}
返回 { "状态": 404, "体": "没找到" }                        # 只要状态和体
返回 { "状态": 200, "头": { "Content-Type": "application/json" }, "体": 网络.到文本(结果) }
```

### 3.3 一条刻意的规矩：`"体"` 不做自动序列化

如果你把列表或字典直接塞进 `"体"`，会**报错**（可以被 `接住`）：

```
第 8 行：响应的 "体" 必须是文本，这里给的是 列表。
line 8: the response "body" must be 文本 (string), but got 列表 (list).
  提示：想返回 JSON，写 网络.到文本(结果)。
```

**为什么不做自动转换？** 因为自动序列化会在新手心里制造一个黑盒：
"到底是谁转的？为什么是这个格式？我传了个函数进去会怎样？"
而显式写一行 `网络.到文本(结果)` 换来的是——**我永远知道我正在发什么格式**。
报错的时候，卅 也直接把该写的那一行告诉你了。

所以请记住这条对应关系：

| 你想返回的东西 | 正确的写法 |
|---|---|
| 一句普通文本 | `"体": "你好"` |
| 一个字典 | `"体": 网络.到文本(条目)` |
| 一个列表 | `"体": 网络.到文本(结果)` |
| 一个数 | `"体": 文本(42)` 或 `网络.到文本(42)` |

### 3.4 处理函数出错会怎样

如果处理函数里抛了错、而你没有 `接住`，宿主会：

1. 返回状态 `500`，正文是一条文本 `"服务内部出错：<消息>"`；
2. 把完整的双语诊断打印到**终端**；
3. **程序不退出**——一个请求出错不该毁掉整个服务。

这正是"错误一旦被接住，程序继续往下走"（规范 6.5）在服务端的形态。
不过更好的做法还是你自己用 `尝试/接住` 把错误变成一句人话，见第 8 节。

## 4. 带查询参数的路由

### 4.1 v1.1 只有精确匹配

v1.1 的路由匹配规则非常简单：

> **方法相同，并且路径一字不差，才算命中。**

- `服务.路由("GET", "/待办", 列出)` 只认 `GET /待办`；
  `GET /待办/`（多一个斜杠）**不匹配**，`POST /待办` 也**不匹配**。
- **不支持**路径参数（`/待办/{序号}`）、不支持通配符、不支持正则。
  理由很实在：路径参数会立刻引出"参数语法"这种新的词法规则，
  那就不是"给语言加扩展"，而是"改语言"了——留到 v2。
- 方法与路径重复注册时，**后注册的覆盖先注册的**。

那"对某一条记录做操作"怎么办？**把参数放进查询串**，也就是网址里 `?` 后面的部分。

### 4.2 查询串长什么样

```
http://localhost:8080/你好?名字=小明&城市=杭州
                      └─路径─┘ └──── 查询串 ────┘
```

宿主会把它解析成一个字典交给你：

```
{ "名字": "小明", "城市": "杭州" }
```

多个参数用 `&` 隔开；键和值都是**文本**。

### 4.3 完整示例：会看名字的问候服务

```
# 问候服务：读查询参数，缺参数时也有兜底
服务 = 网络.服务()

函数 问好(请求)
    查询 = 请求["查询"]
    如果 包含(查询, "名字")
        名字 = 查询["名字"]
    否则
        名字 = "朋友"
    完毕
    返回 { "体": "你好，{名字}！" }
完毕

服务.路由("GET", "/你好", 问好)
打印("试试：http://localhost:8080/你好?名字=小明")
服务.监听(8080)
```

访问测试：

```bash
curl "http://localhost:8080/你好?名字=小明"
# 你好，小明！

curl "http://localhost:8080/你好"
# 你好，朋友！
```

> **为什么网址要加引号？** 因为 `?` 和 `&` 在某些终端里有特殊含义，加引号最安全。
> 在 Windows 的 PowerShell 里记得用双引号把整个网址包起来。

### 4.4 三个要点

**（1）先用 `包含(查询, "名字")` 判断，再去取。**
`包含(字典, 键)` 是 29 个内置函数之一，判断字典里有没有某个键。
如果直接写 `查询["名字"]` 而这个参数不存在，卅 会报错并列出候选键：

```text
第 6 行：字典里没有键 "明字"。你是不是想写 "名字"？这个字典现有的键是：名字、城市。
line 6: the dict has no key "明字". Did you mean "名字"? Existing keys: 名字, 城市.
```

**（2）块不创建作用域，所以 `名字` 能带到 `完毕` 之后。**
上面 `如果/否则` 里赋值的 `名字`，出了块照样能用（规范 5.3 第 2 条）。
这和入门教程里"条件块里设的变量，块外还在"是完全一致的——卅 只有函数作用域。

**（3）中文查询串会被自动编码，但你不必操心。**
浏览器里输入 `?名字=小明`，它会变成 `%E5%90%8D%E5%AD%97=%E5%B0%8F%E6%98%8E` 发出去，
宿主会**自动解码**，你在 `请求["查询"]` 里拿到的还是好好的 `"小明"`。
`curl` 和多数字符串更简单的工具也会自己处理。

## 5. 用 POST 收 JSON

### 5.1 GET 和 POST 的差别（一句话版）

- 用 `GET` 来"**看**"：参数放在查询串里，`?序号=1`，短、可见、能收藏。
- 用 `POST` 来"**交**"：要提交的内容放在**请求体**里，长、不显示在网址上，可以是一整段 JSON。

### 5.2 两个翻译官：`网络.自文本` 与 `网络.到文本`

| 方向 | 函数 | 结果 |
|---|---|---|
| JSON **文本** → 卅 值 | `网络.自文本(文本)` | 对象 → 字典、数组 → 列表、`null` → 空值 |
| 卅 值 → JSON **文本** | `网络.到文本(值)` | 字典 → 对象、列表 → 数组、空值 → `null` |

对应关系表（背下来，只有这几条）：

| JSON 里 | 卅 里 |
|---|---|
| `{"a": 1}` 对象 | 字典 |
| `[1, 2, 3]` 数组 | 列表 |
| `"你好"` 字符串 | 文本 |
| `42`、`3.5` 数字 | 数（只有一种数） |
| `true` / `false` | 布尔 `真` / `假` |
| `null` | 空值 |

两点必须注意：

- **`网络.到文本` 遇到循环引用会抛错**（对齐规范 S11）。比如你让字典 `甲["自己"] = 甲`，
  再想去序列化它就报错，而不是死循环。
- **`网络.自文本` 解析失败时会抛一个可接住的错误**，消息里会带出错字符的位置和收到的开头内容。

### 5.3 完整示例：一个收留言的服务

**先看"不设防"的版本**（能跑，但请求体不合法时整个响应会变成 500）：

```
服务 = 网络.服务()

函数 收留言(请求)
    条目 = 网络.自文本(请求["体"])
    内容 = 条目["留言"]
    返回 { "状态": 201, "体": 网络.到文本({ "收到": 内容, "字数": 长度(内容) }) }
完毕

服务.路由("POST", "/留言", 收留言)
打印("用 curl 试试：")
打印("curl -X POST http://localhost:8080/留言 -d '\{\"留言\":\"你好\"\}'")  # 花括号要写 \{ \}
服务.监听(8080)
```

**再看"设防"的版本**——用 `尝试/接住` 把两种坏情况都变成 400：

```
服务 = 网络.服务()

函数 收留言(请求)
    条目 = 空值
    尝试
        条目 = 网络.自文本(请求["体"])
    接住 错误信息
        返回 { "状态": 400, "体": "请求体不是合法的 JSON：{错误信息}" }
    完毕

    如果 类型(条目) != "dict"
        返回 { "状态": 400, "体": "请求体要是一个 JSON 对象" }
    完毕

    如果 非 包含(条目, "留言")
        返回 { "状态": 400, "体": "少了留言这个字段" }
    完毕

    返回 { "状态": 201, "体": 网络.到文本({ "收到": 条目["留言"] }) }
完毕

服务.路由("POST", "/留言", 收留言)
服务.监听(8080)
```

这个"设防"版本一步步检查了四件事：**能不能解析 → 是不是对象 → 有没有该有的字段 → 才处理**。
这就是一个真实后端处理用户输入的标准姿势，值得抄下来。

### 5.4 调用与结果

```bash
# 正常情况
curl -X POST http://localhost:8080/留言 -d '{"留言":"今天天气不错"}'
# {"收到":"今天天气不错"}

# 请求体不是合法 JSON
curl -X POST http://localhost:8080/留言 -d '{留言: 今天}'
# 请求体不是合法的 JSON：...

# 是合法 JSON，但不是对象
curl -X POST http://localhost:8080/留言 -d '[1,2,3]'
# 请求体要是一个 JSON 对象

# 少了字段
curl -X POST http://localhost:8080/留言 -d '{"名字":"小明"}'
# 少了留言这个字段
```

不设防的版本遇到坏请求体时，终端里会出现这样一条双语错误（注意它有行号、有建议）：

```text
第 14 行：请求体不是合法的 JSON，第 1 个字符就出问题了。
line 14: the request body is not valid JSON (the problem is at character 1).
  提示：检查是不是少了一个引号或逗号。收到的开头是：{留言: 今天}
```

> **写文本里的小坑**：如果你想在响应的文本里写一个 JSON 例子，
> 花括号要转义成 `\{` 和 `\}`，否则 卅 会以为你要插值。
> 例如 `返回 { "体": "格式应该是 \{"留言": "内容"\}" }`。

## 6. 完整项目：待办事项 REST 服务

现在把前面所有东西合起来，写一个真的有用的小后端：**待办事项服务**，
支持"查全部、加一条、删一条"。这一段与《05-前端后端扩展设计》第 2.5 节的示例**逐字一致**。

### 6.1 什么是 REST

REST 这个词听起来吓人，其实只有一句话：

> **同一个网址，用不同的"方法"表达不同的动作。**

| 动作 | 方法 | 网址 | 意思 |
|---|---|---|---|
| 查全部 | `GET` | `/待办` | 把清单给我看看 |
| 加一条 | `POST` | `/待办` | 我要加一条 |
| 删一条 | `DELETE` | `/待办?序号=1` | 把 1 号删掉 |

网址只有 `/待办` 一个，全靠方法和查询串区分。这也是为什么 v1.1 不需要路径参数——
参数放查询串就够了。

### 6.2 完整代码（37 行，含注释与空行）

```
# 待办事项 REST 服务（v1.1 网络模块）——内存存储：查、增、删
#   v2 落地后，第一行改为：用 "网络" 引入
待办 = {}            # 键是序号的文本，值是条目字典（用字典存内存，因为字典能原地删除）
状态 = { "下一个序号": 1 }

函数 列出(请求)
    结果 = []
    for 键 于 待办
        结果.添加(待办[键])
    完毕
    返回 { "状态": 200, "头": { "Content-Type": "application/json" }, "体": 网络.到文本(结果) }
完毕

函数 新增(请求)
    条目 = 网络.自文本(请求["体"])
    序号 = 状态["下一个序号"]
    条目["序号"] = 序号
    状态["下一个序号"] = 序号 + 1
    待办[文本(序号)] = 条目
    返回 { "状态": 201, "体": 网络.到文本(条目) }
完毕

函数 删除(请求)
    键 = 请求["查询"]["序号"]
    如果 包含(待办, 键)
        待办.删除(键)
        返回 { "状态": 200, "体": "已删除序号 {键}" }
    完毕
    返回 { "状态": 404, "体": "没有序号 {键} 的待办" }
完毕

服务 = 网络.服务()
服务.路由("GET", "/待办", 列出)
服务.路由("POST", "/待办", 新增)
服务.路由("DELETE", "/待办", 删除)
print("待办服务已启动：http://localhost:8080")
服务.监听(8080)
```

> 关于"多少行"：《05》第 2.5 节称它为"36 行示例"；
> 这里把两行注释、四行空行也编了号，一共 37 行。**格式不重要，完整可运行最重要。**

### 6.3 逐行解释

#### 第一段：内存存储（第 1–5 行）

| 15 | `条目 = 网络.自文本(请求["体"])` | **把请求体原文翻译成 卅 值**。客户端发来 `{"事项":"买菜"}`，这里就得到一个字典 `{ "事项": "买菜" }`。不是合法 JSON 会抛错、可被 `接住`。 |

## 7. 反过来：用 `网络.请求()` 当客户端

### 7.1 你也能当"顾客"

前面你一直当"餐厅"。但 卅 也能当"顾客"——去访问别人的服务：

```
网络.请求(网址, 方法: "GET", 头: 空值, 体: "")
```

| 参数 | 说明 |
|---|---|
| `网址` | 完整的网址，如 `"http://localhost:8080/待办"` |
| `方法` | 命名参数，缺省 `"GET"`，还可以是 `"POST"`、`"PUT"`、`"DELETE"` |
| `头` | 命名参数，缺省 `空值`，要发 JSON 时写 `{ "Content-Type": "application/json" }` |
| `体` | 命名参数，缺省 `""`，POST 的内容放在这里，必须是**文本** |
| 返回值 | 一个**响应字典**，和你在服务端返回的那个结构**一模一样** |

两个重要特性：

1. **它是同步的**——调用会一直等到对方回应才往下走。没有回调、没有 Promise、没有 `async/await`
   （D7 明确砍掉了异步），所以调用它就像调用 `读取文件` 一样简单。
2. **它只在服务端宿主可用，浏览器里不提供**（《05》3.5 节）。因为浏览器的主线程不允许这样阻塞地发请求。

响应字典的用法：

```
回答 = 网络.请求("http://localhost:8080/待办")
打印(回答["状态"])          # 200
打印(回答["体"])            # 还是文本！[{"事项":"写作业","序号":2}]
待办们 = 网络.自文本(回答["体"])   # 这才变成 卅 的列表
```

**再强调一遍：`回答["体"]` 是文本，不是列表。**
不管是服务端还是客户端，`"体"` 永远是文本——这种一致性让你少记一条规则。

### 7.2 完整客户端示例

先启动第 6 节的服务（终端 1），然后新建 `待办客户端.saho`（终端 2）：

```
# 待办客户端：查列表 -> 加一条 -> 再查列表
回答 = 网络.请求("http://localhost:8080/待办")
待办们 = 网络.自文本(回答["体"])
打印("服务返回状态：{回答["状态"]}")
打印("现在有 {长度(待办们)} 条待办")

新条目 = { "事项": "买牛奶" }
回答 = 网络.请求(
    "http://localhost:8080/待办",
    方法: "POST",
    头: { "Content-Type": "application/json" },
    体: 网络.到文本(新条目)
)
打印("新增结果：{回答["状态"]} {回答["体"]}")

回答 = 网络.请求("http://localhost:8080/待办")
待办们 = 网络.自文本(回答["体"])
for 条目 于 待办们
    打印("· {条目["事项"]}")
完毕
```

运行：

```bash
sahou 待办客户端.saho
# 服务返回状态：200
# 现在有 1 条待办
# 新增结果：201 {"事项":"买牛奶","序号":2}
# · 写作业
# · 买牛奶
```

几点说明：

- 多行的函数调用是合法的：圆括号**内部的换行会被忽略**（规范 2.10），
  所以长调用可以放心折行，命名实参写在位置实参之后就行。
- `网络.到文本(新条目)` 把字典变成 JSON 文本，正好是服务端 `网络.自文本` 要的东西。
  **一个发、一个收，两个翻译官配成一对。**
- 想删掉刚加的：`网络.请求("http://localhost:8080/待办?序号=2", 方法: "DELETE")`。

### 7.3 在同一份程序里同时当服务端和客户端？

可以，但要**注意顺序**：`服务.监听(端口)` 会一直阻塞，所以客户端调用必须写在它**之前**。

```
# 先自己调一下自己的服务地址是行不通的（服务还没开门），
# 正确顺序是：先访问别人 -> 再做别的事 -> 最后才监听
```

最简单的做法还是**开两个终端、跑两个 `.saho` 文件**：一个当服务端，一个当客户端。
这也是真实世界的常态。

### 7.4 客户端也会出错

如果服务没启动就去请求它，会得到一个**可接住**的双语错误。所以客户端要包 `尝试/接住`：

```
尝试
    回答 = 网络.请求("http://localhost:8080/待办")
    打印("成功：{回答["状态"]}")
接住 错误信息
    打印("连不上服务：{错误信息}")
    打印("先确认另一个终端里 sahou 待办服务.saho 还在跑。")
完毕
```

## 8. 常见错误与排错

### 8.1 端口被占用

**症状**：一运行就报错，服务起不来。

```text
第 36 行：端口 8080 已被占用，服务起不来。
line 36: port 8080 is already in use, so the server cannot start.
  提示：换一个端口（如 8081），或者先关掉占用 8080 的程序。
```

**为什么会这样**：门牌号不能挂两家店。常见原因是**上一次的服务没关干净**
（终端窗口关了但进程还在），或者另一个软件正好占了 8080。

**怎么办**：

1. 最省事：**换个端口**。把两处 `8080` 一起改掉（`服务.监听(8081)` 和提示文本）。
2. 想找是谁占着：Windows 上在 PowerShell 里运行

   ```powershell
   Get-NetTCPConnection -LocalPort 8080 | Select-Object OwningProcess
   ```

   拿到进程号后可以用任务管理器结束它。
3. **让程序自己兜底**——用 `尝试/接住` 换一个端口重试：

```
服务 = 网络.服务()
问好 = 函数(请求) => { "体": "你好，世界！" }
服务.路由("GET", "/", 问好)

尝试
    打印("准备用 8080 开门…")
    服务.监听(8080)
接住 错误信息
    打印("8080 起不来：{错误信息}")
    打印("换成 8081 再试。")
    服务.监听(8081)
完毕
```

注意：`服务.监听` 只有在"端口占用"这种错误上才会返回/抛错；
一旦成功，它会一直阻塞，`接住` 块根本不会有机会执行。这正是 `尝试/接住` 的常见形态。

4. 顺带提醒：**监听 80、443 这类低端口通常需要管理员权限**，初学阶段请用 1024 以上的端口。

### 8.2 响应的 `"体"` 不是文本

**症状**：请求打过去，浏览器/curl 显示"服务内部出错"，终端里出现：

```text
第 8 行：响应的 "体" 必须是文本，这里给的是 列表。
line 8: the response "body" must be 文本 (string), but got 列表 (list).
  提示：想返回 JSON，写 网络.到文本(结果)。
```

**原因**：你直接 `返回 { "体": 结果 }`，而 `结果` 是列表或字典。

**改法**：套上 `网络.到文本(...)`。

```
# 错的
返回 { "体": 结果 }

# 对的
返回 { "体": 网络.到文本(结果) }
```

**要检查的还有"每一条返回路径"**：一个处理函数里常常有好几个 `返回`。
如果正常路径记得转换、错误路径忘了，就会出现"有时候好、有时候 500"的现象。
建议让每个 `"体"` 都是文本：

```
如果 出错了
    返回 { "状态": 400, "体": "参数不对" }              # 本来就是文本，OK
完毕
返回 { "状态": 200, "体": 网络.到文本(结果) }            # 容器必须转换
```

### 8.3 跨函数共享状态：要改容器，不能重新赋值

这是整个网络模块里**最容易错、也最值得花时间理解**的一条。

**规则回顾（规范 5.3）**：函数内给一个名字赋值，是在**当前函数作用域新建一个局部变量**，
**不会**修改外层的同名变量。但列表和字典是**可变对象**：
通过 `容器["键"] = 值`、`容器.添加(...)`、`容器.删除(...)` 修改的是**共享的那个对象本身**，调用者看得见。

先看**错误的写法**：

```
# 错误示范：每个新条目都会拿到序号 1
状态 = { "下一个序号": 1 }
待办 = {}

函数 新增_错的(请求)
    条目 = 网络.自文本(请求["体"])
    序号 = 状态["下一个序号"]        # 每次都是 1
    条目["序号"] = 序号
    下一个序号 = 序号 + 1            # ← 错！这只是新建了一个局部变量，函数一结束就没了
    待办[文本(序号)] = 条目
    返回 { "状态": 201, "体": 网络.到文本(条目) }
完毕
```

运行结果：第一个条目序号是 1，第二个条目序号**还是 1**，`待办` 里永远只有一条。
`下一个序号 = 序号 + 1` 这行写得很像对的，但它改的是局部变量，外面的 `状态` 一个字节都没动。
（如果你写成 `下一个序号 = 下一个序号 + 1`，效果一样糟，而且更隐蔽。）

**正确的写法**：改容器里的字段。

```
状态["下一个序号"] = 序号 + 1
```

同理，删除待办时：

```
# 错的：这也会变成局部变量，外面的 待办 没变，条目删不掉
待办 = 剩下

# 对的：原地删除共享字典里的键
待办.删除(键)
```

**为什么这个坑在网络程序里特别危险？**
因为在命令行程序里，这种 bug 你一运行就发现了；
而在服务端，**"服务只启动一次、处理函数被调用很多次"**，
第一次请求看起来完全正常（序号 1 很对），错要等到第二个请求才现形。
所以写处理函数时，请养成一句自问：

> **"我这个赋值，是要改外面那个容器，还是只想建个本地变量？"**

顺带一个对照：示例里 `列出` 函数的 `结果 = []` 和 `结果.添加(...)` 是**完全正确**的——
`结果` 本来就是"这个函数自己的"局部变量，不需要共享给谁。判断标准就是"这个数据要不要活过这次请求"。

### 8.4 其他常见坑（速查）

| 现象 | 原因 | 改法 |
|---|---|---|
| 路由明明写了，访问却 404 | 路径要**一字不差**：`/待办/` 不等于 `/待办`；方法也必须大写 `"GET"` | 统一写成 `"/待办"`、`"GET"`（宿主把方法统一成大写，但你的路由表里也要写大写） |
| 浏览器显示"服务内部出错" | 处理函数抛错且没被 `接住`，宿主回 500 并在终端打印诊断 | 去看**终端**里的双语报错；在处理函数里用 `尝试/接住` |
| `请求["查询"]["序号"]` 报"字典里没有键" | 客户端没带这个查询参数 | 先用 `包含(请求["查询"], "序号")` 判断，缺就返回 400 |
| `网络.自文本(请求["体"])` 抛错 | 请求体不是合法 JSON，或客户端没发 `Content-Type` 但发了 JSON | 用 `尝试/接住` 包住，返回 400 和一句人话 |
| 响应里中文乱码 | 没声明内容类型 | 加 `"头": { "Content-Type": "application/json; charset=utf-8" }` |
| 浏览器打开页面一片空白 | 路径 `/` 没有注册路由 | 给 `/` 单独写一条路由 |
| 别人访问不到我的服务 | 默认只绑 `127.0.0.1`（只允许本机） | 需要局域网访问时显式传主机：`服务.监听(8080, 主机: "0.0.0.0")`；**注意这会把自己的电脑暴露给同一网络，课堂上先问老师** |
| 服务卡住不动 | 某个处理函数里有很慢的循环；v1.1 是**串行**的，一次只处理一个请求 | 精简处理逻辑；理解"一个请求没处理完，其他请求都在排队" |
| 中文参数看起来是乱码 `%E5%90%8D` | 那是网址编码 | 不用管：宿主会自动解码，你拿到的仍是正常文本 |
| 改完 `.saho` 没生效 | 服务还在跑旧代码 | `Ctrl + C` 停掉，重新 `sahou 待办服务.saho` |
| 少了一个 `完毕` | 块没收尾 | 报错会告诉你是**从第几行开始的块**没关上，照着补 |

## 9. 速查表、自检与练习

### 9.1 一页速查

**三步起服务**

```
服务 = 网络.服务()
服务.路由("GET", "/路径", 处理函数)
服务.监听(8080)
```

**请求字典的键**：本文用到 `方法`、`路径`、`查询`、`头`、`体`（值全是文本或字典）。
v1.6 起又新增 `表单`（POST 表单+查询串）、`Cookie`、`会话`、`文件`（上传）、`参数`（路径参数 `:名` 捕获）——见《14-全栈开发》第 1 节。

**响应字典 3 个键**：`状态`（缺省 200）、`头`（缺省 `{}`）、`体`（缺省 `""`，**必须是文本**）；另有便捷键 `"Cookie"` 自动转 Set-Cookie。

**两个翻译官**：`网络.自文本(文本) -> 值`、`网络.到文本(值) -> 文本`

**客户端**：`网络.请求(网址, 方法: "GET", 头: 空值, 体: "") -> 响应字典`（同步、服务端可用）

**最常用的状态码**：`200` 成功、`201` 已创建、`400` 请求有问题、`404` 找不到、`500` 服务内部出错

**路由匹配**：方法和路径都要**精确**相等；参数一律放查询串，不放路径里。

### 9.2 语言纯度的自检（你应该没有学到任何新语法）

| 检查项 | 本模块是否破坏 |
|---|---|
| 关键字总数 | 仍是 **18 个**，`网络` 是模块名不是关键字，**+0** |
| 内置函数总数 | 仍是 **29 个**，模块成员不占名额，**+0** |
| 数据类型 | 仍是 **数/文本/列表/字典/布尔 + 空值**，服务、请求、响应**都是普通字典**，**+0** |
| 块收尾 | 全部用 `完毕`/`end`，没有花括号、没有缩进规则 |
| 双语 | 模块成员全部中英双名（`网络/net`、`监听/listen`、`自文本/json_from`…） |
| 错误处理 | 只有 `尝试/接住` + `抛出`，错误对象就是一段文本 |
| 函数 | 定义只有一种写法；匿名仍只有 `函数(x) => 表达式` |

如果你发现自己想用 `class`、`async`、`await`、`import`、`装饰器`——**它们都不存在**，
而且你也不需要用：`服务 = 字典 + 函数` 就够了。

### 9.3 练习（附参考答案）

**练习 1**：写一条 `GET /问候` 路由，读取查询参数 `名字`；
有参数就返回 `你好，{名字}！`，没有就返回状态 `400` 和一句提示。

<details>
<summary>参考答案</summary>

```
函数 问候(请求)
    查询 = 请求["查询"]
    如果 包含(查询, "名字")
        返回 { "体": "你好，{查询["名字"]}！" }
    完毕
    返回 { "状态": 400, "体": "缺少查询参数：名字" }
完毕

服务.路由("GET", "/问候", 问候)
```

要点：`包含` 先判断再取值；`如果` 块里的 `返回` 会立刻结束函数，
所以最后那行 `返回 400` 只在"没进 `如果`"时才会执行。

</details>

**练习 2**：给第 6 节的待办服务加一条 `GET /待办/数目` 路由，
返回 `{"条数": 3}` 这样的 JSON。

<details>
<summary>参考答案</summary>

```
函数 数一数(请求)
    返回 { "头": { "Content-Type": "application/json" }, "体": 网络.到文本({ "条数": 长度(待办) }) }
完毕

服务.路由("GET", "/待办/数目", 数一数)
```

要点：`/待办/数目` 是一个**独立路径**，和 `/待办` 不冲突（精确匹配）；
它必须注册在 `服务.监听(8080)` 之前；`"体"` 仍然是文本。

</details>

**练习 3**：写一段客户端代码，把服务端的待办列表逐条打印成人话（只打印事项）。

<details>
<summary>参考答案</summary>

```
回答 = 网络.请求("http://localhost:8080/待办")
待办们 = 网络.自文本(回答["体"])
打印("一共 {长度(待办们)} 条：")
for 条目 于 待办们
    打印("· {条目["事项"]}")
完毕
```

要点：`回答["体"]` 是文本，必须先 `网络.自文本` 才能遍历；
`网络.请求` 是同步的，返回之后马上就能用。

</details>

**练习 4（动脑子）**：把第 6 节 `新增` 里的 `状态["下一个序号"] = 序号 + 1`
改成 `下一个序号 = 序号 + 1`，然后加三条待办，猜猜会发生什么？再亲手验证。

<details>
<summary>参考答案</summary>

三条待办的"序号"都会是 `1`（因为 `状态["下一个序号"]` 永远是 1），
并且 `待办[文本(1)] = 条目` 每次都覆盖同一个键，所以清单里最终只有 **1 条**。
原因就是第 8.3 节讲的：函数内赋值只创建局部变量，外层字典没有被修改。

</details>

### 9.4 接下来

你已经会用 卅 起服务、发请求、收 JSON 了。往下可以试：

1. **加持久化**：处理函数里用 `写入文件` 把 `待办` 存成 JSON 文本，启动时用 `读取文件` + `网络.自文本` 读回来。
2. **加一个前端**：用《05》第 3 节的 `页面/page` 模块（`sahou build`）写一个网页，
   用 `页面.取元素` 显示列表。注意：浏览器端**没有** `网络.请求`，
   这一版的做法是把数据在构建期渲染进 HTML，或者用普通表单提交。
3. **读懂设计文档**：《[05-前端后端扩展设计](./05-前端后端扩展设计.md)》第 2 节讲了这些 API 为什么长成这样，
   第 5 节还明确列出了"**不做的事**"（不做 WebSocket、不做虚拟 DOM、不做路径参数路由），
   每一条都有理由——知道"为什么不做什么"，比知道"能做什么"更重要。

> **一句话收尾**：后端不是魔法，它只是"**一个一直开着、等着别人来提问的字典 + 函数**"。
> 你已经会写函数、会写字典，所以你已经会写后端了。
