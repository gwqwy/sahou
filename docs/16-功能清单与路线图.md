# 卅 · 功能清单与路线图

> 本文档是待办功能的唯一清单：每个版本从这里"领活"。状态标记：☐ 待办 / ◐ 进行中 / ☑ 完成。
> 优先级：**P0** 缺陷（破坏口径或正确性）、**P1** 建议纳入最近版本、**P2** 后续排期。
> 语言级改动（L 系列）实施前须在 00-设计决策简报补决策记录；明确不做的东西见文末。

## 一、缺陷修复（P0）

### F1 ☑ 格子（响应式）转译缺失 ⭐（v0.3.0 已完成：rt.js 响应式运行时 + CellStmt 代码生成 + 页面.绑定/绑输入）
- **现象**：`internal/transpile/transpile.go` 的 `stmt()` 语句分派没有 `CellStmt` 分支，
  `sahou build` 转译出的网页 JS 会**静默丢弃**格子语句（不报错、不生效）。
  解释器与 wasm 浏览器直跑都支持格子，唯独转译路径是哑的，破坏"四侧同口径"原则。
- **方案要点**：rt.js 增加响应式运行时（依赖图 + 脏标记传播，对应解释器 reactive.go 的 JS 版）；
  `CellStmt` 生成格子注册与首次求值；格子读取在追踪期记录依赖；与 `页面` 模块控件打通
  （格子变化 → 控件自动刷新）。
- **涉及面**：internal/transpile/{transpile.go, rt.js}、tests/build.sh、docs/13。
- **验收**：新增响应式页面用例在 DOM 桩下与 wasm 侧行为一致；build.sh 用例数 +1 全绿。

### F2 ☑ 数学模块补取整组（v0.3.0 已完成：发现 数学.向下取整/向上取整 早已存在，四包已改用并删除取整 hack）
- **动机**：语言没有下取整/上取整，stones 包里"转文本按点分割"的取整 hack 已重复 4 处
  （数列库/日期库/分数库/时长库各一份 `取整数部分`）。
- **方案要点**：`数学` 模块新增 `下取整/上取整`（模块不计 D9 的 30 个内置名额）；
  各包改用后删除各自的取整数部分（对正数行为一致）。
- **涉及面**：internal/interp/stdmod.go（数学模块）、internal/transpile（模块 JS 映射）、
  stones 四包、editors/shared/language.json、docs/09。
- **验收**：packages.sh 双侧期望输出不变；`数学.下取整(-3.5)` 得 -4、`上取整(2.1)` 得 3 的快照用例。

## 二、语言增强（P1）

### L1 ☑ 用户函数默认参数（v0.3.0 已完成：parser/interp/transpile 三侧 + 098 快照）
- **动机**：参数表当前明确"没有默认值"（parser paramList 的提示语），但 v4.2 已支持命名实参，
  默认参数是自然延伸：`函数 问候(名字, 标点: "！")`。
- **方案要点**：paramList 解析 `名字: 字面量` 默认值；AST 参数从 `[]string` 升级为带默认；
  callSahou 缺参时用默认；转译器生成 JS 默认参数；LSP 签名显示默认；00 简报 D5 加注记。
- **涉及面**：internal/parser、internal/interp/{interp.go, value.go}、internal/transpile、
  internal/lsp、docs/{00, 02, 11}、tests/cases 新快照。
- **验收**：三侧（run/build/wasm）快照一致：缺省、覆盖、命名实参混用。

### L2 ☐ 字典点号读取（设计决策项，先立项再实施）
- **动机**：`动物.名字` 当前报错（要求 `动物["名字"]`）；键为合法标识符时允许点读对初学者更友好。
- **风险**：与模块成员访问同形，消歧规则必须清晰（求值期按对象类型判定：字典即字段）；
  错误提示体系随之调整。
- **前置**：在 00-设计决策简报补一条决策（建议 D11）后再动工。

### L3 ☐ 解释器性能 phase B（v0.4+）
- docs/04 已规划：常量折叠、作用域槽位化（`map[string]Value` 查名改下标）、闭包环境扁平化。
- 语言行为零变化，靠 conformance 语料兜底；待教学示例出现可感知卡顿再启动。

## 三、stones 包扩充（P1/P2）

### S1 ☐ 表格库
- `表格(表头列表, 行列表)` → 对齐的文本表格；核心教学点是 CJK 全角宽度（宽度算 2）。
- 验收：含中英混排的快照用例，双侧一致。

### S2 ☑ 算法库扩展：递归经典（v0.3.0 已完成：汉诺塔/八皇后，92 解断言）
- `汉诺塔(层数)` → 步骤列表；`八皇后()` → 解列表。展示递归与回溯，纯卅可写。
- 验收：八皇后解数 = 92 的断言；双侧一致。

### S3 ☐ 配置库
- `读配置(文本)` → 字典：key=value、`#` 注释、`[节]` 分节——"看得见过程的解析器"教学示范。

## 四、工具链与编辑器（P1/P2）

### T1 ☑ LSP 服务端悬停（v0.3.0 已完成：SharedJSON 注入 + textDocument/hover + 扩展转发）
- 悬停内置函数/关键字/模块/stones 成员，显示签名与说明；数据口径对齐
  editors/shared/language.json（服务端动态 + 静态合并）。

### T2 ☐ LSP 跳转定义与 Quick Fix
- 跳转：函数定义 ↔ 调用、跨模块跳进 `用 "工具" 引入` 的源文件；
- Quick Fix："你是不是想写 X" 一键替换。

### T3 ☐ 编辑器数据生成器
- 从 editors/shared/language.json 生成 sublime-syntax / JetBrains 用拼写文件，
  让路线图上的 Sublime/Vim/JetBrains 变成低成本接入。

### T4 ☐ CI 强化
- gofmt 门禁（gofmt -l 为空才过）；Linux 测试 job（先验证 tests/*.sh 在 ubuntu 的可跑性，
  现在只有 Linux 构建检查）。

### T5 ☐ 跨平台发版
- Release 工作流加矩阵，产出 Linux/macOS 的 sahou；`nativewin_other` 已是浏览器事件桥，
  桌面/写页面在非 Windows 走浏览器。验收：对应平台冒烟通过。

## 五、生态（P2）

## 六、明确不做（对照 00-设计决策简报，保持定位）

并发编程、类与继承、async/await、生成器、类型注解、多重继承、列表推导式、
缩进块等——除非 00 简报修订决策，否则本清单不收。
